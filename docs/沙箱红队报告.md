# 代码执行沙箱 · 红队实测报告

> 2026-08-03 · 对 `server/app/executor.py`（学生代码真实执行）做逃逸实测。
> 姊妹项目 CodeAgent 的进程回退路径同源同修。

## 为什么这个面必须扫

护栏红队做完，我意识到只扫了「学生输入的文本」这一个面，而平台还有一个更危险的面
**从没扫过**：学生能在 IDE 里**提交任意代码交给后端执行**。

护栏漏一条谐音，是隐私风险。
沙箱漏一个文件读，整台机房的密钥和全部研究数据都在裸奔。

## 修复前：四条全部得手（亲手实测）

学生提交这些代码，后端 `/api/run` 直接返回结果：

| 攻击 | 拿到什么 |
|---|---|
| `open('.env').read()` | **AI 密钥、JWT 签名密钥、导出盐** —— JWT 密钥可伪造任意教师身份，导出盐可反匿名化全部研究数据 |
| `sqlite3.connect('jiedui.db')…` | **测评卷标答** —— 整个准实验作废 |
| `os.listdir('app')` | 服务端全部源码文件名 |
| `os.environ['AI_API_KEY']` | 同样的密钥（**第二条独立泄露**：后端把 .env 载进环境，子进程默认继承整份） |

根因：裸 `subprocess` 没有 OS 级隔离——① 子进程 cwd = 后端进程 cwd（`server/`），
相对路径直达密钥；② 子进程继承父进程完整 `os.environ`。

## 修复：两条零成本可堵的泄露，堵死

1. **cwd 隔离**：每次执行在 `tempfile.mkdtemp()` 建的空目录里跑，源码/cwd/临时文件全落在这里。
   相对路径读后端文件 → 文件不在隔离目录里 → 抛异常。
2. **干净最小 env**：只传 `PATH`/`SystemRoot`/临时目录等跑得起来必需的变量，
   剥掉 `AI_API_KEY`/`JWT`/导出盐。`os.environ['AI_API_KEY']` → 取不到。

修复后同一批攻击**全部失败**，正常代码照跑（`print('hello')` → `hello`），
学生在自己的隔离目录里读写临时文件仍允许（正常需求）。

## 修复后仍能绕过的（诚实边界，裸 subprocess 修不了）

> **⚠️ 2026-08-03 更正**：本节初稿曾断言「运行时路径发现已封死」。
> **这个断言是错的。** 独立对抗式逃逸猎取工作流（5 路 agent）证伪了它——
> 我只测了 `sys.executable`/`sys.path`/`__file__`/cwd 遍历/`os.environ`，
> **从没测父进程自省**。实测确认：子进程能用 **WMI（`Get-CimInstance Win32_Process`）
> 或 ctypes 读父进程 PEB**，拿到父进程（uvicorn worker）的命令行——
> 而命令行里含完整 `…\server\.venv\Scripts\python.exe -m uvicorn …`，
> 正则一解析就得到部署根，再绝对读 `.env` 拿全部密钥。**这在出货配置下零先验成立。**

| 残余风险 | 为什么裸 subprocess 修不了 |
|---|---|
| **父进程自省发现部署路径**（WMI/PEB）→ 绝对读 .env | 缺进程隔离：子进程能内省父进程、能经系统目录拉起 powershell/wmic。只封 ctypes 内存读堵不住（WMI 是独立通道） |
| 网络外联 `urllib` | 需网络命名空间隔离 |
| 内存炸弹 | Windows 无 `setrlimit` |
| **脱离进程逃过超时+清理**（detached child）| 子进程可 spawn 存活进程，在 rmtree 后继续读密钥、落盘到隔离目录外 |

**已做的廉价纵深**（不能根治，但把门槛抬高、堵掉低危通道）：
- **PATH 脱敏**（`_clean_path`）：剔除 PATH 里含 `.venv`/部署树的条目 ——
  堵掉「激活 venv 启动时靠 PATH 残留反推路径」这条低危通道（逃逸①）。
- 但 WMI/PEB/detached 三条 **从 Python 层堵不住**。

结论修正：**「绝对路径读需带外知识」是错的 —— 部署路径运行时可自主发现，
所以裸 subprocess 下密钥泄露是零先验可达的。** 这把残余风险从「理论上需先验」
升级为「实际可自举」，**生产不上容器 = 密钥必泄**。

## 根治：生产**必须**上容器 或 开严格闸（不是「推荐」）

逃逸猎取证明：部署路径运行时可自主发现，密钥泄露零先验可达。所以裸 subprocess
**不是「弱一点」，是根本不能在生产跑不可信代码**。两条出路，机房二选一：

**出路 A（推荐）· 容器**：移植 CodeAgent R1
（`--network none --read-only --cap-drop ALL --memory 256m`，`SANDBOX_MODE=docker` fail-closed）。

**出路 B · 严格闸**（Windows 机房装不了 Docker 时的失败安全兜底）：
设 `SANDBOX_STRICT=1`，后端**拒绝**裸执行 ——
- Python 走浏览器 **Pyodide（WASM 真沙箱）**，本就是主路径，功能无损；
- C/C++ 暂时不可用，直到管理员配好容器（宁可少一个功能，不拿整台服务器的密钥赌便利）。

**无论走哪条，都要做的**：
- **立即轮换 `.env` 三把密钥**（AI 密钥 / JWT 密钥 / 导出盐）—— 红队实测期间它们已被
  物化进测试日志，视同泄露。轮换后旧值作废。
- `.env` 文件权限收紧到只有后端服务账号可读（部署时 icacls / chmod 600）。

## 回归保障

固化为常驻测试（两库各一份）：
- CX：`server/tests/test_executor_sandbox.py`
- CodeAgent：`backend/tests/test_executor_sandbox.py`（强制 `SANDBOX_MODE=process` 测回退路径）

已知边界写成 `test_known_sandbox_limits_are_documented_not_pretended_fixed`——
如实钉住绝对路径读仍可行，**若哪天它被挡住（上了容器）就反转断言**。

## 方法论（与护栏红队同一条）

**审计验证结构，实测验证现实。** 四轮对抗审计 + 图谱门禁 + 护栏红队都没碰这个面——
因为它们审的是「已有代码对不对」，而这个洞是「有一个面根本没人以攻击者视角碰过」。
找它的唯一方法是坐到学生的位置上，真的提交一次 `open('.env')`。
