# 教师使用手册（一页版）

> 结对编程智能体平台 · 给信息技术老师的完整操作路线。
> 全程实测约 **24 次点击**（20 人 × 2 班规模）。每一步平台只显示**一个主按钮**，照着点即可。

## 0. 登录

浏览器打开平台地址 → 选「教师」页签 → 输入账号与教师口令。
学生用「学生」页签，账号是学号（不带前缀），密码问老师。

## 1. 开学：建班（每班约 5 次点击，只做一次）

「班级」页 → **＋新建班级** → 起名 → 把学籍表里的学号整列**复制粘贴**进名单框（不用加前缀，粘裸学号即可）→ 保存 → 选这个班是**实验班**还是**对照班**。

两个班都建好后，去「课题」页。

## 2. 课题：一条线走完（每一步就是屏幕上唯一的主按钮）

| 步骤 | 你点的按钮 | 发生什么 |
|---|---|---|
| ① | **开始**（建课题） | 勾选实验班 + 对照班，创建课题 |
| ② | **下发前测** | 名单在此刻冻结；全体学生收到同一份 18 题情境卷 |
| ③ | **已核验纸质件，批量开通** | 收齐纸质监护人同意书后点它 —— 一次开通全部（没开通的学生做不了测评、用不了 AI） |
| ④ | **开始上课（进入干预期）** | 实验班 AI 自动只提问不代写；对照班照常。前测没收齐会拦一道，你可以坚持开始（报告会如实注明） |
| ⑤ | 上课期间：**课堂监看** | 一屏看谁卡住（卡住的排最前） |
| ⑥ | **结束这一轮** | 干预期封账；两班 AI 设置恢复原状 |
| ⑦ | **下发后测** | 与前测同蓝图不同题 |
| ⑧ | **收官并生成结论** | 数据冻结，出对比报告 |

## 3. 看结论、导出

- **看对比结论**：两组前后测均分、增值、效应量，附一段**可直接抄进结题报告的写法**。
- 报告底部的**边界声明**是平台按规则硬生成的（样本小、非随机化等），**关不掉**——请原样抄进论文的「研究局限」，这是保护你不在答辩上被问倒的。
- **导出**：去标识化 CSV/JSON（无姓名、无班名、学号已假名化），可直接交给高校导师做统计。

## 4. 三件容易踩的坑

1. **乱答的卷子不用你剔**：8 秒交卷、全选同一项的作答，平台自动剔除并在报告里注明剔了几份。
2. **六维雷达是过程指标，不是成绩**：它反映「做了多少、修没修好」，不能单独当能力证据——结论以前后测卷为准（报告里已按此口径写好）。
3. **学生端永远看不到分数**：只有「较强/中等/待加强」。这是研究设计的一部分，不是缺陷——给了分数学生就会去刷行为，数据就废了。

## 4.5 本学期新能力（2026-08）

- **学生端「设计」抽屉**（IDE 工具条）：写代码前先写伪代码计划（每行一步）。任何语言、
  积木或代码模式都能用；写满 3 步保存，计入「做过设计」。鼓励学生先想后写——这也是
  建模维度此前对 C++/代码模式学生不公平的修复。
- **运行即自动保存**：学生点「运行」自动存版本（代码没变不重复存）。手动「保存到云端」
  收进了 ⋯ 菜单，一般不需要教。
- **学生端顶栏「我的数据」**：学生可查阅/下载自己的数据，可申请删除（老师核验后执行，
  见教师端删除入口；删除不可撤销，执行前与家长确认）。学生撤回同意**不会**删数据，
  这两件事界面上都写清楚了。
- **语言切换**改为下拉（一节课语言固定，不必教切换）。

## 5. 出问题找谁

- 页面显示「没加载出来 / 重试」：先点重试；不行则检查后端服务是否在跑（见《进校首日检查单》）。
- 学生说「让我交同意书」：正常流程——收他的纸质同意书，回「课题」页点批量开通。
