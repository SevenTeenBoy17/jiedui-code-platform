# 完整产品上线纠偏方案

日期：2026-10-14。状态：根因核查完成，完整产品迁移未完成；本片未发布或修改云端资源。

## 一、目标纠正

用户要上线的是已有结对编程产品：原学生端、原教师端、已有界面资产和完整业务流程。不是重新设计一个作品编辑器，也不是只展示静态画布。

此前已同意的“Netlify 原生函数＋PostgreSQL 分片迁移”是实施方式，不意味着允许替换产品界面或缩小最终交付范围。此前上线的 N1 是独立技术试用入口，不能替代完整应用。后续以本方案的产品保真与完整性标准约束迁移；旧报告保留为阶段证据，不删除历史失败和未验事项。

延续已确认条件：前端/API 使用 Netlify、数据库使用现有独立 Supabase 新加坡项目、指定人员试用、保留本地版。不另建产品、不擅自换云平台、不升级套餐、不上传本地真实学生数据库。AI 沿用用户已选模型服务，不擅自切换供应商。

两个独立代理分别只读复核了前端与后端，结论一致。图谱工具返回与当前项目不相符的旧索引，未用作依据。

## 三、完整产品边界

### 必须保留的原界面

当前 `web/src/router/index.ts` 定义 24 个受保护业务页面，另有登录页；下表不计重定向。

| 区域 | 页面 |
| --- | --- |
| 学生 9 页 | 学习工作台、结对编程、编程工坊、思维成长、成长画像、重做复核、测评中心、具体测评作答、我的数据 |
| 教师教学 7 页 | 今日、学情、班级、资源、任务、课堂实况、课堂观察 |
| 教师教研 8 页 | 课题、课题结论、班级分析、数据导出、学生画像、教学案例、量规、研究报告 |

- 直接复用原 Vue 组件、布局、路由、样式与已制作的资产，不再维护第二套用户界面。
- 保留学生紫色侧栏及编程猫用户头像、IP 伙伴、教师教学/教研双区导航；不以迁移为由重做美术或删掉菜单。
- “保留 24 页”是覆盖基线，不等于这 24 页当前业务均已完成。页面显示、接口接通、真实业务验收分开记录。
- `ThinkingView.vue:76` 等仍引用本地 `studentGrowth`；`GrowthProfileView.vue:53` 明示“前端演示，尚未发送教师”；`IdeView.vue:124,159` 明示任务说明/反思提交缺口。这些需列入业务补齐，不能改文案冒充真实功能。

### 后端不是简单换发布目录

原后端 `server/app/main.py:34` 注册 15 个模块。独立静态扫描发现 138 个显式 API 装饰器，不含健康检查、SPA、自动文档；源码包含 44 个去重建表名。N1 当前只有 8 个方法/路径组合、4 张应用表。两者口径不同，不能计算成“迁移百分比”。未读取本地或云端业务数据库。

直接发布 `web/dist` 不能接通现有 N1：

| 项目 | 原前端 | 当前 N1 | 所需处理 |
| --- | --- | --- | --- |
| 登录 | 角色路径、username/password、返回 token | email/password、HttpOnly Cookie | 云端认证适配，服务端决定角色；不恢复模拟登录兜底 |
| 会话与退出 | Pinia token、Bearer 请求 | Cookie＋服务端会话核验 | 初始化会话、权限失效、退出与未保存稿流程贯通 |
| 保存作品 | code/blockState | 另需 requestId、expectedVersion | 接入幂等、版本冲突与原稿保留，不删除保护以兼容旧调用 |
| 错误 | detail | error.code/error.message | 统一可读错误，禁止失败显示为“暂无数据”或保存成功 |
| 教师权限 | 班级、任务、观察、研究 | teacher 当前仍只有个人作品 | 建立班级/任课/任务范围授权，不只是添加教师账号 |

源码依据：`web/src/api/auth.ts:29`、`web/src/api/http.ts:54`、`web/src/api/projects.ts:26`、`cloud/pilot/lib/api.mts:70`、`cloud/pilot/supabase/migrations/20261014062932_pilot_identity_projects.sql`。

## 四、纠正后的实施顺序

以下是后续逐片执行计划，本片没有实施这些业务变更。每片先声明实际文件白名单，保留本地行为；完成后按项目规则记进度并等待 next。开发分片不等于缩减最终产品。

| 切片 | 实际工作 | 可核验交付，未达标不能报通过 |
| --- | --- | --- |
| F1 原产品接入基础 | 原 Vue 全量构建/资源/路由基线；云端认证与错误适配；保留原双端外壳；承接 N1 版本保存与冲突保护 | 原登录、学生首页/IDE、教师外壳与深链在受控候选环境可见；未迁移页面明确提示，不以此宣称全产品上线；补齐既有退出竞态与未保存稿浏览器验收 |
| F2 双端课堂基础 | PostgreSQL 用户映射、班级授权、资源、任务分发、学生接收、作品与设计材料关联 | 教师建合成班级/发布任务→指定学生收到→保存作品→教师看见同一任务原件；其他班级不可读 |
| F3 可信 AI 与引导规则 | 原会话策略、角色、生成合同、输出核验、模型调用、回执与撤回；统一函数时间预算 | 当前模型真实调用与同版本浏览器回执；禁止无权限调用、迟到内容发布、核验失败泄露候选答案、重试重复记证据 |
| F4 单任务证据与反馈复核 | 分析/设计/运行/测试/反思原件；教师反馈→学生再做→教师复核 | 每条判断回到任务、作品版本和原件；反馈前后证据分离；无复核不能称有效，次数不能变成能力分 |
| F5 测评、画像与教研 | 补齐学生测评、成长三页真实来源、教师学情/研究、导出、数据权利与同意撤回 | 指定学生可作答，未发布结果不可见；画像可回证据；课题及导出按授权；demo 与真实记录严格分开 |
| F6 完整产品发布 | 同一候选版本完成两角色逐页、跨账号、刷新、异常与恢复检查；验证静态资源/模型/数据库/运行环境 | 全部承诺功能实测后，原应用才接替现有正式入口；同时交付学生/教师两个限定账号和跨角色演示流程 |

F3→F4→F5 延续“可信对话、引导规则→单任务证据→教师反馈复核→真实画像”的业务顺序。F2 是其可信任务、身份和授权的前置，不是绕开此顺序。

## 五、不能默默省略的执行环境问题

- Python：保留浏览器 Pyodide 路径，验收 Worker/WASM、离线资源、海龟画布及真实错误。当前 pilot 的 CSP 不能不经核对就直接覆盖原应用资源策略。
- C/C++：原 `executor.py` 依赖 gcc/g++ 子进程；严格模式会拒绝执行，源码并无已完成的容器执行实现。需在前期做安全运行环境可行性核验，不能上传裸执行器、用模拟成功代替或默默删除功能。若需要额外隔离服务/费用/更改“API 全在 Netlify”边界，应先给出具体方案与费用请求确认；这项是完整上线门槛，而非已获准删减项。
- AI：保留当前模型选择；Netlify 同步函数当前限制 60 秒，不能把现有多段模型调用原样塞入函数就称迁移成功。后台任务方案必须同时有授权、幂等、取消、终态和取回结果机制。[官方函数限制](https://docs.netlify.com/build/functions/configuration/)
- 本地 Python/FastAPI 常驻服务与 Netlify 原生函数运行模型不同，需要迁移 API；前端原 Vue 不需要因后端迁移而重画。[Netlify Functions 入门](https://docs.netlify.com/build/functions/get-started/)
- 继续使用合成试用数据，不自动导入原学生库；不得将已有 N1 demo 当作真实课堂证据。身份映射、演示数据标识及原件关联要单独验证。

## 六、最终验收定义

1. **外观保真**：原登录＋全部学生/教师页面逐页对照同视口截图；原侧栏、图标、IP、编辑器、图表、弹层无丢失，无以简化页代替。
2. **真实双端链路**：教师发布→学生执行与提交→AI 引导/核验→教师反馈→学生再做→证据与画像更新；刷新和重新登录后数据一致。
3. **权限与数据**：未邀请者、其他学生、其他班级、撤回权限全部拒绝；角色由服务端控制；并发保存、重复提交、退出竞态、恢复及导出/删除有实测证据。
4. **功能真伪**：假数据明确标识；前端演示、后端实现、真实模型和正式验收不能互相代替。当前原版未接通项纳入完成清单，不因“原来就没完成”而从完整上线承诺中隐去。
5. **同版本交付**：记录构建/部署版本与验收证据；原本地版不受损；只上传产物、服务端必要代码，不上传密钥、真实学生库、验收凭据或工作区备份。
6. **未达标不切正式入口**：迁移中的预览只能称候选环境。当前站点仍是 N1 技术试用，不对外称完整产品。
