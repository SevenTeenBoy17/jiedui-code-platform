## 4. 边界与发现

1. 90s 是单次聊天请求的主动事件循环预算，不是整段交互的绝对时限。聊天截止后原逻辑会自动查询一次状态，查询另有 15s；顺序极限可以是约 105s。后台页面暂停、计时器节流和主线程阻塞不受严格墙钟 SLA 约束。
2. 客户端 abort 不证明服务器已取消，也不证明请求失败；因此保留 request_id 和状态查询，不生成答复、不重发 POST。服务端可能仍完成原请求。
3. 不新增“切换就 abort”，继续依赖原身份/会话/轮次 epoch 隔离，保留现场迟到成功和旧身份 401 验收的意义。
4. 新两行输入和轮廓目前仅代码改动，**尚无同构建 390px 截图**；不能宣称已消除像素裁切。中文 IME 候选确认与 Enter 的现存行为需现场检查；本片未获准改键盘行为。
5. 曾向主代理报告：初版 REQUEST_TIMEOUT 仅提“查询本次请求状态”，但元数据 GET / openRound 只有“重新读取”。主代理明确授权兼容两动作措辞，现已按第2节文字收口并另做 RED/GREEN；此发现已关闭。未新增按钮或界面动作。
6. 曾一次 apply_patch 上下文验证失败（旧代码 CONSENT_REVOKED 与预期行误写不一致），未写入任何改动；以实际源内容修正补丁后成功。未更改安全错误语义。

### 9.2 请求事件与身份隔离证据是否充分

日志把每个场景标为 runtime_fault / provider_forwarded=false，消费与释放保留 sid/rid/request_id，未含正文或token。LATE-A1于B1实际消费后释放success；A/B请求标识不同，随后B1单独释放。ABA-A1与A2同会话同轮次但request_id不同，A1在A2消费之后释放；等待图仍仅新A2。IDENTITY-OLD明确在旧请求消费之后释放401，新身份图和主代理现场记录仍保留新账号。以上是本轮零模型受控网络场景的互相印证，已比只运行epoch合同更完整；但本代理未现场重放，且每类仅一次限定路径，评分不提升到“所有异步隔离完备”。

RECOVERY-DISCONNECT日志仅一次chat_consumed，正文实际截断后一次pending查询，手动查询同request_id得到failed，没有第二次POST。NO-BODY-RELEASED和INVALIDATED也各为一次原请求加匹配状态；与图片中没有新增对应AI气泡、保留恢复入口相符。日志不是学习能力数据，不能进入真实学生证据链。

### 9.3 仍需保留的问题和未验项

- **失效指引残余**：invalidated沿用REQUEST_FAILED文案，只说核实会话后手动提问，而当前输入被禁用。虽有“重新读取会话”可操作，应该后续明确“会话/请求已失效，先重新读取或联系老师”；本片没有追加产品文案授权，不修改。
- 固定浮动IP在 released-without-body-mobile / invalidated-mobile 的长会话截图中覆盖底部一小部分用户气泡，可滚动但不够理想；它未覆盖本轮alert、查询/登录按钮或输入文本。此为既有固定层布局风险，不把定点textarea修复宣传成全页面可达性全部通过。

- 未复跑材料待核实→保存新版本→重新读取的完整现场流程；不能用旧runtime截图填补。
- 窄屏成功仅合成短文本；实际AI正文、长段落/代码、保存版本、教学输出质量没有本片验收证据。
