## 一、教学模式结构

### 1.1 论文没有"教学模式图"，只有"技术协同范式图"

必须先讲清楚一个判别：本文的图 2-2「三维度技术协同范式」（p.20）与图 3-1「导学智能体设计框架」（p.35）**都是技术架构图，不是教学模式图**。全文没有教师角色，没有师生机权责划分，没有课堂环节。它是"**智能体 = 师傅**"的替代式设计（认知学徒制里的 master 被 AI NPC 老药师/小壶灵完全接管，p.67-68）。

因此本文对用户模型的贡献不是"另一个模式"，而是"**模式内某个环的实现细节**"。

### 1.2 唯一的阶段划分：合法边缘参与（LPP）→ 三阶段，且是**有限、终结**的

§2.4.1「合法边缘参与映射导学交互流程」（p.30-32）+ §3.3.2（1）落地（p.63-66）：

| 阶段 | 任务体裁 | 学习者身份 | 反馈/支架特征 | 页码 |
|---|---|---|---|---|
| **新手阶段** | 药园种植（播种/浇水/除草）、药材鉴别、采集（狩猎/伐取/采摘/垂钓四类采集法） | 边缘参与者 | "**明确反馈机制是新手阶段关键设计**"，实时逐步纠错提示（浇水过量→即时提示原因） | p.30-31, 63-65 |
| **进阶阶段** | 方剂配伍挑战（开放性、多解空间）、药材炮制 | 半熟练 | 从"给答案"转为"给资源"：查知识手册、与壶灵 RAG 对话、同伴讨论；**开放性问题、无固定答案** | p.31, 65 |
| **专家阶段** | 虚拟坐诊、辨证论治（复杂多病机病例）+ **时间压力** | 接近核心 | 无步骤提示，靠 CoT 名师 NPC 显性对话；考综合与临床思维 | p.31-32, 66-67 |

**这是有限三阶段，不是无限闭环。** 终点明确写为"逐渐接近专家水平"（p.32、p.66）。这与用户"三轮徽章显式呈现有限迭代"的主张**同向**，但理论依据不同：本文用 Lave & Wenger 的合法边缘参与（情境学习），用户用 CT 要素演进。

⚠️ 我研读时的怀疑：本文把 LPP 误归给"现代认知学徒制由让·莱夫和艾蒂安·温格在《情境学习：合法的边缘性参与》一书中正式提出"（p.17）——这是**理论溯源错误**，认知学徒制是 Collins/Brown/Newman(1989)，Lave & Wenger(1991) 提的是情境学习/LPP。本文把两个理论混为一谈。**引用它时要绕开这个溯源，只引其阶段划分与技术实现，不引其理论归属**，否则会把错误传递进自己的论文。

### 1.3 阶段推进的触发条件：**弱**（这是它的短板，也是留给用户的空间）

阶段跃迁的表述全是软的："随着玩家在游戏中的成长和知识积累，他们将进入进阶阶段"（p.65）。没有阈值、没有判据、没有回退。真正硬的判据只存在于**阶段内的难度微调**（贝叶斯网络评估→难度升降，p.55-57），而**跨阶段的门限没有操作定义**。

→ 对用户模型的直接启示：用户"第一轮·分解建模→第二轮·算法实现→第三轮·综合优化"若也只写"随着深入"，会踩同一个坑。**必须给出每轮的出口判据**（见第六节 CX 落地建议）。

## 二、智能体架构

### 2.1 两套正交的切法（本文最值得偷的方法论）

本文有**两个层级的功能分解**，并明确说明二者关系是"需求→架构"的映射：

**(A) 需求层四维模型**（由认知学徒制解构而来，图 2-1，p.17-19）：
1. **情境模拟** —— 游戏引擎构建药材市场/中医馆/炮制车间等实践情境
2. **知识组织** —— 知识图谱系统化表征 + **循序渐进的个性化推送**（"游戏初期推送基础常用中药知识…随着深入逐步推送复杂内容"，p.18）
3. **互动引导** —— 实时答疑 + **任务拆解式阶段性提示** + 成就/积分激励
4. **评估反馈** —— 全过程数据采集（答题准确率/时间/复习频率、操作步骤合规性/耗时/重复次数、提问频率/讨论活跃度）→ 即时纠错反馈 + 阶段性学习报告 + 改进建议

**(B) 架构层三层模型**（结合"智能体经典设计模式"，图 3-1，p.34-38）：

```
认知层 Cognitive
 ├─ 感知 Perception ── 玩家行为 Input（操作序列→行为特征向量）
 │                  └─ 游戏环境 Environment（事件监听 + 场景状态跟踪）
 └─ 记忆 Memory ──── 短期：对话历史(窗口化管理) + 当前任务上下文
                    └─ 长期：① 玩家偏好矩阵（学习进度 / 错题分布 / 任务耗时热力图）
                             ② 画像 Profile（导学规则 / 导学角色 / 导学场景）  ← 支架规则存放处
                             ③ 知识 Knowledge（RAG 知识库：本草纲目等）
决策层 Decision
 ├─ 推理 Reasoning ── CoT 思维链（症状分析→病机推导→治则确定→方剂推荐）
 └─ 规划 Planning ─── 任务分解为子任务 + 为每子任务定学习路径 + **执行后反思**
                      （"若大部分玩家在某子任务花费时间过长或错误率高，智能体反思任务
                        难度设置和导学方法，对后续任务调整优化"，p.38）
执行层 Execution
 ├─ 多模态交互 ── 视觉/听觉(TTS)/物理(手柄震动)
 └─ 环境干预 ──── 动态难度调节 + NPC 行为控制
```

**这是单体智能体（monolithic agent）+ 分层模块，不是多智能体。** 全文无 agent 间通信、无角色分工协商。多智能体只在文献综述里作为背景出现（王者荣耀"绝悟"，p.12）。

### 2.2 与 LLM 的关系：LLM 是"决策中枢"，Agent 是"协同驱动"，游戏是"交互场域"

三维协同范式（§2.1.2，p.19-22）：

- **LLM 决策中枢**：RAG 保准确（内容组织层）+ CoT 保显性（教学策略层）+ Prompt 模板库保场景适配
- **Agent 协同驱动**：多模态交互框架 + **混合决策机制**（战略层 LLM 生成教学意图，战术层行为树转具体步骤）——原文明说这是"有效实现教学策略维度的**渐进式能力培养机制**"（p.21）
- **游戏交互场域**：文化隐喻设计 + 动态叙事生成（表现好→生成更具挑战性的情节分支）

Agent↔LLM 的三种协作机制（§2.3.1，p.27-28）值得单列，因为它就是"人机权责边界"的技术版：
1. **知识请求与精准获取** —— Agent 做 NLP 解析、实体/意图抽取，再走 RAG 检索，Agent 是"精准筛选与引导"的过滤器
2. **推理辅助与解释生成** —— Agent 做预处理，并把 LLM 的推理步骤**可视化重排**（流程图/步骤列表）后再呈现
3. **提示词定制与内容调控** —— Agent 按学习者层级改写送给 LLM 的提示词 ← **支架渐退的技术载体就在这里**

## 三、实施机制

### 3.1 任务如何生成下发（= 用户的"任务链实例化"，本文写得最实）

**这是全篇对 CX 缺口②最有价值的一段（§3.2.2.1，p.49-51）**。完整管线：

```
① 埋点持续采集多维数据（答题准确率、答题时长、错误类型分布、尝试不同配伍组合的频率）
        ↓ 触发条件：频繁出错 且 准确率低于阈值
② DeepSeek-R1 对错误数据做特征提取 → 识别薄弱环节（药材功效理解 / 配伍原则运用）
   结合知识图谱相关节点，注意力机制聚焦
        ↓
③ 输出自然语言【教学意图】：
   "强化方剂配伍知识学习，针对风热感冒方剂，重点讲解药材功效及配伍原则，
    提供更多针对性练习和案例分析"
        ↓ 难点：LLM 输出不确定，行为树要结构化 → Dify 自建【意图解析器】
        ↓ 提取"教学重点 / 目标任务 / 适用场景"转结构化数据
④ 行为树解析为可执行序列：
   [序列节点]
     ├ 展示风热感冒方剂配伍案例   ←【选择节点】初学者→银翘散经典简单案例
     │                              有基础→银翘散加味(咳嗽甚)变化案例
     ├ 讲解风热感冒方剂药材功效
     ├ 阐述风热感冒方剂配伍原则
     └ 提供风热感冒方剂配伍练习题 ←【并行节点】同时启动贝叶斯实时监测程序
                                     （答题时间/准确性），为后续动态调整供依据
```

三种节点语义被明确定义：**选择节点=多选一（用于难度变体选择）、序列节点=顺序保证教学逻辑连贯、并行节点=主任务与监测程序同跑**（p.50-51）。

这是文献里少见的、把"抽象教学意图 → 可执行任务序列"讲到节点级的描述。**用户模型里"任务链=智能体依学情实例化的可执行序列"这句抽象话，在这里有了现成的工程原型。**

### 3.2 过程数据如何采集回流：**两速数据闭环**（§3.1.2，p.39-40）

| 环 | 时延预算 | 链路 | 作用对象 |
|---|---|---|---|
| **实时反馈环** | **< 500ms**（明确写出的工程指标） | 感知层捕捉操作 → 推理层快速判断 → 决策层生成反馈指令 → 交互层多模态呈现 | 学习者当下体验（例：选错药材→语音"还缺一味关键药材，再仔细想想哦"+屏幕颜色标记） |
| **长期优化环** | 跨会话 | 全量学习轨迹（操作/时长/答题/交互记录）→ 数据挖掘 → ① 推送补强资料 ② **迭代更新知识图谱**（玩家频繁关注炮制工艺→图谱增补该领域节点与关系） | 系统自身 |

**关键缺陷（也是用户的差异化空间）**：长期环的终点是**系统**（知识图谱、推送策略），**不是教师**。全文没有任何面向教师的输出——没有学情画像看板、没有过程诊断报告、没有策略调整建议。所谓"数据闭环"是机器自循环。这恰好印证了用户对文献"闭环画得漂亮但不落到教师决策"的判断。

### 3.3 教师如何介入：**不介入**（零）

全文教师角色缺席。唯一的"师"是 LLM 驱动的 AI NPC（老药师、小壶灵、中医名师 NPC），构成"师承关系网络"（p.68）。这是替代式而非增强式设计。评估实验里也只有被试与系统，没有教师变量。

### 3.4 人机权责边界："助学不代学"**未被落实，反而相反**

本文没有任何"不代做"的约束机制。相反：
- CoT 会把 **症状分析→病机推导→治则确定→方剂推荐** 完整答案链条直接展示给学习者（p.44-46、图 3-32"专家阶段—中药名师 NPC 思维链显性对话"）
- 提示词工程的"渐退"是**减少引导量**，不是**拒绝给答案**："对于初级学习者，使用详细、引导性强的提示…对于高级学习者，**适当减少提示信息**，鼓励其深入思考和探索"（p.25）

→ **CX 的 ai_navigator（拒写完整代码 + 反越狱规则）在这一点上比本文更严格**。本文可以作为"文献普遍缺乏不代学机制"的反例证据被引用。

## 四、支架 / 脚手架（本文最强项，逐条拆）

**有，且是我在本轮文献里见到的最可操作的分级支架描述。** 它分布在五处，可合成一张"支架强度矩阵"：

### 4.1 支架规则的存放位置：长期记忆的"画像 Profile"（p.37）

> "在导学规则设定方面，针对不同阶段的玩家制定差异化规则。**初级玩家以基础知识普及为主，在中药识别任务中给予明显提示；进阶玩家则侧重于自主能力培养，减少直接提示，引导其自主探索。**"

这是架构级安排：**支架强度不是散落在提示词里的临时约定，而是作为一条持久化规则存在于智能体长期记忆的 Profile 模块中**。CX 目前的 `scaffold` 参数是无状态入参，正好缺这一层。

### 4.2 三级提示词模板族（§3.2.1.3(2)，p.47-49）—— 渐退的操作定义

| 层级 | 提示词设计原则 | 原文模板骨架 |
|---|---|---|
| 初级 | 具体、简单、通俗、**避免专业术语**、生活化比喻 | "用简单直白、贴近生活的语言…想象一个常见的生病场景…**用生活中的物品或现象来比喻**药材的作用原理"（金银花→"小卫士"/"浇一盆水"） |
| 中级 | 加强**引导思考与知识拓展** | "结合[方剂]的组成药材，**分析其在治疗[病症]时的作用机制**。同时**探讨该方剂在临床应用中的常见加减变化，并说明这些变化的依据**" |
| 高级 | 侧重**启发创新思维与学术研究**、批判性 | "从现代医学研究角度深入分析化学成分、药理作用及潜在机制。结合最新研究文献探讨发展趋势，并**对目前研究中存在的问题进行批判性分析**" |

**这三级 = 用户"示例支架→提示支架→仅诊断点拨"的现成参照物**，只是学科不同。注意它的渐退轴是"具体化↓、自主思考↑、批判性↑"。

### 4.3 行为树选择节点的案例难度分级（p.50-51）
初学者→经典且简单案例（银翘散，详展药材组成/功效/配伍原理）；有基础→加减变化案例（银翘散加味治咳嗽甚者）。**支架渐退在"教学材料选择"这一层也有实现。**

### 4.4 任务界面可供性递减（§3.2.3.2，p.60）
> "对于初级玩家，**界面会简化，只提供常见的药材选项，并给予较多的提示和引导**。随着玩家知识水平的提高，任务执行模块会**增加药材的种类和配伍的复杂性**"

→ 支架不只在语言层，还在 **UI 可供性层**（选项集大小）。这是 CX 完全没想过的一条渐退通道：Blockly 积木集/代码片段库的可见范围可以随轮次收窄或放开。

### 4.5 性能触发的动态难度调节（§3.2.2.3，p.55-57）
贝叶斯网络评估掌握度 → UE5 关卡蓝图动态改任务参数：
- 错误率高 + 耗时长 → **减少炮制步骤数量、简化操作流程**，并调 LLM 生成更详细讲解
- 表现出色 → **提高药材选择多样性与复杂性、引入更多特殊病症配伍要求**
- 另有情绪通道：表情识别 + 语音情感分析 → 检测到负面情绪 → 调整 TTS 语气与内容（p.57）

### 4.6 合成：本文支架渐退的"双驱动"
```
支架强度 = f( 阶段/层级 [离散，来自 Profile 规则] ,
              掌握度估计 [连续，来自贝叶斯网络/BKT] ,
              情绪状态 [来自表情+语音情感] )
渐退通道 = 提示词模板族 ⊕ 案例难度选择 ⊕ UI 选项集 ⊕ 任务步骤数 ⊕ TTS 语气
```
**"依据什么撤"回答得比"第几阶段给什么"更好**：撤的依据是掌握度概率估计，不是轮次计数。这是它对用户"按轮次递减"的一个实质挑战（见下节）。

## 五、对用户模型的检验

### 5.1 支持哪里

1. **支持"有限轮次"**：本文的 LPP 三阶段（新手→进阶→专家）是**明确有终点的线性阶梯**，不是无限闭环。可作为"有限阶段划分在教育智能体设计中已有先例"的旁证（p.30-32, 63-67）。注意措辞：它不是"三轮迭代"，是"三阶段进阶"——用户仍需论证"迭代"（同一问题反复深化）与"进阶"（不同难度依次通过）的区别，这恰是用户模型比本文更进一步的地方：**用户的三轮是围绕同一项目的三次迭代，本文的三阶段是三类不同任务的顺序解锁**。这个区别值得在论文里明确点出，是真差异化。
2. **支持"支架渐退可实现"**：给出了五通道渐退的工程证据，堵住"渐退是口号"的质疑。
3. **支持"任务链应由智能体实例化"**：LLM 教学意图 → 意图解析器 → 行为树序列，是可引用的实现原型。
4. **支持"四职能"中的三项**：其需求层四维（情境模拟/知识组织/互动引导/评估反馈）与用户四职能（学情感知/支架推送/学习分析/评价生成）有明显对应关系——知识组织≈支架推送、互动引导≈适时点拨、评估反馈≈学习分析+评价生成。
5. **反向支持"教师必须在环"**：本文教师完全缺席，长期优化环只回流到系统自身。它的实验也暴露了纯机器闭环的后果——知识记忆维度**输给传统网课**（Q1 3/5 vs 4/5，Q2 4/5 vs 5/5，p.76-77），作者自承"游戏化场景侧重原理探究而弱化机械记忆训练""智能体对基础知识点的推送频率不足"。**没有教师做课程性判断，智能体的自适应会系统性偏向它擅长的维度。** 这是用户"师—机—生"三方模型的一条硬证据。

### 5.2 挑战哪里

1. **【最重要】四职能是"需求层"的切法，不能直接当"架构层"用。** 本文明确做了两次分解并给出映射：需求层四维（从理论解构来）→ 架构层三层（从智能体设计模式来）。用户目前的"四职能"是需求层语言（学情感知/支架推送/学习分析/评价生成），但 CX 的落地却是按模块（ai.py/ct.py/insights.py/study.py）散着的，**缺一张"四职能 × 三层（感知-决策-执行）"的映射表**。补上这张表，模式图的说服力和系统章的可写性都会跳一个台阶。建议的替代切法不是取消四职能，而是**四职能保留为对外功能承诺，内部按 感知/记忆/推理/规划/执行 五模块实现，并给出映射矩阵**。
2. **渐退的触发轴：轮次 vs 掌握度。** 本文的渐退主驱动是**贝叶斯掌握度估计**，轮次只是粗粒度默认值。用户"支架随三轮递减"若纯按轮次，会出现"第三轮仍不会分解的学生被撤掉了示例支架"的伦理与效果问题。**建议改为：轮次定支架档位的上界（默认档），掌握度估计可向下补档，教师可手动锁档。** 这是本文能给用户模型带来的最实质的一处改进。
3. **"评价生成"的位置。** 本文把"反思"放在**决策层的规划模块内部**（任务执行后反思难度设置与导学方法，p.38），而不是作为一个平行职能。这提示：用户的"评价生成"若只作为对外输出（结论卡/报告），就丢了它作为**智能体自我调参输入**的角色。**评价链要既外供教师，又内驱下一轮任务链生成**——这才叫"首尾呼应闭合"。
4. **两速闭环 vs 单一闭环。** 用户的"数据回流·反思迁移"是一条粗线。本文拆成 <500ms 的实时反馈环 + 跨会话长期优化环。**用户模式图外圈的回流箭头应当拆成两条：堂内即时回流（生←机）与跨轮/跨课回流（师←机）**，否则读者会把它读成单一速率的闭环，也就正好落回用户批评的"只画无限闭环"。
5. **理论溯源风险。** 本文把认知学徒制的提出者错记为 Lave & Wenger（p.17）。若用户要引它谈"支架渐退"，**只引其技术实现与阶段设计，不要引其理论归属句**。

### 5.3 该文自身的软肋（引用时要留心 / 也是 CX 能超越的地方）

- **样本 N=10（实验组 5 / 对照组 5）**，无统计检验，只报均分与逐题正确率（p.74-77）。量表自编（SUS 改造成 5 点 10 题、知识测试 6 题、文化认同 4 题）。
- **稳定性差**：实验组在稳定性（Q5/Q6）、知识准确性（Q3）、操作简易性（Q1）三项**低于**传统网课对照组，作者归因于大模型响应延迟、知识图谱生僻药材缺失、多模态操作复杂（p.75-76）。
- **声称与实现脱节**：BKT + MCTS 只在理论章出现，实现章用的是贝叶斯网络 + 行为树，MCTS 未见落地；感知层多处描述（游戏内"摄像头""传感器"采集光照温湿度）是概念性表述而非实现。
- 结论章无"研究局限与展望"独立小节，仅一句"研究仍存在一些不足"（p.79）。

## 六、可落到 CX 的具体工程（对着四个已知缺口）

### 缺口① 支架渐退无实现 → 落到 `backend/app/routers/ai.py` + 新增 profile 表

**照搬本文的"Profile 规则 + 三级模板族 + 掌握度触发"三件套：**

1. **持久化支架档位**：新增 `student_profile` 表（学生×班级×课题维度），字段 `scaffold_tier`（`example` / `hint` / `diagnose`）、`round_index`（1/2/3）、`mastery`（六维掌握度快照）、`locked_by_teacher`（教师锁档）。对应本文 p.37 的"画像 Profile—导学规则"。
2. **三级 persona 模板族**：把 `build_system_prompt` 的 `scaffold` 从布尔/单值扩成三档，写死渐退轴（参照 p.47-49）：
   - `example`（第一轮）：允许给**同构但不同题**的完整示例代码 + 逐行注释；禁止给本题可提交代码
   - `hint`（第二轮）：只给结构性提示（"你需要一个循环 + 一个判断"）、伪代码骨架、反例；禁止出现可运行代码块
   - `diagnose`（第三轮）：只做诊断与提问（"你第 7 行的边界条件在 n=0 时会怎样？"）；禁止给结构提示
   - 三档都继承现有 ai_navigator 的反越狱规则——**CX 在"不代学"上比本文强，要保住这个优势并写进论文差异化**
3. **档位决策函数**：`tier = min(默认档(round_index), 掌握度补档(mastery), 教师锁档)`。即轮次定上界、掌握度可向下补、教师可强制。这是对本文"纯掌握度驱动"和用户"纯轮次驱动"的折中，也是论文里可写的一处创新点。
4. **UI 可供性通道**（本文 p.60 的启发，CX 独有的施展空间）：Blockly 积木分类可见集 / 代码片段库条目数随档位收窄；`/student/ide` 的"求助"按钮在 diagnose 档只暴露"提问"入口不暴露"给例子"入口。

### 缺口② 任务链无实现 → 新增 `agent/planner`，照搬 p.49-51 的四段式管线

```
POST /api/v1/agent/plan   (教师触发 或 监测阈值自动触发)
 1. 取数：ct_events 六维 + 近 N 次运行错误类型分布 + 用时 + 求助频次
 2. LLM 生成【教学意图】(自然语言, 一句话)      ← 对应本文 DeepSeek-R1 生成意图
 3. 【意图解析器】结构化：{focus, goal, scene, ct_dim, difficulty}
    —— 用 JSON schema 强约束输出，等价于本文的 Dify 意图解析器（解决 LLM 输出不确定性）
 4. 【计划器】展开为任务链（存 task_chain 表，外键指向教师的 problem_chain）：
    - sequence：有序子任务（读题拆解 → 建模 → 编码 → 自测 → 复盘）
    - selector：同一子任务的难度变体，按 scaffold_tier / mastery 选一
    - parallel：任务下发的同时挂一个"监测作业"（埋点规则 + 阈值），用于本轮内触发再规划
```
数据模型上要显式建 `problem_chain`(教师制品) → `task_chain`(智能体实例化) → `eval_chain`(评价) 三张表并串外键，让用户模式图的"三链"在库里有对应实体——**这一步做了，"三链"就从图上的话变成系统里的表，答辩时可直接展示 ER 图**。

### 缺口③ 三轮迭代无对应结构 → `studies` 之外新增 `round` 维度

- 明确区分两个正交概念：`studies.status`（pretest/running/posttest，**研究流程**）vs 新增 `round_index`（1/2/3，**教学流程**）。当前把两者混谈是缺口③的根因。
- 每轮绑定四元组：`(CT 要素, 任务体裁, 支架档位, 出口判据)`。参照本文表：

| 轮 | CT 要素 | 任务体裁 | 支架档 | 出口判据（本文缺，CX 要补） |
|---|---|---|---|---|
| 1 分解建模 | 问题分解 + 抽象建模 | 需求拆解 + 数据建模，不求可运行 | example | 分解维度得分 ≥ θ₁ 且 提交拆解图 |
| 2 算法实现 | 算法设计 | 编码实现 + 单测通过 | hint | 通过率 ≥ θ₂ 且 调试维度有活动 |
| 3 综合优化 | 调试评估 | 重构/优化/边界处理 + 互评 | diagnose | 优化前后指标差 ≥ θ₃ 或 教师判定 |

- **出口判据必须可教师覆写**（本文完全没有这一层），并在教师端显示"卡在第 N 轮的学生名单"。

### 缺口④ 数据回流→教师策略调整无闭环 → 两速环 + 教师侧新增"策略调整建议"

1. **快环**（借本文 500ms 预算的思路，给 CX 定一个可测的服务指标）：`/student/studio` 内的即时反馈（运行结果 + 苏格拉底追问）保持在可感知延迟内，并记录 `latency_ms` 到埋点，写进论文的系统性能一节。
2. **慢环，且必须终结于教师**（这是超越本文的关键）：在 `insights.py` 的结论卡里新增两个字段：
   - `next_round_scaffold`：建议下一轮的班级默认支架档 + 需要单独降档/升档的学生名单
   - `strategy_suggestion`：面向教师的策略调整建议（本文的长期环只回流到知识图谱，没有这一格）
   并在教师端"教学区—今日"暴露一个**确认/修改**动作，把教师的选择回写为下一轮任务链的输入参数 —— **这一步一落，用户模式图外圈的"数据回流→教师策略调整"就在系统里有了实体路径，"闭环"不再是画上去的箭头。**
3. **反思迁移**的落地物：每轮结束生成学生可见的"过程诊断卡"（不是分数，是"你在第 2 轮的调试尝试从 3 次降到 1 次"），对应本文 p.19 的"阶段性学习报告 + 改进建议"。

### 额外提醒（本文实验教训 → CX 实验设计）
本文实验组在**知识记忆维度输给传统网课**（p.76-77）。CX 若做对照实验，**必须预先设计"记忆/基础技能"维度的补偿模块**（本文的补救方案：间隔重复 SRS + 记忆小游戏 + 基础-原理-应用三级知识分层 + 保留传统归纳表），否则同样的坑会重演，并成为评审攻击点。

## 七、可直接引用的观点与页码

> **P1 支架分级作为持久化规则**（p.37）：
> "在导学规则设定方面，针对不同阶段的玩家制定差异化规则。初级玩家以基础知识普及为主，在中药识别任务中给予明显提示；进阶玩家则侧重于自主能力培养，减少直接提示，引导其自主探索。"
> —— 用于论证支架强度应作为智能体长期记忆中的持久规则，而非临时提示词参数。

> **P2 渐退的语言学操作定义**（p.25）：
> "对于初级学习者，使用详细、引导性强的提示，帮助其逐步理解…对于高级学习者，适当减少提示信息，鼓励其深入思考和探索。"
> —— 用于说明"渐退=减少引导量"这一朴素定义；同时可作为**批评靶子**：减少引导量 ≠ 拒绝代做，本研究进一步以"不直接产出可提交代码"的硬约束落实"助学不代学"。

> **P3 混合决策实现渐进式能力培养**（p.21）：
> "战略层面，大模型…生成具有针对性的教学意图。战术层面，行为树将大模型意图转化为具体可执行步骤…有效实现教学策略维度的渐进式能力培养机制。"
> —— 用于支撑"任务链由智能体依学情实例化"的技术可行性。

> **P4 意图→任务链的不确定性治理**（p.51）：
> "大模型输出的自然语言教学意图具有一定的不确定性，而行为树要求输入的指令具有明确的结构化格式。为解决这一问题，本系统…设计了特定的意图解析器。"
> —— 用于论证任务链生成必须有结构化中间层（CX 用 JSON schema 强约束）。

> **P5 两速数据闭环**（p.39-40）：
> 实时反馈环"将延迟控制在 500ms 以内"；长期优化环"通过对玩家学习轨迹的深度分析…对知识图谱进行迭代更新"。
> —— 用于支撑数据回流应分快慢两条；**并指出其局限：两环终点均为系统自身，未回流至教师决策**。

> **P6 三阶段有限进阶**（p.30-32）：
> 新手阶段（药材鉴别与采集种植）→ 进阶阶段（方剂配伍与药材炮制）→ 专家阶段（辨证论治与虚拟坐诊）。
> —— 用于支撑"有限阶段划分"有先例；同时说明其为**任务难度顺序解锁**，本研究的三轮为**同一项目的迭代深化**，二者性质不同。

> **P7 纯机器自适应的偏斜代价**（p.76-77）：
> 实验组在知识记忆维度低于对照组，作者归因"游戏化场景侧重原理探究而弱化机械记忆训练"、"智能体对基础知识点的推送频率不足"。
> —— 用于论证**教师必须在环**做课程性判断，否则智能体自适应会系统性偏向其擅长维度。

> **P8 教师缺位的事实陈述**（全文）：该研究以 AI NPC（老药师、小壶灵、名师 NPC）完全替代师傅角色（p.32, 67-68），未设教师介入通道。
> —— 用于文献综述中"替代式 vs 增强式"的分类对照。

## 八、研读时的思考痕迹（存疑与判断过程）

1. **第一印象误判**：标题是中药 + 游戏，一度以为与编程教育无关。读到 §3.2.2.1 才发现，它的"教学意图→行为树"管线与用户"问题链→任务链"是同构问题，**学科无关性很强**。教训：wave2 的筛选不该按学科筛，该按"是否给出模式→系统的映射细节"筛。
2. **摘要里那句"混合决策模型实现渐进式能力培养机制"是全篇最值钱的线索**，我据此定向去找"渐进/渐退"的实现，最后在五个分散位置拼出了完整的支架矩阵（§4.6）。作者自己没有把这五处收拢成一张表——**这张合成表是本轮研读的增值，可直接用于用户论文的文献述评段**。
3. **一处让我警惕的"纸面技术"**：§2.2.3(2) 大谈 BKT + MCTS 规划最优教学顺序，但第 3 章实现里彻底没有 MCTS，换成了贝叶斯网络 + 行为树。类似地，"部署于场景中的摄像头""传感器收集光照温度湿度"（p.28-29）在游戏引擎语境下是概念混淆（游戏内不存在物理摄像头/传感器）。**判断：本文理论章与实现章之间有明显的落差，引用时务必以第 3 章的实现描述为准，不要引第 2 章的技术宣称。**
4. **关于"它算不算支持用户的有限三轮"**：我反复权衡后的结论是"**部分支持，但要说清差别**"。它的三阶段是 LPP 的任务难度阶梯（三类不同任务顺序解锁），用户的三轮是同一项目的迭代深化（同一问题三次穿过 CT 要素）。如果论文里含糊地把它列为"有限轮次的先例"，会被审稿人指出概念混淆。**正确写法：以它证明"有限阶段划分 + 阶段绑定支架档位"在教育智能体设计中可行，同时点明本研究把"阶段"升级为"对同一任务的迭代轮次"，因而需要额外的出口判据设计。**
5. **意外收获**：UI 可供性递减（选项集大小随水平变化，p.60）这条渐退通道是我事先没想到的。CX 有 Blockly 双模，天然适合做"积木可见集随轮次收窄"，这可能是比提示词渐退更可观测、更容易做量化证据的一条路——**建议作为 CX 的一个独立小创新点。**
6. **N=10 的实验规模**让我意识到这个细分领域的实证门槛确实很低。CX 若能做到班级级（N≥60）+ 三轮全过程埋点 + 教师干预记录，实证强度会显著高于本轮读到的多数文献。这一点应写进用户论文的"研究贡献"。

## 苏格拉底追问（第二波·模式与架构向）

> 追问对象不只是这篇文献，更是用户已定稿的顶层模式图。每条链都按「问 → 再追问 → 暂时的答」走，不接受表面结论。

### 链 1｜「有限三轮」的依据是什么？

**问：** 用户把"三轮有限迭代"当作对四篇文献（谢鑫/方海光/柴兴祝/梁家健）的改进。但"和文献不同"是**差异**，不是**依据**。马金帅的三阶段依据是 LPP（合法边缘参与，一条社会学习的参与轨迹）；用户的三轮依据是什么？

**再追问：** 如果三轮 = 三课时，那"轮"只是"课时"的重命名，模式图退化成课程进度表，审稿人一句"这不就是课时安排吗"就打穿；如果三轮压在一节 40 分钟课内，初中生在第三轮"综合优化"上极可能空转——他们连第二轮的可运行代码都未必写得出。**轮的边界到底由什么定义：时间？内容？还是产出物？**

**暂时的答：** 轮必须锚在**产出物形态的跃迁 + 可判定的出口判据**上，与时钟解耦。
- R1 分解建模 → 产出物 = 拆解图 / 数据结构选择说明（**明确不要求可运行**）
- R2 算法实现 → 产出物 = 可运行且通过基础用例
- R3 综合优化 → 产出物 = 重构 + 边界用例 + 互评记录

并且必须在论文里写死一句话：**"有限"限的是外圈轮次，不是内圈循环。** 教师侧的调控环（干预→解读→调整）与学生侧的调试环（运行→定位→反思）本来就是无限环，只有跨轮的外圈是三步有限闭环。这个"**内无限、外有限**"的双层结构恰恰是用户这张图相对四篇文献最有价值的地方，但**目前图上并没有说清**——现在只画了三个轮次徽章，读者会误读成"整个过程只迭代三次"，反而变成软肋。

**必须同时点破的概念差别：** 马文三阶段是**任务难度顺序解锁**（新手/进阶/专家是三类不同任务），用户三轮是**同一项目的迭代深化**（同一问题三次穿过 CT 要素）。可以引它证明"有限阶段划分 + 阶段绑定支架档位"在教育智能体里可行，但必须点明本研究把"阶段"升级为"轮次"，因而**多出一份出口判据的设计负担**——这正是比它更进一步之处。

---

### 链 2｜支架渐退按轮次撤，还是按掌握度撤？在结对场景里这个问题会变形

**问：** 用户图上写"支架随三轮递减"。若纯按轮次，会出现"第三轮仍然不会做分解的学生被撤掉示例支架"——效果与伦理双输。马文的主驱动是贝叶斯掌握度估计，轮次只是粗粒度默认值（p.55-57 阶段内难度微调有硬判据，跨阶段跃迁反而没有，p.65 只有"随着玩家成长"这种软表述）。**换到 CX 还成立吗？**

**再追问（本轮最有价值的一步）：** 就算折中成 `tier = min(轮次上界, 掌握度补档, 教师锁档)`，这个公式在 **CX 的结对场景下会直接崩**。一个房间两个学生，掌握度不同，AI 只有一个对话上下文。**档位是给"人"的还是给"房间"的？** 降档迁就弱者 → 强者也被暴露示例支架、跟着退化；升档迁就强者 → 弱者失去脚手架。**马文是单人游戏，完全没有这个问题；这是 CX 的独有难点。**

**暂时的答：** 档位持久化在 **(学生, 课题, 轮次)** 上，但**渲染在角色上**：
- 驾驶员侧看到的支架档 = 驾驶员本人的档位；
- 领航员侧走 `ai_navigator` persona，且档位取**两人中较低档再收一档**（对领航员更收敛，逼其提问而非替队友要答案）；
- 角色轮换时档位**随人走**，由 collab.py 在 `role_switch` 广播里一并下发。

这把"支架渐退"和"结对角色"耦合成一个机制，理论增量高于马文的单人分级。**副产品：弱者档位在三轮内是否上升，本身就是比后测分数细得多的过程性证据**——"支架转移"可以作为 CX 的独立观测量。

---

### 链 3｜四职能是好的切法吗？——四个缺口其实是一个缺口

**问：** 用户的四职能是学情感知 / 支架推送 / 学习分析 / 评价生成。但"感知"与"分析"的边界在哪？在 CX 里 `ct.py` 六维聚合既是分析、又是感知管线的下游——它们其实是**同一条数据管线的两段**，并列为两个职能会让人追问"那记忆呢？推理呢？"

**再追问：** 马文做了两次正交分解并给出映射（需求四维：情境模拟/知识组织/互动引导/评估反馈 → 架构三层：认知/决策/执行，p.17-19 与 p.34-38）。注意它的架构层里**没有"评价生成"这一格**，反思被塞进决策层的规划模块内部（任务后反思难度设置与导学方法，p.38）。那么用户把"评价生成"平列为职能，是不是丢掉了它**作为智能体自我调参输入**的角色？再往下逼一层：**四职能里到底缺了什么？**

**暂时的答：缺的是"记忆"。** 而这正是四个已知缺口的**共同根因**：
- 支架档位无处存 → 缺 Profile（马文 p.37 明写导学规则存在长期记忆的画像模块里）
- 任务链无处挂 → 缺跨会话状态
- 三轮结构无对应 → 缺 `round_index` 这个持久维度
- 数据回流无终点 → 缺一个可被写回、可被读取的学生状态对象

**结论：四个缺口不是四件事，是一件事——CX 没有跨会话的学生画像持久层。** 建议：四职能保留为**对师生的功能承诺**（模式图语言不动），内部补一张 **4 职能 × 5 模块（感知/记忆/推理/规划/执行）映射矩阵**，系统章直接照矩阵写；同时把"评价生成"在图上改成**双箭头**——既外供教师，又内驱下一轮任务链，"首尾呼应闭合"才不是画上去的。

### 链 4｜数据回流到教师，教师真的会去点吗？（最弱环）

**问：** 用户批评马文"两条闭环终点都是系统自身，不回流教师"（p.39-40），这个批评成立。但用户自己的方案——结论卡加 `next_round_scaffold` + `strategy_suggestion`，教师端确认/修改后回写下一轮——**依赖教师每轮都去点确认**。初中信息科技教师一人带十几个班、一周十几节课。教师不点，闭环照样断，**只是从架构里断变成在 UI 上断**。

**再追问：** 怎么让闭环在**教师不作为时仍然闭合**、在教师作为时**教师优先**？

**暂时的答：把 opt-in 改成 opt-out（默认自动 + 教师否决制）。** 轮末系统自动生成下一轮参数，进入"待生效"状态（下节课前生效）；教师端只展示一行"3 名学生将降档、1 名将升档 [维持 / 改]"。教师不操作也闭环，操作则覆盖。

**关键副产品：** 记录 `teacher_override` 事件（是否覆写、方向、理由标签）。**教师覆写率与覆写方向，是"师—机—生"三方模型中"教师在环"的唯一可量化证据**——比"教师看了看板"强一个量级，也是本研究能同时超越马文（教师缺席）和四篇文献（闭环只画不落）的实证抓手。若最终只能做一个新指标，就做这个。

### 链 5｜马文记忆维度输给传统网课——CX 会不会同坑？顺带：任务链会不会飘出课标？

**问：** 马文实验组在知识**记忆**维度输给传统网课（p.76-77），作者自承"游戏化侧重原理探究而弱化机械记忆""智能体对基础知识点推送频率不足"。CX 的对应物是什么？编程里的"记忆维度"≈ 语法与 API（for 怎么写、列表有哪些方法）。**苏格拉底式 navigator + 渐退支架，在初中零基础上极可能重演同一坑：学生"想得出、写不出"。**

**再追问：** 那是不是意味着第一轮根本不该渐退，甚至该反向增强？还有另一条飘移风险：马文的任务链有 Neo4j 中药本体兜底（p.41-43），**CX 没有学科知识图谱，LLM 生成的任务链凭什么不飘出课标/教材？**

**暂时的答：两条约束。**
1. **渐退曲线不是单调直线，而是双通道**：语法/API 层**始终保持高支架**（代码片段库、Blockly 积木、随查手册，允许直接给）；只有 **CT 层（分解/抽象/算法/调试策略）**随轮递减。这让"助学不代学"更可辩护——**不代的是思考，不是打字**。同时实验设计里必须预置"基础技能后测"，否则被评审按马文原样的点打穿。
2. **任务链候选池约束**：planner 的 selector 变体只能从**教师问题链下挂的候选任务池**里选，LLM 只做"选择 + 排序 + 措辞"，**禁止自由生成任务体**。这既治了飘移（等价于马文用知识图谱兜底），也构成"助学不代学"在教师侧的对偶：**AI 不代教师做课程性判断。**这个对称结构很漂亮，值得单独写一段。

### 本轮收敛

1. **最重要的一句：四个缺口是同一个缺口——缺 `student_profile` 持久层。** 先建表，其余三个缺口才有共同挂靠点。
2. **模式图需要改三处**：外圈回流拆成快/慢两条箭头；"评价生成"改双箭头；显式标注"内环无限、外环三轮有限"。
3. **真正的差异化不是三个轮次徽章，而是"有限轮 + 出口判据 + 教师覆写"三件套**——单画徽章会被读成课时表。
4. **CX 相对本文的既有优势要写进论文**：`ai_navigator` 的拒写完整代码 + 反越狱，正是本文（乃至多数文献）缺失的"不代学"硬约束；本文 p.25 的"适当减少提示信息"可作反面靶子。
5. **实验层面**：本文 N=10、量表自编、无统计检验。CX 若做到班级级 + 三轮全过程埋点 + `teacher_override` 记录，实证强度显著高于本轮多数文献。
