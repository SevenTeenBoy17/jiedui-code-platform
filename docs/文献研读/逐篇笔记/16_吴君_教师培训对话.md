## 1. 模式结构：知识建构四阶段 + 交互模型

### 1.1 阶段划分及其依据（3.2.2，论文 p27，PDF 34）

以**建构主义**「学习者与学习内容的交互即知识建构过程」为依据，把知识建构划分为**形成 → 整合 → 精化 → 扩展**四阶段。但作者在建模时**把后三个合并了**，实际交互模型只有两段：

| 阶段 | 认知任务 | 智能体动作 | 交互形态 | 资源模态 |
|---|---|---|---|---|
| **知识形成** | 新知初步接触/理解，快速获取目标知识点 | 知识点总结 + 知识点导览（视频定位跳转） | **单轮对话**为主，提问→快速回应 | **纯文字** |
| **知识整合—精化—扩展** | 融入已有结构 → 高阶思考/解决问题 → 拓展边界 | 实时答疑 + 个性化资源推荐 | **多轮对话**，轮次随认知复杂度上升而增加 | 文字+图片+视频+动画+实时交互模块 |

> 「随着交互轮次的增加、交互频率的提高，智能体不仅能够更快响应学习者的需求，还能提供更丰富的多模态资源，以支持更为复杂的认知任务。」（p28，PDF 35）

**阶段推进的触发条件 = 认知任务复杂度**（由学习者自己发起的问题难度决定），**不是**由学情数据判定、**不是**由教师决定、**不是**定时推进。→ 这是一个**学习者自驱、无守门人**的阶段推进。

### 1.2 循环形态：**既不是无限闭环，也不是有限三轮 —— 它是线性两段，无回流**

交互模型（图 3-7，p29，PDF 36）是**单向线性递进**：形成 → 整合精化扩展。没有「回到起点」的箭头，没有轮次徽章，没有反思迁移回流。**这一点很重要**：用户此前判断「谢鑫/方海光/柴兴祝/梁家健四篇都只画无限闭环」，吴君这篇是**第五种形态——线性无环**，比无限闭环还弱。用户图的「有限三轮 + 数据回流」相对它是**双重改进**（既给了轮次边界，也给了回流箭头）。

### 1.3 唯一的「有限迭代」在哪：**在研究层，不在教学层**

论文真正的有限迭代是**两轮准实验**（5.1，p45，PDF 52）：
- 第一轮（R1）：N=39（实验 21 / 对照 18），线上，问卷 → 得出改进方向
- **5.2.3 第二轮实验改进建议**（p50，PDF 57）：① 智能体提示词中「资源推荐技能的工作流程限定」优化，**将用户对话历史纳入资源检索的参考依据**；调整检索插件；优化交互设计使其「更自然地引导教师进行深度思考」。② 问卷题项修订（删/改低 CITC 题）+ 扩样本 + 加多模态数据。
- 第二轮（R2）：N=47（27/20），线上线下结合，加脑电+表情

→ **这是标准的「基于设计的研究（DBR）两轮迭代」**：每一轮有明确终点、有产出（改进清单）、下一轮带着修订版进场。作者自己在展望里也说未来应「结合行动研究或者是基于设计的研究方法，扩大使用范围以及实验观察周期」（p62，PDF 69）。

**对用户最有价值的一条实证**：R1 认知投入 **不显著**（t=0.199, p=0.843）→ 按改进清单改了提示词工作流 → R2 认知投入 **极显著**（3.93→4.52, t=−5.032, p=0.000）。**同一批设计、只改了智能体的提示词工作流与交互引导，效果从无到有。** 这是「有限轮次迭代不是装饰，每一轮的调整会改变结果」的**直接证据**，可以拿来支撑用户「三轮不是随便定的、每轮要有可交付的调整」的主张。

## 2. 智能体架构：单体 · 提示词驱动 · 五功能

### 2.1 职能切法（3.1.2，p25-26，PDF 32-33；结论复述见 p59-60，PDF 66-67）

**三大主功能 + 两大优化/基础功能**：
1. **知识点总结** —— 调课程专属知识库，分层输出 + **标注重难点** + 调 mind 插件出思维导图。理论挂钩：奥苏贝尔先行组织者。
2. **实时答疑** —— NLP + 知识库；四特点：快速响应、**多轮对话支持**、动态问题分析（结合上下文与语义匹配，避免机械回答，模糊问题补背景）。
3. **个性化学习资源推荐** —— 按兴趣/需求/进程推多模态资源；理论挂钩：媒体丰富度。
4. **知识点导览**（优化性辅助）—— 语义分析定位**视频中知识点位置 + 一键跳转**。
5. **基于对话**（基础形态）—— 其余功能全部经由对话实现。

**与用户「四职能」的对照**：

| 用户四职能 | 吴君对应 | 差距 |
|---|---|---|
| 学情感知 | **无独立模块**。仅在提示词里写「能够根据用户的互动情况判断用户的知识点掌握情况」，以及技能 4「总结用户之前的问题主要集中在哪个知识点」——**感知即上下文窗口**，无埋点、无落库、无画像 | 用户模型强得多 |
| 支架推送 | 知识点总结 / 导览 / 资源推荐（三个都是内容型支架） | 吴君更细，但全是「给内容」，没有「给方法/给提示」 |
| 学习分析 | **无**。分析全部由研究者用 SPSS 离线做，不在智能体内 | 用户模型强得多 |
| 评价生成 | 技能 4 生成测试题 + 核对 + 讲解 + 学习建议（**对学生**）；**对教师的评价/画像输出＝零** | 吴君缺「对师输出」这一整条边 |

**结论：吴君的切法是「学习者可见的功能（affordance）」，用户的切法是「智能体的职能（capability）」。**两者不在同一层。吴君的切法更靠近产品功能清单，用户的切法更靠近角色分工。用户的四职能里「学习分析」与「评价生成」易被读者理解为同一件事——吴君这篇提供了区分证据：**它把"生成测试题+讲解+建议"（评价生成）放在智能体内，把"六维/投入度聚合分析"（学习分析）放在智能体外（SPSS）**，说明这两件事在工程上确实可分离、且分离是常态。用户如果要坚持四职能并列，需要在文中说清"学习分析"是**面向教师的群体/过程聚合**，"评价生成"是**面向学生的个体即时判读**——否则会被审稿人指为重复。

### 2.2 单体 vs 多智能体

**单体**。一个 Coze bot，四个 skill 在同一段提示词里，靠自然语言分支路由（"当用户……时，执行以下步骤"）。无编排框架、无状态机、无 Agent 间通信。

作者在展望里明确点名了多智能体作为未来方向：
> 「学习支持也可以通过设计**多智能体之间的协同工作**来达到更好的支持。」（p62，PDF 69）

→ 这句可以作为用户论文中"单体不够、需要职能分化"的**同行呼吁式引用**。

### 2.3 与 LLM 的关系：纯提示词工程 + RAG（知识库）+ 插件

架构极简，但**提示词结构值得逐条抄**（表 3-1，p30-32，PDF 37-39）。骨架：`# 角色` → `角色背景` → `## 技能1..4`（每个技能：编号步骤 + `===回复示例===` few-shot 模板）→ `## 限制`。

**技能 2「问答引导」的回复模板（这是"助学不代学"的最小可行机制）**：
```
- <分析用户问题>
- <检索"课程知识"知识库，围绕用户提问的知识点生成回答>
- <基于回答，引导用户结合实际教学情境进行进一步思考的问题>
```
即：**每一次回答必须以一个引导性追问收尾**，且追问必须锚定"实际教学情境"。这是把苏格拉底性从"禁止写代码"（否定式约束）改成"必须追加问题"（**肯定式产出约束**）——后者更可测（可用正则/结构化输出校验"本条回复是否含追问"）。

**技能 4「生成测试题」的完整闭环（本篇最有工程价值的一段）**：
1. 有对话历史 → **总结用户之前的问题主要集中在哪个知识点**；无则跳过
2. 询问题量
3. 依知识库主知识点 + **对话历史中疑问集中的知识点加权出题**（"之前用户询问过的知识点的测试题可以适当多一些"）
4. 学生以 `；` 分隔提交答案
5. 逐题核对 + **详细讲解** + 语言激励 + 提出下一步学习建议
6. **根据错误点给学习建议 → 按建议调 bingWebSearch 推荐资源**

→ **这是一条完整的「学情（对话历史）→ 任务实例化（加权命题）→ 评价 → 诊断 → 再供给（资源）」链，全部在提示词里，零后端。**

**`## 限制` 四条**（p32，PDF 39）：
- 只围绕本课程，拒绝无关话题
- **每次回答一定要基于之前所有的对话内容**
- 语言简单易懂，所有内容围绕实际具体的教学场景，**并且启发用户思考**
- 输出内容的主题不能脱离知识点

## 3. 实施机制

### 3.1 培训流程（4.2.2，p44，PDF 51）—— 极简单，值得当"反例"

看 15 分钟视频 → 实验组与智能体**互动不少于 5 分钟** → 知识测试问卷 → 学习投入问卷 → 技术接受度问卷。

**没有任务下发、没有分组、没有教师在场、没有阶段推进控制。**"互动不少于 5 分钟"是唯一的过程约束——这暴露了一个真实的实施难题：**当没有任务链时，只能用"时长"当作交互量的替代指标。** 用户的 CX 若要论证任务链的必要性，这就是最好的对照：吴君只能规定"聊够 5 分钟"，用户可以规定"完成任务链的第 N 个任务"。

### 3.2 问题链 → 任务链：**没有**

课程内容是固定三模块（政策背景 / 教学设计原理与 LEARN 模式 / 具体案例），录播视频。不存在教师设计的问题链，也不存在智能体实例化的任务序列。**唯一的"依学情实例化的可执行序列"就是技能 4 的加权测试题**——这是任务链的胚胎形态（序列由学情决定、可执行、有反馈），但只覆盖"测评"一种任务类型。

### 3.3 数据回流：**离线、研究者中介、按轮次**

- 过程数据来源：问卷（TAM 七维度：使用行为/感知有用性/感知易用性/学习投入/学习效果/满意度/未来使用意愿）+ 知识测试分 + FaceReader 效价与唤醒 + 脑电注意力（70 分为注意力高低分界）
- 流向：**学习者 → 问卷/设备 → 研究者 SPSS → 提示词修订 → 下一轮**
- **教师（培训师）在整个回路中不存在。** 没有实时学情看板，没有干预入口。

→ 由此逼出一个对用户很有用的**概念区分**：
- **课中回流**（智能体 → 教师实时学情 → 课堂干预）——吴君完全没有；CX 的 `teacher/live` 有
- **课间/课程间回流**（沉淀数据 → 教研 → 备课修订）——吴君有，但由研究者手工承担；CX 的教研区 `studies` 状态机是它的产品化
用户图里"数据回流·反思迁移 → 回教师侧"这根箭头，如果不区分这两条，会被质疑"到底是实时还是课后"。**建议在图注或正文里把回流拆成双通道**。

### 3.4 人机权责边界

模型里**智能体就是教师**（"模拟'教师'身份"、"作为在线培训中 AI 教师角色"，p19/摘要）。没有"助学不代学"的表述，也不需要——培训场景里教师是成人学习者，智能体给出完整答案不构成"代做"。**这恰恰说明"助学不代学"是 K-12 编程场景的特有约束，用户不能引吴君来支撑它，只能引它来做场景对比。**

## 4. 支架与渐退：**方向相反，且无渐退**

**明确结论：本文无支架渐退机制，且其支架是"递增"的。**

- 递增维度一：**对话轮次**（形成阶段单轮 → 整合精化扩展阶段多轮，"轮次随认知任务复杂度增加而增加"）
- 递增维度二：**媒体丰富度**（纯文字 → 文字+图片+视频+动画+实时交互模块）
- 递增维度三：**即时反馈能力**（"教学智能体即时反馈能力增强"）

作者自述这叫"**分层、渐进的学习支持**"：
> 「总的来看，本模型能够使学习者在面对复杂学习任务时能得到**分层、渐进**的学习支持。」（p60，PDF 67）

**这不是矛盾，是必须做的切分。** 我的判断：支架至少要分两类，方向相反——

| 支架类型 | 例子 | 随进程应当 | 依据 |
|---|---|---|---|
| **内容/媒体型支架**（信息通道） | 多模态资源、图示、视频跳转、追问引导 | **递增**（任务变复杂，通道要更宽） | 媒体丰富度理论；吴君 p28-29 |
| **答案/代码型支架**（认知替代） | 示例代码、可提交解、直接答案 | **递退**（否则剥夺建构机会） | 用户模型；最近发展区 |

用户的"示例支架 → 提示支架 → 仅诊断点拨"三级递减只覆盖了第二类。**建议在论文里补一句"支架的双向调节"**：代码型支架递退的同时，诊断型/媒体型支架可以保持甚至增强——这样既回应了吴君这类"渐进增强"文献，又让"渐退"不至于被读成"越到后面帮助越少、学生越难"。这是一个能让审稿人眼前一亮的细化。

**撤除的操作定义：吴君没有。** 阶段切换靠学习者自己提出更复杂的问题，无判据、无阈值、无教师确认。→ 用户如果给出「第几轮给什么、依据什么撤」的可操作定义，相对本篇是纯增量。

## 5. 对用户模型的检验

### 5.1 支持

1. **三元关系的政策/理论背书（可直接引）**：课程内容第一部分明确写
   > 「教师、人工智能与学生之间的**三元动态关系**正在形成，这要求教师充分认识到 AI 在知识获取和应用方式上的重塑作用。」（p41，PDF 48）
   这是用户"师—机—生"三元结构在文献中的**同表述背书**，且紧接 UNESCO《教师人工智能能力框架》（获得/深化/创造三层次）。
2. **LEARN 模式提供"按阶段列三方权责"的现成表格体例**（p42-43，PDF 49-50）：Lead-in（课前）/ Engage·Excite（课堂开始）/ Adjust（课堂中）/ Reflect（课堂结尾）/ Navigate（课后），**每阶段都分别写"教师做什么、AI 助手做什么、学生做什么"**。这正是用户图里"每阶段师生机权责"需要的落地表。注意 Reflect 阶段"AI 助手收集、分析学生学习情况，生成课堂总结和知识归纳材料"、Navigate 阶段"AI 为学生生成个性化学习建议、推送延伸资源；教师掌握学生学习情况、设置课后实践活动"——**这是"数据回流→教师决策"在文献里最接近的表述**。（注：LEARN 的 E 在原文里 Excite / Engage 两处不一致，引用时按"Excite"写，标注阶段名"课堂开始"更稳妥。）
3. **有限轮次迭代的可行性证据**：两轮实验 + 轮间改进清单 + 认知投入从不显著到 p=0.000 的翻转（见 §1.3）。
4. **等效交互理论为"重点做生—机交互"辩护**（p19，PDF 26）：Anderson(2003)"只要有一种交互形式达到较高水平，其他交互形式可以相对减少甚至不提供，而不会显著影响学习效果"。→ 用户模型里"智能体承担高频交互、教师承担低频高价值干预"的分工，可以直接用等效交互理论辩护，而不必解释为"教师被边缘化"。
5. **多智能体协同被列为公开待办**（p62，PDF 69）——用户的多职能分化正好接上。
6. **形象/具身与情感投入**：吴君两轮实验情感投入均不显著，作者归因"本研究中设计的智能体**并不具有虚拟形象**可能是原因之一"（p61，PDF 68）。→ CX 有小狐/小枭具象角色，可引此作为"为何要做角色化 IP"的循证理由。

### 5.2 挑战

1. **"支架渐退"会被这类文献反驳。** 主流建构主义+媒体丰富度路线是"任务越难、支持越厚"。用户必须在文中主动区分支架类型（见 §4），否则"渐退"读起来像"越到后面越不管学生"。
2. **"三轮"的阶段推进判据缺失是共性硬伤，但吴君替用户暴露了后果**：吴君靠"复杂度自然上升"推进，结果只能用"互动≥5 分钟"当过程约束。用户如果也说不清推进判据，同样会退化成"每轮 X 分钟"。**判据必须写死**（例如：本轮任务链完成率 ≥ K 且调试事件收敛 → 允许进入下一轮）。
3. **四职能的"学习分析 / 评价生成"边界需要防重复指控**（见 §2.1 表后分析）。
4. **本篇没有教师角色，因此不能作为"师—机—生"模式的直接支撑**，只能作为"二元模式的局限"引证：其结论第 1 条自承交互模型局限于"学习者—智能体"，展望里才提"以更全面的视角去关注**'学习内容-学习者-教学智能体'三者间的交互**"（p62，PDF 69）——注意它补的第三方是"学习内容"，**不是教师**。这一点可以写成一句很有力的对比：「已有研究即便意识到二元交互的不足，其扩展方向仍是'学习内容'而非'教师'，教师在智能体教学模式中的结构性缺席尚未被系统回应。」
5. **替代切法提示**：吴君按「学习者可见功能」切，用户按「智能体职能」切。第三种可能更优的切法是**按"对谁输出"切**：对生（点拨/反馈）、对师（画像/诊断）、对内（感知/分析）。用户图其实已经画了"对师输出/对生输出"两条边——**可以考虑把四职能重排为"内部两职能（感知、分析）+ 外部两职能（支架推送→生、评价生成→师+生）"**，这样职能与箭头一一对应，图的逻辑更闭合。

## 6. 可落到 CX 的具体工程（对四个已知缺口）

### 缺口① 支架渐退无实现（`scaffold` 参数存在但无递减机制）
- 在 `backend/app/services/ai_service.py` 的 `build_system_prompt` 里，把 `scaffold` 从单一强度参数扩成**二维**：`code_scaffold_level`（示例码 → 提示 → 仅诊断，随 round 递减）× `media_scaffold_level`（文字 → 图示/可视化 → 视频/动画，随 round 可增）。理论依据直接引吴君 p28-29（媒体丰富度随认知复杂度递增）+ 用户的渐退主张，形成"双向调节"表述。
- 撤除判据用 CX 已有的 `ct_events` / 六维聚合（`ct.py`）：例如"上一轮示例支架调用次数 = 0 且调试收敛"→ 自动降一级；教师可在教学区手动覆写（保留人在回路）。

### 缺口② 任务链无实现（问题链→任务链的实例化缺失）
- **直接移植吴君技能 4 的加权实例化逻辑**：`对话历史 + ct_events 中的薄弱维度 → 加权生成本轮任务序列`。吴君的原句"之前用户询问过的知识点的测试题可以适当多一些"就是加权规则的最小表达。
- CX 第一版可以完全走提示词 + 结构化输出（要求 LLM 返回 `[{task_id, 目标CT维度, 支架级别, 通过判据}]` 的 JSON），不必先建表——这正是吴君证明的"零后端也能跑通"路径。教师端只需一个"审核/改写任务链"的确认位（吴君没有这一位，这就是 CX 相对它的改进点）。

### 缺口③ 三轮迭代在平台里无对应结构（`studies` 只有 pretest/running/posttest）
- 吴君的证据是：**教学层轮次与研究层轮次是两套东西**，硬塞在一起会拧巴。建议 CX **不动 `studies` 状态机**（它对应研究层的 DBR 迭代，和吴君两轮实验同构），另起一个**课堂会话层的 `round` 字段**（1=分解建模 / 2=算法实现 / 3=综合优化），挂在结对会话或作业实例上，由任务链完成度驱动推进。
- 论文里可以直接写：本平台在**研究层**（studies 的 pretest→running→posttest）与**教学层**（三轮迭代）分设两套推进机制，前者对应设计研究的轮次，后者对应课堂内的认知进程——这个区分本身就是相对已有文献（吴君只有前者、其余四篇只有后者的无限环）的贡献。

### 缺口④ 数据回流→教师策略调整无闭环
- 把回流拆成**双通道**并分别落地：
  - **课中通道**：`ct_events` → `teacher/live` 已有；补一条"轮次告警"（某学生第 2 轮仍在第 1 轮支架级别 → 推给教师）。
  - **课程间通道**：`insights.py` 结论卡 / `study.py` 对比报告 → 输出**下一轮备课修订建议清单**，体例照抄吴君 5.2.3「第二轮实验改进建议」（分"智能体功能优化"与"任务/测量优化"两栏，每条都要可执行）。这份清单本身就是用户图中"数据回流 · 反思迁移 → 回教师侧"那根箭头的**制品化证据**。
- 苏格拉底锁（`ai.py` 两 persona）加一条**肯定式产出约束**：领航员每条回复必须以一个锚定当前代码/任务情境的追问收尾（吴君技能 2 模板）。这比"禁止写完整代码"更好测——可在后端校验回复是否含追问句式，不含则重生成。同时把吴君的四条 `限制` 并入 `ai_navigator`：不脱离当前任务主题、每次回答基于全部对话历史、语言浅白且锚定具体情境、拒答无关话题。

## 8. 研读时的思考痕迹

- **一开始以为跑偏了**：标题是"教师培训对话"，场景是成人培训、录播微课、没有代码。读到第 3 章才意识到价值不在"模式"而在"提示词工程的可复制性"——技能 4 那一段是我在这一波文献里见到的**最完整、最省成本的"学情→任务→评价→再供给"闭环**，而且它证明了这条闭环可以完全不落库。CX 的任务链第一版应该照这个思路做，而不是先设计五张表。
- **最意外的发现是支架方向相反**。第一反应是"这篇要挑战用户的核心创新点"，但读完媒体丰富度那一节就明白了：吴君调的是**信息通道宽度**，用户调的是**认知替代程度**，两个东西被同一个词"支架"盖住了。这其实是用户论文的一个**送分题**——主动区分两类支架，既显得读透了文献，又把"渐退"从"少给帮助"洗成"精准降低替代性"。我认为这是本篇对用户最大的贡献，超过任何一句可引的话。
- **两轮实验的 p 值翻转让我改变了对"有限轮次"的看法**。原本觉得"三轮"是个略显武断的数字，但吴君 R1→R2 认知投入从 p=0.843 到 p=0.000，中间只改了提示词工作流（把对话历史纳入资源检索）——这说明**轮次的意义不在数字本身，而在"每轮之间必须有一份可交付的改进清单"**。用户论文里"三轮"要立得住，关键不是论证"为什么是三不是四"，而是给出**每轮之间的交付物是什么**（第一轮出分解模型 → 第二轮出可运行代码 → 第三轮出优化报告 + 反思迁移）。这个角度比纠结轮数更有说服力。
- **"互动不少于 5 分钟"这个细节我盯了很久**。它是整篇论文里唯一的过程性约束，也是没有任务链时的必然产物。CX 有任务链，就能把"聊够 5 分钟"换成"完成本轮任务链"，这在方法学上是从**时长代理指标**升级到**完成度真实指标**——值得在论文的"实施机制"一节点一句。
- **注意一处文本不一致**：LEARN 的 E 在 p42（PDF 49）同段内先写 "Excite" 后写 "课堂开始 Engage 阶段"。引用时建议写"Excite（课堂开始阶段）"并注明依原文，避免被查出转述错误。
- **一个没解决的疑问**：吴君的"知识建构四阶段"提出了形成/整合/精化/扩展，但建模时把后三个合并成一段，四阶段实际退化为两阶段。论文没解释为什么。我倾向于认为是**因为没有阶段推进判据，所以无法在整合/精化/扩展之间划界**——这反过来印证：**没有可操作的推进判据，再漂亮的阶段划分都会在实现时坍缩。** 用户的三轮如果不给判据，同样会在 CX 里坍缩成"一个长会话"。这是我给用户最强的一条警告。

## 苏格拉底追问（第二波·针对顶层模式图的批判性检验）

> 规则：每一条主张都问三件事——**依据是什么／换到初中结对编程+CX 还成立吗／最弱环在哪**。
> 本节的对话者是"用户的顶层模式图"，吴君这篇只作证据与反例来源。

### 追问链 1：三轮的**阶段划分依据**到底是什么？

**Q1.1｜"第一轮分解建模 / 第二轮算法实现 / 第三轮综合优化"的划分依据是什么？**
表面答：来自 CT 四要素（分解→抽象→算法→调试）的顺序展开。

**Q1.2｜再追问：CT 四要素是**思维成分**还是**时序阶段**？**
Wing 以来的 CT 要素从来是**并行的分析维度**，不是流程步骤——学生写第一行代码就会调试，做优化时仍在重新分解。把评价维度直接时序化，会推出一个荒谬结论：**第一轮不评算法、第三轮不评分解**。而 CX 的 `ct.py` 六维聚合恰恰是每次会话全维度出分的，模式图与平台数据结构在这里**已经打架了**。

**Q1.3｜三追问：吴君提供了什么先例？**
反例。他以建构主义提出"形成/整合/精化/扩展"四阶段（p27/PDF34），**建模时把后三个合并成一段**，四阶段实际退化为两阶段，全文未解释原因。我的判断：**因为没有阶段推进判据，所以无法在整合/精化/扩展之间划界。** 这条对用户是直接的：三轮若无判据，在 CX 里会坍缩成"一个长会话"。

**Q1.4｜四追问：换到初中场景，"一轮"的物理边界是什么？**
40 分钟一节课＋两人结对，三轮跑完不现实。那"轮"是课时？是作业实例？是结对会话？——**模式图没有回答，这是它当前最容易被追问倒的地方。**

**暂时的答**：把轮次的锚点从"CT 要素"换成"**可交付制品**"——
- 轮 1 交付：问题分解卡 + 数据/变量草图（对应"需求〔数据〕建模"）
- 轮 2 交付：可运行代码 + 一次通过的测试
- 轮 3 交付：优化说明 + 一道迁移题的解

制品定义边界（可跨课时、可挂作业实例），CT 四/六维**每轮全评**，只是权重不同。这样既给了"有限"以实体，又不与 `ct.py` 的全维聚合冲突。

---

### 追问链 2：**支架渐退**的操作定义——"怎么撤"？

**Q2.1｜依据是什么？** ZPD + scaffolding fading 的经典主张：支持随能力上升而撤除。

**Q2.2｜再追问：用户当前的撤除触发是"轮次到了"，这是**时间驱动**还是**能力驱动**？**
是时间驱动。经典 fading 的合法性完全建立在"能力已上升"这个前提上。**若学生第 2 轮仍不会，按轮次撤支架＝惩罚弱生**。讽刺的是，吴君那条"相反方向"的递增反而是能力/任务驱动的（复杂度上升→通道加宽，p28-29/PDF35-36）。**在"驱动源"这个更本质的维度上，吴君比用户更合规。**

**Q2.3｜三追问：那用什么信号判"能力上升"？CX 的 `ct_events` 够吗？**
不够。最直觉的信号"上一轮示例支架调用次数=0"有致命歧义：**弃用 ≠ 掌握**。学生可能是放弃求助、或者干脆放弃任务。单一负向信号不能作降级依据。

**Q2.4｜四追问：撤了之后能不能加回来？**
模式图画的是**单调递减**。但真实教学里支持一定是**可逆**的。单向箭头会让"渐退"在答辩现场被一句话打穿："学生第三轮突然卡住怎么办？"

**暂时的答**：渐退必须重写成**可逆的自适应策略**，三条写死——
1. **降级＝双条件合取**：`本轮任务链通过判据达成` AND `示例型支架请求率低于阈值`（只有低求助不降级）。
2. **升级（fade-in back）**：连续 N 次运行失败 / 同类错误重复率上升 / 停滞时长超阈 → 自动升回上一级，并向教师告警。
3. **人在回路**：教师可覆写任一级别，覆写动作本身入库（这是 CX 相对吴君"无守门人"的结构性优势，必须显性化）。

并在论文补"**支架双向调节**"：代码型（认知替代）递退 × 诊断/媒体型（信息通道）可增（引 Q2/Q3）。否则"渐退"会被读成"越到后面越不管学生"。

### 追问链 3：**四职能**（感知/支架/分析/评价）这个切法站得住吗？

**Q3.1｜依据是什么？** 功能完备性直觉——"看得见、给得出、算得清、评得准"。

**Q3.2｜再追问：四者是同一层的并列关系吗？**
不是。**"学情感知"与"学习分析"是同一条流水线的前后两段**（取数 vs 算数），并列会被审稿人指为切分维度不纯。吴君这里给了硬证据：他把"生成测试题+讲解+建议"（评价）放在智能体提示词里，把"投入度/效果聚合"（分析）放在智能体外用 SPSS 做——**说明二者工程上确实可分离，但它们的区分依据是"对谁输出"，不是"做什么"。**

**Q3.3｜三追问：有没有更闭合的切法？**
有。按**输出对象**切：对内（感知＋分析）／对生（支架推送＋即时点拨）／对师（画像＋过程诊断）。用户图上本来就画了"对师输出/对生输出"两条边，改成这个切法后**职能与箭头一一对应**，图的逻辑自洽度立刻上一档。

**Q3.4｜四追问：那放弃"四职能"的对称感值不值？**
不必放弃。可以保留四个名字，但在正文写死**两条正交轴**：
- 轴 A（处理阶段）：感知 → 分析
- 轴 B（输出对象）：支架推送 → 学生；评价生成 → 学生（即时判读）＋ 教师（诊断卡）

**暂时的答**：四职能保留，但必须补一句防重复指控的定义——"**学习分析＝面向教师的群体/过程聚合；评价生成＝面向学生的个体即时判读**"。这句话是吴君这篇替用户挡下的一刀。

### 追问链 4："**助学不代学**"能落成机制，还是只能当口号？

**Q4.1｜依据是什么？** K-12 编程特有的学术诚信约束。吴君完全不适用（成人培训里给完整答案不构成"代做"）——**只能引作场景对比，不能引作支撑**。

**Q4.2｜再追问：现在 CX 的实现形态是什么？**
`ai_navigator` 的**否定式约束**（禁止输出完整代码）。否定式约束的两个毛病：越狱容易；**不可验证**（"没写完整代码"很难自动判定）。

**Q4.3｜三追问：吴君有没有更好的形态？**
有，技能 2 模板：`分析问题 → 检索知识库作答 → 基于回答，引导用户结合实际情境进一步思考的问题`。这是**肯定式产出约束**——每条回复必须以锚定情境的追问收尾。**肯定式约束可被结构化校验**（后端检查回复末尾是否含追问、追问是否引用了当前代码行/报错），这是从"禁止"到"必须产出"的范式转换。

**Q4.4｜四追问：初中生扛得住连续追问吗？**
存疑，且有反面证据：吴君 R1 **认知投入 t=0.199, p=0.843 完全不显著**，说明"多轮对话"本身不自动带来认知投入；需求侧 N=213 里"模拟师生/同事讨论"综合得分 2.16 垫底。成人尚且如此，初中生被连问三轮不给任何着力点，很可能直接放弃或转去抄答案。**纯苏格拉底是有代价的。**

**暂时的答**：三层机制，缺一不可——
1. **结构层**：每条回复 = 一个可执行的下一步动作 + 一个锚定当前代码行/报错的追问（不许泛问"你觉得呢"），后端正则 + LLM 裁判双校验，不合格重生成。
2. **配额层**：连续纯追问 ≤ 2 轮，第 3 轮必须给**部分解**（一行提示 / 一段伪代码 / 一个反例输入），防挫败。
3. **计量层**：埋"追问率 / 追问被采纳率 / 学生自解率"三指标。**把口号变成可测三元组**——这才是能进论文"实施机制"一节的东西。

### 追问链 5：**数据回流 → 教师策略调整**，最弱环在哪？

**Q5.1｜依据是什么？** DBR / 形成性评价的常规主张：数据驱动教学决策。

**Q5.2｜再追问：吴君的回流是怎么发生的？**
问卷 + FaceReader + 脑电 → **研究者用 SPSS 离线做** → 写《第二轮实验改进建议》→ 修订提示词 → 下一轮。**教师（培训师）在整个回路中根本不存在。** 结论刺耳但重要：**回流的成本决定了它是否发生**。它之所以只发生在两轮之间，是因为它贵。

**Q5.3｜三追问：CX 课中回流的真实带宽是多少？**
一间机房 40 人、一节课 40 分钟、教师还要巡台。教师课中能真正消化的信息量上限大约 **3–5 条**。那么用户图上"对师输出＝**学情画像**"在课中就是**错的输出形态**——画像是高维只读物，教师课中没有解码预算。

**Q5.4｜四追问：那正确的课中输出是什么？**
**排序后的干预建议队列**：Top-3，每条含〔谁 / 卡在哪个 CT 维度 / 建议说的一句话 / 一键推送某级支架〕。画像与诊断留给课后。

**暂时的答**：把"数据回流"拆成两态并在图上分开画——
- **课中通道**（吴君完全没有，是 CX 的原创点）：`ct_events` → Top-3 干预队列 → 教师一键动作 → 动作回写。
- **课程间通道**（吴君有，但由研究者手工承担）：结论卡/对比报告 → **《下一轮备课修订建议清单》**（两栏：智能体功能优化 / 任务与测量优化，每条可执行）。

这份清单就是图上"数据回流·反思迁移→回教师侧"那根箭头的**制品化证据**。**最弱环点名：若不做带宽约束与制品化，这根箭头会成为整张图上最漂亮、落地最空的一段。**

### 本轮结论（给用户的三句话）

1. **"有限三轮"的价值不在徽章，在判据与制品。** 吴君 R1→R2 只改了提示词工作流，认知投入就从 p=0.843 翻到 p=0.000——**轮次的意义是"轮间必须有一份可交付的改进清单"**，不是"为什么是三不是四"。
2. **"渐退"必须切成两类且必须可逆**：代码型递退 × 诊断/媒体型可增，降级用双条件合取、升级用错误信号、教师可覆写。否则会被这类"支持随复杂度递增"的主流文献正面反驳。
3. **最该先写的代码不是表，是判据和提示词。** 吴君技能 4 证明了"学情→任务实例化→评价→再供给"完整闭环可以**零后端**跑通；CX 的任务链第一版应当是一个返回结构化 JSON 的提示词，加一个教师审核位——那个审核位正是 CX 相对全部已读文献的结构性增量。
