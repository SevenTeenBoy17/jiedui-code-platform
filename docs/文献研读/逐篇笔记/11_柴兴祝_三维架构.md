## 二、模式结构：三维架构 + 三范型（**无阶段、无轮次**）

### 2.1 纵向三层（图 1，p.74）

```
认知层  ──提供知识框架──▶  交互层  ──产生过程数据──▶  评估层
  ▲                                                      │
  └──────────── 反馈优化认知模型（策略实时调适）──────────┘
```

- **总闭环口径**：`数据感知 → 动态建构 → 反馈优化`（摘要 p.73、结束语 p.77 两次重复，是本文的核心口号）
- **层级闭环口径**：`认知层 → 交互层 → 评估层`，实现`感知 → 建构 → 反思`的**螺旋认知进化**（p.74）
- 三层各自定义：
  1. **认知层：知识网络的动态建构与认知赋能**（p.74）
     - 理论：建构主义；技术：知识图谱 + 思维链 CoT + 神经符号系统
     - 功能：多学科知识节点动态整合 → "可扩展的认知资源网络"；把静态知识库转成"动态认知数据集资源"
     - 例：物理"经典力学→量子力学→现代物理应用"跨层级知识联结
     - **本层被明确定义为提供"脚手架"的层**（p.74，引[7]建构主义）
  2. **交互层：情境驱动的沉浸式学习生态**（p.74）
     - 理论：情境学习；技术：多模态感知（眼动追踪/语音/手势）+ XR
     - 闭环：`情境沉浸 → 社会互动 → 需求化学习`
     - 例：历史课 AI 生成三维古战场 + NLP 模拟**苏格拉底式对话**（Socratic questioning，[9]）
  3. **评估层：数据闭环驱动的动态优化机制**（p.75）
     - 技术核心：**强化学习**；循环：`认知诊断 → 反馈优化 → 策略迭代`
     - 关键动作：实时识别**认知断层**（如数学解题逻辑偏差）+ 元认知可视化工具个性化反馈
     - **多模态数据反哺知识图谱优化**，实现从"结果评价"到"过程干预"的跃升
- **闭环运行 = "师生机"三元认知共同体**（p.75）：机制表述为`数据闭环 → 策略叠加 → 动态适应`

### 2.2 横向三范型（教学范式，p.75–76）

三重跃迁（p.75）：`单向知识传递 → 认知"脚手架"建构`；`静态教学设计 → 数据驱动的动态策略调整`；`低阶技能训练 → 高阶思维培养`。

| 范型 | 转向 | 理论底座 | 核心技术 |
|---|---|---|---|
| 元认知引导范型 | 被动学习 → 认知觉醒 | 建构主义 + 元认知[12] + ZPD[13] | 苏格拉底式提问链（NLP 驱动）+ 认知图谱 |
| 动态知识建构范型 | 线性传递 → 认知共生 | 认知科学/学习理论 → 人机共生[14] | 生成式 AI + 知识图谱 + 多模态学情感知 |
| 跨域协同探究范型 | 学科割裂 → 系统思维 | 跨学科学习 + 多元智能[15] | **多智能体协作系统** + 动态演化引擎 |

### 2.3 三张要素表（表 1–3，p.76）——本文**最可复用的结构**

三表统一采用 **5 列模板**：`核心要素 | 定义与内涵 | 技术支撑 | 教育功能 | 应用场景 | 潜在风险`。
每范型给 5 个核心要素。**"潜在风险"独立成列**是本文最值得抄的设计（见 §7.5）。

**表 1 元认知引导范型**
| 核心要素 | 定义与内涵 | 技术支撑 | 教育功能 | 应用场景 | 潜在风险 |
|---|---|---|---|---|---|
| 策略引导 | 设计**问题链**以引导批判性思维 | 规则引擎、认知图谱 | 促进深度思考 | 哲学课堂 | 可能抑制创造力 |
| 自我监控 | 实时反馈认知偏差 | 认知诊断模型 | 提升反思准确性 | 科学探究 | 可能引发焦虑 |
| 问题设计 | 生成**适配 ZPD** 的交互问题 | NLP、强化学习 | 激发高阶思维 | 历史教学 | 可能导致认知疲劳 |
| 效能评估 | 量化元认知能力指标 | **学习分析仪表盘** | 可视化认知发展 | 数学解题 | 可能忽略个体差异 |

| 系统思维培养 | AI 生成模型 / 复杂系统建模 | 系统思维提升 | 评估体系滞后 |
| 协作效能优化 | 虚拟协作平台 | 协作能力提升 | 文化偏见风险 |

### 2.4 ⚠️ 结构性判定：**无阶段划分、无轮次、无终止条件**

> 我特意逐句检索了"轮/阶段/第一/第二/第三/次序/终止"等表述。**全文没有任何时间序阶段划分**。
> 三层是**空间/职能分层**，不是时间阶段；三范型是**并列范型**（按学科场景选用），不是先后环节。
> 唯一带方向性的词是"**螺旋**认知进化"（p.74），但螺旋只是隐喻，无圈数、无收敛判据、无退出条件。

**结论：用户"四篇文献的模式图均只画无限闭环"这一判断，在本篇上完全成立，且比其余三篇更极端**——
其余三篇至少有环节名，本篇连环节都没有，只有三个并行的层。这对用户是**最好用的靶子**。

## 三、智能体架构：**分层切，不是分职能切**

### 3.1 切法对比（这是本篇对用户模型最有价值的一击）

| | 柴兴祝 | 用户 CX 模型 |
|---|---|---|
| 切分维度 | **纵向分层**：认知层 / 交互层 / 评估层 | **横向分职能**：学情感知 / 支架推送 / 学习分析 / 评价生成 |
| 切分依据 | 技术栈 + 数据流向（知识→情境→数据） | 教学动作 + 输出对象（对师 / 对生） |
| 层间关系 | 明确单向传递 + 一条反馈边（认知→交互→评估→认知） | 四职能并列，未声明彼此数据依赖 |
| 优点 | 数据流清楚，可映射到技术模块 | 教学语义清楚，可映射到师生权责 |
| 缺点 | 教学动作不可见，教师在哪一层不明 | **模块间数据流未定义**；无"交互/情境"位置 |

### 3.2 单体 vs 多智能体

- 主架构（三层）是**单体智能体的功能分层**，不是多智能体。
- "多智能体"只在**表 3 的一个要素格**里出现（技术支撑=多智能体系统，场景=可持续城市设计，
  风险=教师角色转型困难，p.76），正文对应段落（p.76 跨域协同探究范型）只给了一句
  "通过多智能体协作系统与动态演化引擎，构建'技术赋能→认知重构→协作共生'的三维架构"。
  **没有智能体角色划分、没有通信协议、没有仲裁机制、没有状态管理。**

### 3.3 与 LLM 的关系：**全是名词，没有一行工程**

点名的技术：知识图谱、思维链 CoT、神经符号系统、NLP、强化学习、情感计算、眼动追踪、XR/VR/AR、
规则引擎、语义关联算法、学习分析仪表盘、多智能体系统。

**未出现的词**：提示词/prompt、RAG、检索增强、工作流编排、上下文窗口、微调、Agent 记忆、
工具调用、API、任何框架名、任何模型名。技术词全部停留在"技术支撑"表格单元格层面。

> 研读判断：本篇**不能用于支撑任何架构实现主张**。它能支撑的只有"该切几块""每块叫什么名""每块的风险是什么"。

## 五、支架与渐退：**有支架，无渐退**（这是本文最大的空缺，也是用户最大的机会）

### 5.1 本文的支架表述（共 3 处）

1. p.74 认知层：知识图谱把静态知识库转为动态认知数据集，"为学习者提供了自主建构知识体系的
   **'脚手架'**[7]"——**支架被定义为"知识资源结构"**，而非"渐次撤除的助力"。
2. p.75 三重跃迁之一："从单向知识传递转向**认知'脚手架'建构**"——支架是目标态，不是变量。
3. p.75 元认知引导范型："建立'**机器追问→认知觉醒**'的**渐进机制**，规避认知过载与伦理风险"。
   - ⚠️ 注意是「渐**进**」不是「渐**退**」，且方向相反：这是**机器介入的递增**（追问逐步深入），
     不是支架强度的递减。**不能当成渐退支架的文献支撑**，否则是误引。

### 5.2 但本文两次说出了"需要渐退"的**理由**，却没给解法

这是可以直接拿来做论文对话的两个把柄：

- p.75："然而，**过度结构化也可能会抑制创造性思维**，需遵循《纲要》'着力加强创新能力培养'的原则"
- p.76 表 1「调节干预」潜在风险栏：动态调整认知负荷 → "**可能削弱自我调节能力**"
- p.76 表 2「多模态呈现」潜在风险栏："**技术依赖风险**"

> **研读时的想法（重要）**：柴兴祝把"支架过强会削弱自我调节 / 抑制创造力 / 造成技术依赖"作为
> **风险**列了出来，然后……就没有然后了。全文的处方是"教师协同决策""公平性约束算法""伦理审查"，
> 全是外部治理手段，**没有一条是从支架本身的强度设计上解决的**。
> 这正好是用户"渐退式支架 + 三轮递减"的靶心：**别人识别了病，没开药；我们开药，而且药是可量化的。**

### 5.3 支架渐退的操作定义：**本文给 0**

无"第几轮给什么"、无强度分级、无撤除判据、无触发条件。用户在这一维度上是**纯增量**，不是跟随。

## 六、对用户"师—机—生三轮有限迭代 + 四职能"模型的检验

### 6.1 强支持的部分

1. **"师生机"三元认知共同体 —— 术语级同构**。本文标题级关键词就是"'师生机'三元认知共同体"
   （p.73 关键词、p.75 第（四）节标题、p.77 结束语），英文 `teacher-student-machine ternary
   cognitive community`（p.78）。用户的"师—机—生"三元结构在本篇获得**独立的术语佐证**，
   且本篇明确把它作为**教学范式转型的落点**（"从'知识传递'向'认知共生'转型"）。
2. **智能体居中调解、双向输出**：本文"认知层为交互层提供知识框架，评估层反馈优化认知模型，
   最终实现教学策略的实时调适"（p.75）与用户"智能体对师输出学情画像、对生输出适时点拨"同构。
3. **四职能逐一有对应物**（可作为"四职能划分并非杜撰"的佐证）：
   - 学情感知 ← 表 2「**实时学情感知**」（捕捉认知状态与兴趣偏好；交互日志分析）p.76
   - 支架推送 ← 认知层"脚手架"p.74 + 表 1「策略引导/问题设计」p.76
   - 学习分析 ← 表 1「效能评估」**学习分析仪表盘** p.76 + 评估层"认知诊断"p.75
   - 评价生成 ← 评估层`认知诊断→反馈优化→策略迭代` p.75；"从结果评价到过程干预的跃升"p.75
4. **数据回流的正确方向**：p.75"利用多模态数据反哺知识图谱优化"——支持用户"数据回流"环节，
   且提示回流对象不应只是教师看板。

### 6.2 挑战 / 更好的替代切法（要认真对待的两条）

**挑战 A：用户四职能里缺一个"交互/情境层"。**
柴的三层中，**交互层**（情境沉浸、具身化学习环境、社会互动）在用户四职能中**无对应物**。
但 CX 平台恰恰有极强的交互层：Monaco/Blockly 双模、Pyodide 海龟绘图、PairDock 小狐⇄小枭结对。
用户模型把这些全部隐去了，等于把平台最有特色的一块从模式图里抹掉。
→ 建议：要么在"支架推送"下明确纳入"交互形态支架（Blockly↔代码、结对角色）"，
  要么承认四职能是**智能体的教学职能**，另设"承载环境"为底座（不算职能，但在图中作为底板出现）。

**挑战 B：分层切 vs 分职能切，可以合成二维矩阵。**
柴按数据流分层（有层间依赖、有方向），用户按教学动作分职能（无依赖声明）。
用户模型的隐患是**四职能之间的数据流未定义**——评审很可能追问"感知的输出是不是分析的输入？
分析的输出是不是评价的输入？支架推送依据谁？"
→ 更强的替代切法：保留四职能为**横轴**，加一条**纵向数据流链**：
  `感知(采) → 分析(算) → 支架(供) → 评价(判) → 回流(改)`，即把四职能串成有向链而非并列块。
  这样既保住用户的教学语义，又补上柴那种"层间有向"的架构严谨性。

**挑战 C（弱）：三范型是"按学科场景并列选用"，不是"按轮次递进"。**
若用户想说"三轮"，不能引柴的"三范型"做类比支撑——那是并列的三种范型（哲学课用元认知引导、
化学 AR 用动态知识建构、城市设计用跨域协同探究），不是三个先后阶段。**引用时须避免混淆。**

### 6.3 本篇是用户"有限三轮"论证的**最佳反例**

- 柴的闭环：`数据感知→动态建构→反馈优化`（p.73/p.77）、`认知→交互→评估→认知`（p.74）、
  `感知→建构→反思`螺旋（p.74）、`认知诊断→反馈优化→策略迭代`（p.75）、
  `数据闭环→策略叠加→动态适应`（p.75）——**五个闭环，全部无终点、无轮数、无收敛判据。**
- 一篇 6 页文里画 5 个无限闭环而不给一次"到此为止"的判据，正是"闭环美学掩盖可操作性缺失"的
  典型样本。用户以"第一轮·分解建模 / 第二轮·算法实现 / 第三轮·综合优化 / 数据回流·反思迁移"
  的**有限三轮 + 明确终止与迁移出口**，构成直接的方法论改进。
> 论文可写：「既有研究多以无限闭环刻画人机协同（柴兴祝，2025，p.74–75；……），闭环虽表达了
> 持续改进的意向，却未给出轮次边界与收敛判据，导致模式难以转化为可排课、可评估的教学序列。」

## 七、可落到 CX 的具体工程（对着四个已知缺口）

### 7.1 缺口①「支架渐退无实现」→ 本篇给**理由**和**风险指标**，不给机制

可直接工程化的是把柴的三条风险变成**渐退触发信号**（他只列风险，我们把风险变成阈值）：

| 柴的风险表述（出处） | 转成 CX 可测指标 | 触发动作 |
|---|---|---|
| 调节干预"可能削弱自我调节能力"（p.76 表1） | AI 依赖度 = 求助次数 / 提交次数；首次求助前自主编辑时长 | 依赖度超阈 → scaffold_level 降一级 |
| "多模态呈现→技术依赖风险"（p.76 表2） | 无 AI 通过率（关闭 AI 的检查点任务正确率） | 通过率达标 → 允许进入下一轮更低支架 |
| "过度结构化抑制创造性思维"（p.75） | 方案多样性（同一任务下不同解法比例）、design_create 埋点变异度 | 多样性走低 → 由示例支架切到仅诊断点拨 |

落地位置：`backend/app/services/ai_service.py::build_system_prompt` 增加 `scaffold_level ∈ {示例, 提示, 诊断}`，
由 `backend/app/routers/ai.py` 依「当前轮次 index + 上表依赖度指标」计算下发，而非仅透传前端 `scaffold` 参数。

### 7.2 缺口②「任务链无实现」→ 本篇给**实例化的判据变量**

柴的表 2 给出了任务实例化应依据的三个量：**知识盲点、认知负荷阈值、兴趣偏好**（p.76），
以及"动态知识重组：优化知识呈现路径与复杂度"（p.76）——即**任务链 = 知识图谱上的一条路径**。
→ CX 可做的最小版本：在 `ct.py` 六维聚合之上加一张**轻量概念-技能图**（节点=概念，边=先修关系），
问题链（教师制品）挂到概念节点上，任务链 = 由学生盲点集合 + 负荷阈值在图上求出的一条最短可行路径。
这比"教师手动推送资源"高一档，且不需要真的上知识图谱数据库（SQLite 一张 `concept_edge` 表足够）。

### 7.3 缺口③「三轮迭代平台无对应结构」→ 本篇**帮不上**，是用户的原创区

柴的 `studies` 类比物不存在。唯一可借的是把柴的 `感知→建构→反思`（p.74）
当作**每一轮内部的微循环**（轮内三拍），与用户"三轮"形成 3×3 的时间结构：
`轮 i ∈ {分解建模, 算法实现, 综合优化} × 拍 j ∈ {感知, 建构, 反思}`。
→ CX：`studies` 的 `pretest/running/posttest` 是**研究阶段**，与教学三轮正交，别混用。
  建议新增 `teaching_round` 字段（1/2/3）挂在 `ct_events` 与作业任务上，让六维数据可按轮切片，
  这样"支架递减是否奏效"才可验证（同一学生跨三轮的依赖度曲线）。

### 7.4 缺口④「数据回流→教师策略调整无闭环」→ 本篇给**一条关键设计原则**

p.75："利用多模态数据（语音、手势、眼动）**反哺知识图谱优化**"。
关键在"反哺的对象是知识结构本身，不是仪表盘"。CX 现状 `insights.py` 生成结论卡是**只读呈现**。
→ 工程动作：给结论卡增加**可执行回写**——每张卡带一个 `action`（如"下调第 3 轮支架""把概念 X
  重新插回任务链""对 N 名学生开启苏格拉底锁"），教师一键确认后**写回任务链/支架参数表**，
  并记录 `teacher_decision` 事件。这才让"数据回流→教师策略调整"从箭头变成代码。

### 7.5 额外可抄的一招：**风险标注矩阵**（本篇最好的形式创新）

柴的三表都把"潜在风险"作为**独立一列**与"教育功能"并置（p.76）。
→ 建议 CX 在 `docs/` 建一张《智能体四职能 × 风险 × 护栏》表：每个职能声明其风险与已实现的护栏
（学情感知↔隐私泄露↔PII 打码；支架推送↔代做/削弱自我调节↔苏格拉底锁 + 渐退；
学习分析↔忽略个体差异↔六维分位而非均值；评价生成↔算法偏见↔教师复核）。
这既是工程文档，也直接对应论文里"人机权责边界"一节，把"助学不代学"从口号变成可审计的表格。

## 十、研读思考痕迹（留档）

- **第一印象与修正**：题目里的"三维架构"让我预期是"师/机/生三维"或"感知/分析/干预三维"，
  读完发现是**认知/交互/评估三层**——与用户模型的三元不是一回事。若在论文里并置引用，
  必须写清"柴文之'三维'指架构层级，与本研究之'三元'（师—机—生）不同"，否则会被评审抓。
- **最意外的一点**：全文 5 个闭环，一个终止条件都没有。这不是疏忽，而是这一类"范式文"的
  共同写法——闭环是修辞而非机制。用户的三轮徽章之所以是真改进，正因为它把修辞变成了排课单位。
- **最大的遗憾**：三张表的"潜在风险"列质量出乎意料地好（削弱自我调节、技术依赖、抑制创造力），
  几乎是把"为什么需要支架渐退"完整论证了一遍，然后作者转身用"伦理审查/公平性算法"这类治理
  话术把它盖过去了。用户完全可以在文献综述里写："已有研究已识别支架过载之风险（柴兴祝，
  2025，p.75–76），但其对策止于外部治理，未触及支架强度自身的时序设计。"——这一句能立住。
- **对 CX 最实的一句**：p.75 那句编程调试例（调试行为 → 思维链指导 → 回写知识图谱结构）
  几乎就是 CX 缺口④的原型描述。可惜作者只写了一句、没有下文；但作为"设计意图的文献出处"，
  它比自己凭空提出要有力。
- **不要过度使用本篇**：它没有系统、没有数据、没有实施细节，刊物层级低。定位应是
  **"术语佐证 + 反例靶子 + 风险清单来源"**，共 3 处引用为宜，超过 5 处会拉低综述可信度。

## 苏格拉底追问

> 本节不复述研读结论，只做一件事：对「用户顶层模式图」和「本篇的可用结论」逐条追问
> ——**依据是什么 / 换到初中结对编程+CX 还成立吗 / 最弱环在哪**，直到问出可落地的改动。

### 追问链 A：「三轮」的合法性到底来自哪？（针对用户自称的差异化点）

**Q1｜三轮的划分依据是什么？**
表面答：三轮 = 分解建模 / 算法实现 / 综合优化，对应 CT 要素。

**Q2｜追问：CT 是四要素（分解·抽象·算法·调试），轮次却只有三个。抽象和调试去哪了？**
图上的处理是：抽象标"师导"、调试标"接评价链"，都被挂在环上而不占轮次。
于是**第三轮"综合优化"不对应任何一个 CT 要素**——它是迁移/整合，不是 CT 的第四项。
→ **裂缝暴露**：三轮不是从 CT 四要素推出来的。CT↔三轮的映射不整齐，这是图上最容易被评审戳的一处。

**Q3｜再追问：如果不是从 CT 推出来的，"三"从哪来？**
最诚实的答案：从**支架档位数反推**。示例支架 / 提示支架 / 仅诊断点拨 = 三档，
三档之间有两次降级；若要求"每轮降一档且最后一轮已到最低档"，恰好需要三轮。
→ 即：**轮数 = 支架档位数**，这是一个**工程决定论**，不是教学理论推导。

**Q4｜最弱环在哪？**
评审必问："为什么不是两轮或四轮？"若答"因为 CT 有三个环节"，会被 Q2 打穿；
若答"因为支架有三档"，会被反问"支架为什么是三档"，形成循环论证。
**"三"这个数字本身承受不了论证重量。**

**Q5｜那真正的差异化点是什么？**
把本篇当反例重读：柴 6 页画 5 个闭环，缺的**不是"闭环画成了圆"，而是"没有任何一处说何时停"**。
用户真正超越文献的，不是"三"，而是**给出了退出条件**。
→ **暂时的答（重构口径）**：
> 主张应从「**三轮**有限迭代」改为「**带收敛判据的有限轮迭代，在初中编程课时结构下典型收敛于三轮**」。
> 收敛判据（可证伪、可埋点）：`支架档位已降至最低档` ∧ `无AI检查点通过率 ≥ 阈值` ∧ `依赖度 ≤ 阈值`。
> 三轮 = 该判据在"一个教学单元 3 课时"约束下的**经验落点 + 排课单位**，不是理论常数。
>
> 这个改口径有三重好处：①"为什么是三"从理论争议变成经验数据问题（可用 CX 六维数据回答）；
> ②反而更打文献的脸——别人连"停"的判据都没有；③留出"未收敛学生进入第四轮补偿"的口子，
> 避免"三轮"变成对慢生的截断。

---

### 追问链 B：支架渐退换到「初中 + 结对编程 + CX」还成立吗？

**Q1｜渐退的单位是谁？**
用户图上说"智能体代码支架随三轮递减"，主语默认是"学生"。
但 CX 的学生端是 **PairDock 结对**：两名学生 + 两个 AI 角色（小狐驾驶员 / 小枭领航员）。
→ 追问：小马依赖度低、小华依赖度高，**降级降给谁**？

**Q2｜三种候选各自的坏处**
- 按**班级**降：教师侧最好排课，但对弱生是灾难（第三轮直接断供）。
- 按**结对**降：结对的依赖度是两人混合信号，强者会把弱者"拉过线"，弱者被误判为可降级。
- 按**个人**降：教学上最合理，但同一个屏幕上两人看到不同强度的 AI——技术可行（双 persona 本来就分离），
  **教学风险是污名化**：弱生知道"我被留在示例档"。

**Q3｜最弱环在哪？**
**渐退的粒度单位、可见性、以及"降到底之后是什么"三项全部未定义。**
尤其第三项：图上第三轮是"仅诊断点拨"，再往下就是"没有帮助"——
但初中生在"没有帮助"的状态下不会产生高阶思维，只会卡死或抄袭。**渐退不能以"归零"为终点。**

**Q4｜CX 有没有比"归零"更好的终点？**
有，而且是 CX 独有的：**把帮助从"机"移交到"人"**。
→ 渐退阶梯改为四档三退：
> `① AI示例支架（小狐可写整段代码）→ ② AI提示支架（小狐只写骨架/伪代码）→
>  ③ AI仅诊断点拨（小狐停写，小枭提问）→ ④ 人类同伴接管（AI驾驶员关闭，同伴任驾驶员，AI只做旁证）`
三次撤退，恰好三轮，**且"三"第一次有了非循环的依据：三次撤除动作**。
更重要的是：这让 PairDock 从"交互特色"升格为**渐退机制的承载体**，
直接回应柴对用户模型的挑战 A（四职能缺交互层）——交互层不是缺席，是**支架的物质形式**。

**Q5｜可见性怎么处理？**
**降级不广播、升级才广播**：档位下调对学生不显式提示（只体现为 AI 回答风格变化），
档位上调（如"你已解锁自主模式"）给正反馈徽章。教师端可见完整档位表。

### 追问链 C：四职能到底该怎么切？（正面回应柴的挑战 B）

**Q1｜研读结论建议把四职能串成有向链 `感知→分析→支架→评价→回流`。这条链成立吗？**
追问一句就塌：**在 CX 里，"支架推送"真的发生在"学习分析"之后吗？**
- 支架推送是**实时**的：学生在 IDE 里问小海龟，SSE 流式回，秒级。
- 学习分析是**批量**的：`ct.py` 六维聚合，是课中/课后定时算出来的。
→ 把二者串进同一条链，会造成**时间尺度混淆**：链条上游的"分析"根本来不及供给下游的"支架"。

**Q2｜那正确结构是什么？**
不是一条链，是**两个不同时间常数的回路**，共用"学情感知"作入口：

| 回路 | 路径 | 时间常数 | CX 技术载体 | 决策主体 |
|---|---|---|---|---|
| **快回路（生侧）** | 感知 → 支架推送 → 学生行为 → 感知 | 秒–分钟 | WebSocket `/ws/pair` + AI SSE 流 | 智能体自动 |
| **慢回路（师侧）** | 感知 → 学习分析 → 评价生成 → 数据回流 → 教师策略 → 支架参数 | 课时–单元 | `ct.py` 聚合 + `insights.py` 结论卡 + 教师确认 | 教师（机辅） |

**Q3｜这个切法比柴的"分层"和用户的"分职能"强在哪？**
- 柴按**技术栈**切（认知/交互/评估）→ 教学动作不可见。
- 用户按**教学动作**切（四职能）→ 数据流不可见。
- 按**时间尺度**切 → 二者都可见，**且直接对应 CX 已存在的两套工程设施**（实时通道 vs 定时聚合）。
→ **模式图的改法**：四职能保留为图标，但用两条粗细/虚实不同的回路把它们串起来并**标注时间常数**；
  "渐退决策"必须画在**慢回路**上（因为需要跨轮次证据），"适时点拨"画在**快回路**上。
  这一改，同时补掉"四职能并列无依赖"和"渐退何时触发"两个洞。

**Q4｜最弱环？**
两回路的**同步点**没定义：慢回路算出的 scaffold_level 什么时候生效？课中即时生效会造成
"学生正问着话 AI 突然变冷淡"。→ 答：**档位在轮次边界生效**（下一轮任务开启时），轮内恒定。
这也反过来给"轮"一个功能定义：**轮 = 支架档位的保持区间**。（这是本轮追问里最漂亮的一个副产品）

### 追问链 D：数据回流，到底回流到「什么」上？

**Q1｜柴给的原则是"反哺知识图谱优化"（p.75），CX 有知识图谱吗？**
没有。追问：造得起吗？初中 Python 的概念集很小——变量/输入输出/条件/循环/列表/函数/海龟绘图/调试，
量级 20–40 节点，先修边可由教师手工标注。**造得起，且不需要图数据库**（SQLite 一张 `concept_edge` 足够）。

**Q2｜但回流改的到底该是什么？三个候选：**
①支架档位　②任务链上的题目序列　③教师设计的问题链本身。
追问：如果回流只改①②，那 CX 和一个自适应练习系统没有区别，**"师"在闭环里是纯装饰**。
用户模式图的整个左侧（教师·教学调控环）就落空了。

**Q3｜柴哪句话提示了正解？**
p.77"教师转型**认知架构师**"。架构师改的是**结构**，不是参数。
→ 所以回流的最高级目标必须是 ③：**教师的问题链制品本身**。
数据回流告诉教师"你第 2 轮设计的问题 3 有 70% 学生在此断裂"，教师**修改问题链**，下一轮/下一班用。

**Q4｜落地形态？—— 三级回写，按权限与可逆性排序**

| 级 | 回写对象 | 谁能写 | CX 落点 |
|---|---|---|---|
| L1 | `scaffold_level`（支架档位） | 机器自动（规则可审计） | `ai.py` 依指标计算下发 |
| L2 | 任务链路径（跳过/插入概念节点） | 教师一键确认 | 结论卡 `action` + `concept_edge` |
| L3 | 问题链（教研制品）本身 | 教师手动编辑 | 教研区 `studies` 的真正用途 |

→ **用户模式图的改法**：把"数据回流"那一根箭头**拆成三根**，标注权限。
  这一改，"人机权责边界"就不再是口号，而是图上可数的三条边。

**Q5｜最弱环？**
L3 需要教师有跨轮/跨班的对比证据，否则改问题链是拍脑袋。
→ 这恰好要求追问链 A 的 `teaching_round` 字段先落地：**没有轮次切片，就没有 L3**。

### 追问链 E：「助学不代学」怎么从口号变成不可绕过的机制？

**Q1｜现状是什么？** 两 persona（`ai_navigator` 拒写完整代码）+ 教师可下发的苏格拉底锁。

**Q2｜追问：这是什么类型的约束？**
是**输出侧、单次、二值**的约束：每一次回复不给完整代码 / 锁开或关。

**Q3｜可绕过吗？**
可以。初中生完全能做到：分三次问，每次要一小段，自己拼起来。
**单次输出约束对累积行为无效。** 而且苏格拉底锁是二值开关，与"连续渐退"在语义上是冲突的
（锁一开就从档①跳到档③，中间没有档②）。

**Q4｜最弱环？**
**缺少会话级/任务级的累积约束。**

**Q5｜有没有不可绕过的形式？**
有：**预算制**。本轮任务内，AI 可提供的"可运行代码行数"和"提示次数"有配额，**配额随轮次递减**。
- 配额是累积量，分次索取无法绕过；
- 配额与个人档位挂钩：弱生档位高、配额多，**不会一刀切伤害弱生**；
- 配额耗尽不是断供，而是**自动降级为提问**（小狐停写、小枭接管）——与追问链 B 的四档阶梯同构。

→ **"助学不代学"的三重机制（可审计）**：
> ① 输出侧：不产出可直接提交的完整代码（现有 persona 规则）
> ② 会话侧：本轮 AI 代码行数 / 提示次数**预算**，随轮递减（新增）
> ③ 验证侧：**无 AI 检查点**——关闭 AI 的小任务通过率，作为进入下一轮低支架的**准入门槛**（新增）
柴文在这一维度上**完全空白**（甚至有"生成动态模拟方案"的代做倾向，p.76），
所以这不是跟随，是**用户的原创约束**，且现在有了三条可写进代码的边。

### 追问收敛：本轮问出来的、原研读没有的四个结论

1. **"三轮"不该单独承重**——改主张为"有限轮 + 可证伪的收敛判据"，三轮是经验落点。差异化在**判据**不在**数字**。
2. **轮 = 支架档位的保持区间**——这是"轮"在工程上的功能定义，也解决了"档位何时生效"的同步问题。
3. **渐退的终点是"机→人"而非"有→无"**——PairDock 从交互特色升格为渐退载体，同时补掉柴指出的"缺交互层"。
4. **四职能应按时间尺度切成快慢双回路**，而非串成一条链；数据回流应拆成 L1/L2/L3 三条带权限的边。
