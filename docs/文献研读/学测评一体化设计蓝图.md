# 「学·测·评一体化」设计蓝图（v1）

> 定位：把前/中/后/延迟测全流程收进平台，站在 CX 已有的 `draft→pretest→running→posttest→closed` 状态机、ct_v1 18 题蓝图、AssessmentView、ct_criterion 四时点之上，补齐「中测通道、评分-反馈边界、数据回灌教学」三块，并接入 CodeAgent 独有的代码沙箱与 monitor/activity 事件流。依据为 16 篇文献 + CX 平台自查共 99 条再研读发现。

## 一、文献给出的运营化铁律（逐条带出处）

**铁律1：前测不可省，不可用既有成绩替代。** 汤倩雯纯后测导致效应无法归因且摘要与正文口径矛盾（01, p.83-85）；王玉雯用期末班均值 80.6 当基线，个体增益与前测分层分析全部无法起步（08, p.66-67）；吴君自认「未做前测分组是硬伤」（16, p.61）。→ pretest 是状态机硬关口，期末分只可作效标关联变量进 ct_criterion，绝不当基线。

**铁律2：平台内发收是回收率的决定性变量。** 线下纸卷回收率 63%、近四成数据蒸发（01, p.85-86）；线上发收 94-96%（02, p.55-56）；测评做成流程强制出口节点则零丢样（16, p.44-45：39/39、47/47）；测评运营成本高时研究者会整体放弃测量（05 全文零测量，p.73-75）。→ 全部测评走 AssessmentView，发布成本压到「点一下」。

**铁律3：前后测必须同工具同版本，换题必须实证等值。** 四套卷仅靠专家目测等难，零效应无法解释（04, p.44）；三张不等值卷直接画折线比「提升」（06, 附录2-4）；两轮换卷跨轮不可比（16, p.49-55）。→ 等值靠「题对/题组同蓝图同难度带」+ 跨卷锚题（silent probe 即两波天然客观锚），难度 p 值逐题落库回填，第二轮起有实证等值数据。

**铁律4：量表按构念分类管控。** 体验类量表（心流、满意度、AI帮助感）在前测施测时经验对象为空，前后比较无意义（04, p.40-44）；体验问卷只发实验组则无参照系（08, p.69-73）；可用性量表挪测动机、自编题冠标准量表名会被一票否决（马金帅, p.70-71）。→ 题库打「状态/能力类 vs 活动体验类」标签，状态机在 pretest 阶段禁止拉取体验类题块（可写进代码的防呆）；体验问卷全体统一触发。

**铁律5：反馈时机的练习/测评分界。** 「答错即显正确答案」只可用于练习（李昊东, 正文p27-28）；追问式批改反馈严禁考中出现（08, p.59-61）；「错误原因+修改示例+关联知识点」三段式解析只在练习/中测态开放（09, 刊页66）；CX 刻意只回 total 不逐题回显以保后测等值（CX study.py:482-519）。→ pre/post：零反馈直至交卷、交卷后也不回显逐题对错；练习/probe：可开三段式反馈但不得复用 pre/post 题面。

**铁律6：自动评分分层，确定性证据先行。** 编译/AST/测试用例先行、LLM 只做语义匹配层（02, p.28-29）；LLM 链路 40 秒空窗引发重复提交、污染行为指标（02, p.72）；「自动判分」在实现章退化成人工评阅的设计-实现脱节实锤（刘伯成, PDF p.47-48）。→ 客观题与测试用例秒级同步判分落库，LLM 维度异步补发并显示「评分中」；自动化承诺必须有端到端浏览器测试证据，判分延迟是验收指标（对标石斯瑾 SLO：响应≤2s、并发≥50、覆盖率≥90%，04, p.78）。

**铁律7：AI 评分上线前必须做金标准抽检。** 要点级金标准（先共标校准再独立标，一致性 0.83）报 P/R 而非笼统准确率（06, p.77-79）；双人背对背标注→分歧协商→提示词带前后文上下文→90% 一致率放行线，且预期初期波动（15, p.45-48）；输出必须 schema 强校验 + 类别优先级仲裁规则写进提示词（15, p.45-46）；纯文本 LLM 判不了动作类行为，指标先做「文本可判性」审查（15, p.49）。

**铁律8：测评期 AI 管控是文献空白，属我方原创。** 学习期防依赖做得细、测评期无一字（01, p.59、p.82）；唯一同构先例是「先独立初诊（禁AI）→提交锁定→再放开AI」的两段式（07, p.34）。→ posttest/probe 期 AI 通道技术性熔断 + 初稿锁定，写方案时作为创新点陈述。

**铁律9：独立作答靠架构保证而非事后鉴定。** 教师肉眼判「AI生成比重>50%」不可复现（12, 刊页47-48）；可行方案是风险旗标+教师口头核验的人机分工，且组合指标优于单阈值（02, p.59/50/72）；交互日志即答卷附件（10, 刊页51）。→ 独立性从「评分维度」降级为「平台自动指标」：AI 贡献比、粘贴事件、服务端时长，组合成 risk_flag 推教师端。

**铁律10：乱答/敷衍必须机器检测并留审计痕迹。** 106/106 全有效说明乱答混进了结论数据（06, p.83、91-93）；「有效答卷」黑箱筛除是幸存者偏差模板（01, p.85-86）；剔除规则须在 pretest 前预登记、报告报流失表（07, p.35 反例 50→45 零交代）。CX 的 too_fast/straightline→剔除→caveats 如实报告整套可搬，但 duration 是前端自报可伪造（CX AssessmentView.vue:68,81）——服务端记「下发-提交」时间差。

**铁律11：测评数据必须有预设消费方，否则等于没测。** 批改数据死在对话里、80% 效率提升无测量来源（08, p.78-80）；报告存学生本地 PDF、教师与排课引擎都读不到（李昊东, 正文p28、46）；诊断讲得漂亮但不回流任何一轮教学（12, 刊页48）；正面样本：课前复习答题按 60 分门槛机读驱动排课配比（李昊东, 正文p21）、横比+纵溯+归因干预三阶链路（13, p.113）、弱项定向推送双环（马金帅, p.39-40）。→ 每个测评点在设计期绑定分析承诺与回流动作，「采了不算、算了不报」（03 知识小测零报告，PDF p.46）禁止发生。

**铁律12：报告统计纪律。** 单班规模必须并报效应量 d 与置信区间，禁止只报 p（16, p.49-55：p=0.053+d=0.641 扩样后显著）；天花板/方差压缩要自动检测（12, 刊页48：SD 20.91→7.30 未讨论；01 编程测试 5.00/8 撞顶）；对照/全体同涨触发「疑似重测效应主导」标注（03, PDF p.69-71）；主客观证据分栏、自评只做辅证（12「自评显著客观不显著」经典模式；10 混排反例, 刊页54-55）；各效标 n 对齐一致性校验（01 的 33/43 vs 36/40）；心理测量指标由后端单一来源自动算出直接渲染，禁人手誊抄（06 的 α 0.874 vs 0.963 自相矛盾, p.82-83）。

**铁律13：中测不另设考试，嵌在活动边界。** 「不及格保持激活+重试全记录」让日常作业即中测（02, p.49-52）；测评点嵌在练习阶段边界的重复测量（04, p.88-89）；表单字段绑定认知构念、日志即测评（07, p.38）；过程流自动编码 500+ 节课验证可行（15, p.38-39）。频次剂量上限：每周一次（07 的 8 周 8 案例）。过程数据只进教师参考视图，不做个体效果主张（07, p.31/35/37：过程量规无先例）。

**铁律14：界面与交互细节。** 单题单屏+进度可视+409 幂等（CX AssessmentView）；选项位置随机化防位置记忆与邻座抄袭（李昊东, 正文p27-28）；测评前 2 分钟工具适应演练页，把操作生疏从测量误差剥离（04, p.40-41）;分节限时优于单题限时（04）；实时反馈不弹分数排名以防焦虑（11, 刊页76 风险清单）；打字慢/交互障碍会系统性低估思维水平，输入耗时应作协变量（03, PDF p.58-61）；「先思考-后求助-再验证」规范进学习轮任务文案（01, p.59）。

## 二、功能设计（后端）

### 2.1 状态机扩展

主相位不动：`draft→pretest→running→posttest→closed`，另有 delayed 时点走 ct_criterion。扩展三处：

```
running 期新增子事件（不改主相位）：
  probe_open(round_id)  → probe_submit / probe_close
  warmup_open(round_id) → 轮前复习小测（复用上轮错题池，李昊东式）
closed 后新增：
  delayed_open（延迟测发卷窗口，默认 post 后 2-4 周，可配置）
```

- **闸门规则分级**：pretest 收卷率 <60% 阻断进 running（现有 PRE_DONE_GATE，可 force 留痕）；probe 收卷率只警告不阻断——中测漏几个人不该卡教学进程；无 posttest 收官拦一道（现有）。
- **时点混染防呆**：posttest 时段拒绝补交 pretest（杨瑞珍教训，03）；probe 只在所属 round 的开放窗口内可交。

### 2.2 中测（probe）发卷通道

- `assessments.kind` 扩为 `pre | post | probe | delayed`；`assessment_responses` 加 `round_id` 可空外键（轮外测评填 NULL，遵循 ct.py「轮外事件不硬归轮」原则）——不动现有 schema 任何行。
- **题库结构**：seed_ct_v1 的「维度×难度组题对」扩为三元组 `(pre, probe_pool, post)`，probe_pool 每维 2-3 题轮换使用；六维交错排列逻辑零改动（防中途放弃者维度系统性缺失——15 分钟中测弃答率更高，此细节更关键）。
- **silent probe 形态**（轮末 5 分钟）：AI 通道熔断（navigator/driver 均只读不答）、下发 2-3 道客观锚题或一个微型编程任务、服务端记录窗口内全部 IDE 事件。probe 分落 `ct_criterion(phase=probe)`，复用其 `(study,student,phase,instrument)` 唯一键+覆盖式录入。
- **初稿锁定**（07 两段式移植）：learning_round 任务加 `draft_lock` 事件——学生在 AI 只读态提交首版方案，服务端落库不可改，再开 AI 协作；(初稿, 终稿) 差值为轮内过程指标，与 probe 互为印证，零额外课时。
- **挫败态标记**（03 移植）：probe 中连续 N 次无实质作答（空提交/秒过），该次标 `frustrated` 不计入能力估计，而非记低分。
- **学生入口对账**：现有 `GET /my/assessments` 端点已封装但全站零调用——本次必须接 UI 并走端到端，否则重蹈「posttest 恒 NULL」覆辙（CX study.py:62-68 历史教训）。

### 2.3 自动评分与即时反馈边界

| 题型 | 评分方式 | 反馈时机 |
|---|---|---|
| 单选/多选/判断/排序 | 规则引擎，**提交时算分落库**（禁事后重算，防题目改版污染历史卷） | pre/post：交卷后仅中性完成态；probe/练习：可给三段式解析 |
| 编程实操题 | 沙箱跑测试用例（CodeAgent code_executor 独有底座）+ AST 结构分（Python ast 模块），权重照抄梁家健 rubric 按 K12 下调（02, p.28-29） | 编译/用例结果秒级同步回；练习态即时，测评态延迟到交卷后 |
| 编程题语义层 | LLM 仅做「需求-实现语义匹配」单层，异步补发，UI 显示「评分中」 | 异步回填，不阻塞下一题（防 02 的 40 秒重复提交坑） |
| 开放题/反思 | LLM 初评（schema 强校验 JSON + pydantic 兜底 + 仲裁规则写进提示词）+ 教师抽检 10% 报 Kappa | 仅练习态 |
| 过程量规（调试循环质量等） | **不自动出分**——无文献先例（07），只进教师参考视图 | 不反馈学生 |

多选题部分给分规则在蓝图层显式定义（16 未写即坑）。AI 评分上线前执行 15+06 合并流程：双人背对背标注→协商金标准→few-shot 校准→要点级 P/R + 90% 一致率放行。

### 2.4 乱答/敷衍/代写检测

在 CX 现有 too_fast、straightline 之上补四层：

1. **服务端不可伪造时长**：`GET /my/assessments/{aid}` 下发时刻与提交时刻之差替代前端 Date.now() 自报。
2. **认知卸载检测**（07 设想的首个实现，超越点）：navigator 提问文本→短时间内出现在 driver/外部输入的相似度匹配，命中计一次卸载事件。
3. **risk_flag 组合指标**：高分 + 异常低时长 + 异常低运行次数 + 粘贴大段代码事件 → 风险分推送教师端抽查追问（人机分工，不做纯算法判定；组合优于 02 的「>95分」单阈值）。
4. **群体级异常**：对照/全体同涨检测——各条件组增益差 < 组内普涨的 1/3 时报告自动标「疑似重测效应主导」（03 教训）；后测到顶率超阈值标「效应可能被截断」（现有到顶保险丝挂进 report）。

全部剔除留审计痕迹（谁被剔、按什么规则），无同意剔除与乱答剔除分开交代（CX study.py:592-596 口径纪律）。

### 2.5 与 learning_round / goal_anchor 的嵌合（题眼）

CX 现状是「测评与教学完全绝缘」（submit 刻意不写 ct_event）。改为**双写分流**：

- **测评分独立表不进过程指标**——保 CX 防污染的洁净设计不动。
- **另开只读通道**：pretest→running 转换钩子读 ct_v1 得分，按前测三分位写入 goal_anchor 初始难度/脚手架档位（09 的「测→分流」链路，成本极低）；轮末 probe 的 dim_scores 经只读通道产出 scaffold_level **调档建议**，教师端确认后生效，不自动改（14 的「进度评估→路径调整」内环 + 13 的人作为评价主体）。
- **轮结构钩子**：probe 作为 exit_task 的一种接 `exit_round(rid, passed)` 的 exit_task_passed 布尔位（store_learner.py:197-204 现成钩子）。
- **轮前 warmup**：上轮错题池生成复习小测，低于阈值先复习再 hop 新目标（李昊东 60 分门槛机制），把「测完数据去哪了」写死成状态机转移规则。
- **可比性边界**（14 铁律）：AI 自适应生成题只允许出现在练习与轮间自测，标记「练习性自测」不入正式计分；前中后测锚定固定 ct_v1 蓝图。两端数据分表、报告分栏。

### 2.6 数据流入四要素报告与效标表

- **补断点 (a)**：report() 接入 ct_criterion——probe/delayed/效标数据进报告，效标效度 r 可算；中测落库的同时写好 report 消费逻辑（防「录了没人看」）。
- **report/v1 扩展槽位**：流失表（attrition 原因码）、配对完整样本/全样本双口径、各效标 n 对齐校验、效应量 d+CI、天花板检测、同涨检测、逐题难度 p+点二列（能力卷）/α（态度量表）分开写死、「本报告覆盖该生 X% 活动事件」自评字段（04 SLO 思想）、AI 批改质量抽检小节（P/R+Kappa）。
- **双视角**（13）：横比（同班/同期班分布位置）+ 纵溯（pre→probe→post 个体轨迹），报告尾部挂「归因假设+下一轮干预建议」喂教师端 Today 视图。
- **凡进卷必有槽位**：题目入卷即绑定报告模板槽位，无槽位禁止入卷（03「采了不报」防呆）。
- 所有心理测量指标后端单源自动计算直接渲染，无人手誊抄环节。

## 三、界面设计（前端）

延续 warm cartoon 设计系统：#F5A623 橙 / #7C6BF0 紫 / #6C9CE9 蓝 / #FFF8F0 米白，Inter，🐢 小海龟吉祥物；卡片圆角、大按钮、Element Plus 基座。

### 3.1 学生测评中心（`/student/assess`）

**入口层**
- IDE 常驻推送胶囊（红点）保留，但补轮询或复用配对 WS 通道——现 TaskChip 仅 onMounted 拉一次，课堂同步下发看不见。
- 新增「待做测评」聚合页，接通零调用的 `mine()` 端点：卡片列出 待做（截止时间/预计时长/类型徽标「课堂小测/正式测评」）、进行中、已完成三栏。
- 测评类推送禁止一键标完成（现有约束保留），完成态只由交卷端点写回。

**作答层（AssessmentView 强化）**
- 保留：单题单屏、顶部进度点阵、可回退、双 confirm、409 幂等、错误横幅不拆卷面。
- 新增：①首次测评前 2 分钟演练页（模拟题不计分，04）；②localStorage 草稿（按 aid 键控，交卷后清除——初中生误触刷新是常态）；③软倒计时（题块级、只提示不强收、非红色高压样式，「严谨靠留痕不靠禁止」）;④选项顺序洗牌（李昊东）；⑤空答案交卷前置校验+温和引导（08 空提交防呆）;⑥开卷页固定文案「结果不计入成绩，请据实作答」（03）。
- probe 态特殊 UI：小海龟头像变「安静观察」状态（只读不答的可视化），不弹任何分数。

**结果反馈层（分数纪律——给什么/不给什么）**
- **不给**：总分、维度分、排名、逐题对错、与他人比较。pre/post 交卷页只显示中性完成态：「已完成，谢谢你的认真作答 🐢」。
- **给**：①完成徽章与参与记录（挂激励的是「完成行为」不是分数）；②练习/warmup 态的三段式解析与「诊断+直达练习」捆绑——每个薄弱构念挂 1-2 道可立即点开的练习题（06 学生真实拉动力）；③学期尺度的 neutral 口径成长描述（「你在『分解』上的练习明显变多了」——描述行为不评判能力），不呈现四要素原始分。

### 3.2 教师测评控制台（`/admin/assess`）

**主操作区**：单主按钮状态机（服务端算 next_action 前端只渲染）：建研究→发前测→开始上课→（轮内：开 probe / 开 warmup）→结束→发后测→收官→约延迟测。force 操作留痕并进 caveats。

**发卷面板**：名单冻结确认、排期时间窗（统一发卷时间 = 线上版「监考环境一致」，08）、卷型徽标（pre/probe/post/delayed）、同意门检查——未开通同意者高亮 + 批量开通动作（现有）。

**实时进度监控**：交卷率环形图 + 已交/未交名单实时刷新、未交即时可点名、异常旗标流（too_fast/straightline/风险分即时上浮）、pretest 闸门状态条（<60% 显示阻断原因）。

**probe 面板**：每轮一行——发放/回收/挫败态计数、锚题正确率速览、调档建议卡片（AI 建议 + 教师一键确认/驳回，驳回留痕）。

**结果总览**：
- 横比纵溯双视图（班级分布位置 + 个体 pre→probe→post 折线）；
- caveats 区不可关闭（剔除数、流失表、天花板/同涨警告硬渲染）；
- 主客观分栏（客观测评 | 主观问卷永不混排，10 教训）；
- Today 诊断卡片：典型错误 + 建议话术（01 三段式的自动化）、risk_flag 待核验名单、低满意/低使用学生名单（08 负反馈闭环）；
- 教学薄弱点告警分级可调（1/3 提示、1/2 告警，绕开 02 单阈值失效坑）；
- 报告配对话式解读层——小海龟兼任「报告讲解员」，教师问「这个图什么意思」能答（15）；
- 导出：CSV/JSON 去标识化 + 诊断日志模板（13 三档支架的最低档先落地）。

### 本轮可落地（按依赖排序）

1. **Schema 与门禁基座**：assessments.kind 扩四值、responses 加 round_id 可空外键、题对扩三元组、服务端时长记录；CX 五层门禁移植到新测评路由（404 防枚举、剥 answer/dim/why、dim_max 不下发、锁卷、INSERT OR IGNORE）——**不复用现有 practice/assignments 旧通道**；同意门禁接入。
2. **状态机扩展**：probe/warmup 子事件、delayed 窗口、时点混染防呆、闸门分级。

7. **回流钩子**：pretest→goal_anchor 初始档、probe→scaffold_level 建议（教师确认制）、warmup 错题池。

## 五、红线自查

| 红线 | 本蓝图如何守住 |
|---|---|
| **六维不挂激励** | 学生端一切徽章/积分只挂「完成行为」（交卷、参与 probe、完成练习），任何 UI 不将 thinking 四维/六维分数与奖励、排名、称号关联；probe 结果走 ct_criterion 独立表，不写 ct_event、不进六维公式输入。 |
| **分数不下发学生** | pre/post/probe/delayed 交卷页与测评中心均不显示总分、维度分、逐题对错、排名；学生可见的只有中性完成态、练习态解析、行为描述式成长语（描述练习量与轨迹，不评判能力高低）。CX 现交卷页「答对 X/Y」在本次改造中移除。 |
| **neutral 口径** | 所有学生侧文案由固定模板出（「你最近在调试上花的时间变多了」型），禁止「你很弱/落后于」表述；教师侧诊断话术卡片同样走审核过的模板库；开卷页固定「不计成绩、据实作答」声明。 |
| **同意门** | 取卷/交卷双重 CONSENT_REQUIRED 检查覆盖新增的 probe/warmup/delayed 全通道（新路由不豁免）；学生端 403 翻译为「把签好的同意书交给老师」；报告默认分析集剔除无同意者且剔除数硬写 caveats，与乱答剔除分开交代。 |
| **FORMULA_VERSION** | 测评数据经**只读通道**参与支架档位建议，不改 learner_state 六维公式任何权重；如未来公式需吸收测评信号，必须 bump FORMULA_VERSION 并在报告标注版本切换点，禁止同一研究期内换版；report/v1 渲染时携带 formula_version 与 ct_v1 蓝图版本号，跨版本数据禁止混合比较（16 换卷不可比教训的公式版对应物）。 |

**一句话总纲**：文献证明「发得出、收得回」靠平台强制流程（铁律2），「算得准」靠确定性证据先行+LLM 分层抽检（铁律6/7），「测得真」靠测评态 AI 熔断+服务端留痕（铁律8/9/10，均为我方原创空间），「测了有用」靠设计期绑定消费方——前测分流 goal_anchor、probe 调档建议、warmup 错题池、报告横比纵溯（铁律11/13）。全组文献没有一篇做出「测评→学情→下一轮教学配置」的程序化回灌，这是本方案相对文献的核心增量。

## 附：已拍板（2026-08-11 深度推演后决定：**共机为主形态·强化版**）

**互动占比分子的场景前提**：chat_log 采集的是**打字聊天**——这隐含「双机结对」假设。但真实课堂的结对编程多为**共机**（两人一台电脑），生生交流走口头、平台永远采不到。三个选项待定：
1. **双机线上结对**（各自登录、聊天走平台）——分子成立，但改变了经典结对编程的形态（需在教学设计里明确）；
2. **共机+口头交流**——chat_log 分子结构性为空，互动占比降级为不可用，「支架来源迁移」的验证改走课堂录音编码（人工，进质性线）；
3. **混合**：共机为主，driver/observer 各有平板/手机扫码登录轻端只做举手与质疑标记（「observer 发起质疑」有了数据源，且不破坏共机形态）——工程量中等，是三选中唯一能同时保住指标与形态的。
**此决定影响开课形态与互动指标的效度声明，须在开课前拍板。** interaction 端点已加 chat_channel_available 诚实标志，未接通期不会误报 0。

**拍板结论（选项2强化版）**：以共机为主形态。理由：①构念效度优先——文献底座（Denner/Zhong/McDowell）几乎全为共机，改双机则干预不再是所引文献中的「结对编程」，可比性断裂；②治理现实——双机/轻端触碰课堂手机雷区，且第二设备破坏「观察 driver 屏幕」的结对本质；③数据侧有诚实替代。
**替代验证三角**（取代互动占比作为「支架来源迁移」主验证）：PPME-Q 自陈量表（Xu & Correia 2024，八年级验证 α=0.888，待翻译审校，按铁律4归为活动体验类管理）× role_switch forced/negotiated 轮换行为（已落库）× 教师结构化观察抽样（每轮5分钟扫描计数）。
**如实降级**：互动占比降为「双机/远程场景补充指标」（chat_channel_available 降级机制已就位）；「observer 发起质疑次数」正式移出平台自动指标（隐私设计+共机场景双重封死），入诚实边界；共机下平台对「真人谁在开」半盲——换位打点近似真人轮换（学生-AI 角色切换通常伴随键盘易手），此近似口径写入论文测量局限。
**配套已批准落地**：轮换=底线强制（每轮≥1次，结轮弹层提醒不阻断）+协商自由（换位6秒轻问 forced/negotiated）；pair_matcher 加感知技能差上限（配对前2题微问卷：自评水平+对搭档感知，Katira 2004）；idea32 倒转——能力弱学生给受保护的**驾驶**时间（Lewis & Shah 2015：navigator 是结构性弱势位）。
