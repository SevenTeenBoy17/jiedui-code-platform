**对 R1 第 18 行与 §二-②-3 的强制改写**：不得写「支架强度与 uptake 相关弱且跨数据集不一致」。准确表述为：

> 近零相关仅出现在 benchmark 类数据集，作者归因于 uptake 方差受限；在真实部署的两个类别中，机器支架强度与学生 uptake 的秩相关为 ρ=0.346（有支架）与 ρ=0.308（无支架），p<.001，属中等偏弱。这意味着 hop 类供给侧指标对需求侧的解释力上限约 10% 方差——**必须配需求侧量，但 hop 并非无意义**。

**人工验证方案（整套照抄，含验收门槛）**：两级分层抽样（先按轮级均分四舍五入分箱 1–5，再在每箱内按与箱质心的相似度切 typical/mid/outlier），样本量对标 282；信度报 **Gwet's AC1 而非 Cohen's κ**（U1/U2 为高度不均衡二值，EHS 命中率大概率 <20%，κ 会被基率压到虚低——此点须在方法章先声明）。**预注册降级规则：若 U3 与 U6 金标准的 AC1 < 0.40，则放弃 U7 的连续化，只报 U1/U2 两个布尔量。**

**必须主动承认的上限**：CX 的 uptake 是行为代理＋40 字文本代理，**不是原文的 LLM 语义判定**；预期与人工金标准一致性低于原文的 78.9% / AC1 0.580。同时可主张一条正向差异：CX 的 `reply_class` 四分类（CQ/EQ/RQ/D）与该文 5 信号高度同构（D↔信号a，RQ/CQ/EQ↔信号c，has_code_block↔信号a/d 的硬锚），且是**规则化、零成本、第三方可原样重跑**的版本（对方用 GPT-5-mini，不可复现且有成本）。

### 2.2 诊断脚本规格（开课后第一周整套跑通，不依赖任何新采集）

落成 `server/_diag_dims.py`，与 `_smoke_*.py` 同级，纳入 CI 的「有真实数据才跑」分支。

**脚本 A：六维分布诊断（`round_snapshot`，`evidence_count >= 3` 门槛沿用，勿放宽）**
逐轮逐维报：n、mean、sd、min、max、`p_top`(≥90 分占比)、`p_bot`(≤10 分占比)、偏度、峰度，以及 R1→R2→R3 的**偏度轨迹**（照 cCTt 的呈现方式，评审熟悉）。

判据（**必须双向，且必须在论文中标注为「本研究预先设定」，非文献阈值**）：
- 顶效应：`p_top ≥ 0.15` 或 偏度 < −2 或 峰度 < −7（区间 [−2,+2]/[−7,+7] 引 Gravetter et al. 2020，经 cCTt 引用）
- 地板/塌陷：`p_bot ≥ 0.15` 或 `sd < 8`
- 区分度：R2→R3 同维 Spearman ρ < 0.3 即判排序被噪声吞掉
- 统一判据：**任一维在任一轮触发以上任一条，即判该维在该轮失去区分度**

**v3 公式的数学天花板/地板（终审复核结论：主要风险是地板与压缩，不是触顶）**：
- `algorithm` 顶部压缩最严重（高投入 attempts=120/sr=0.9 时 ≈86，sat 边际收益极小）→ R3 高分段区分度显著下降
- `model` 塌陷风险最高：`designs=0` 时数学上限 = **30**
- `abstract`：`designs=0` 时上限 = 70
- `verify` 伪双峰：`errors=0 且 fixes>0` 的孤儿修复支路固定输出 ≈30 分
- `decompose`：designs=0 且 switches=0 时上限被压到 50

**零成本止损（开课前一周做）**：先测一次 `designs` 的真实产生率。若一个班 `designs` 中位数 = 0，**`model` 维在该班先天报废**，此时在预注册中就把 model 从主分析剔除，或走 `REPORT_FOLD` 现成的通道与 `abstract` 合并为「抽象建模」。这是"先看数据再改公式"与"不动 FORMULA_VERSION"两条纪律的合法交集：**改的是分析计划，不是公式**。

**脚本 B：外部效标相关**
`Spearman(round_snapshot.dims.algorithm @ R3, ct_criterion.total @ post)`。预期区间预注册为 **0.2–0.4**（不是 0.41——ACE 的 r=0.41 是两个 CT 测验之间的相关，过程指标与终结性测验的相关通常更低）。ρ<0.2 则「六维只测了平台熟练度」的质疑坐实。

**脚本 C：口径与缺失诊断（v3 特有的三个陷阱＋一个裁决）**
1. **sv 混合放大**：逐生报 `legacy_events`（summary 已返回）与 `ct_snapshots.sv_mixed`。任何 `legacy_events>0` 的学生**必须在主分析中单列并做剔除敏感性**——`ct.py` 注释已自陈不分版本还原会让"干预后算法维上升"被人为放大。
2. **孤儿修复**：报 `orphan_fix_flag` 占比＋verify 分布 30 分附近堆积检验（Hartigan dip test，但 n≈60 下功效不明，须说明）。占比 >10% 则 verify 的组间比较无效。
3. **`has_real_data` 门槛的 MNAR（评审几乎必问，CX 目前完全没有对应分析）**：把被 `(runs+errors+fixes+designs) >= 3` 剔除的学生按性别/先备分组统计剔除率，组间差 >10pp 即存在幸存者偏倚。**这张表是 CONSORT 流失表的天然延伸，一次工作两处交付。**
4. **REPORT_FOLD 裁决**：算 `Spearman(abstract, model)`。ρ>0.8 → 折叠有据（写进论文）；ρ<0.5 → 折叠掩盖真实差异（应拆回）。**把一个工程妥协变成一次可证伪的构念检验**——零成本、高说服力。（阈值 0.8/0.5 为本研究预设，须预注册声明。）

### 2.3 偏倚诊断：前置阻塞项与统计方案

**前置阻塞（这是本线真正的 P0，必须在开课前落地）**：实库 38 表全量 dump 确认 CX **没有任何人口学/协变量字段**（无 users 表，`auth.py` 为 DEMO_USERS 硬编码；`study_members`/`class_students` 均无；全仓 grep `gender|性别|typing_speed|编程基础|prior_prog` 零命中）。开课后补采既不合伦理也不可信。

按仓库纪律（`store.py:78`「一律 CREATE TABLE IF NOT EXISTS，不 ALTER 已存在的表」）**新建表**：

```sql
CREATE TABLE IF NOT EXISTS student_profile(
  student_id   TEXT PRIMARY KEY,
  gender       TEXT,     -- 'F'|'M'|'other'|'refuse'（必须有 refuse：未保条例第32条）
  prior_prog   INTEGER,  -- 0无/1图形化/2代码<1年/3代码≥1年（自报）
  typing_wpm   REAL,     -- 服务端实测 60 秒录入基线，不可自报
  device_kind  TEXT,     -- 机房机型（键盘差异是 typing_wpm 的混淆源）
  collected_at INTEGER,
  consent_scope TEXT     -- 'teaching'|'research'，对齐 R1 合规缺口 #8 的两级同意
);
```

三个关键设计点：
- `typing_wpm` **必须服务端实测**——它是 runs/fixes/attempts 的吞吐上限，测不准就无法把"六维在测思维"与"六维在测手速"分开。
- **打字基线任务一次采集两用**：它本身就是「无 AI 独立完成」的最小前测锚，是 R1 P0-1（撤 AI 后独立表现）所必需的基线。
- `gender` 属敏感度较高字段，必须进《未成年人个人信息处理规则》字段清单并提供 refuse 选项；research 用途走独立勾选。

**统计方案（必须区分两类对象，且必须"主动认怂"）**：
- **ct-v1 测评题（`assessment_responses.item_scores`）**：这才是 DIF 的合法对象。但 cCTt 用了 **N=2709** 才跑通 IRT+MI+DIF；CX 若 2 个班≈60 人，**DIF/CFA/测量不变性一律功效不足**。
  - 主分析只报 CTT 层：题目难度指数（>.85 判太容易，<.25 判太难）、点二列相关（>.15 可接受，>.25 为好题）。**这两条今天就能用在 `ct_v1_items.py` 的题库筛选上。**
  - 局限性一节明写：「本研究 N=xx，不足以支持 IRT/DIF/测量不变性分析（对照 cCTt N=2709）；题目层偏倚检验留待多校推广后。」**这句话把一个漏洞变成一个成熟度信号——在 60 人样本上跑功效不足的 DIF 然后写"未发现偏倚"，在评审眼里比不做更糟。**
- **六维过程分（0–100 连续合成分）**：DIF 与测量不变性**不适用**。正确做法：分组分布比较（Mann-Whitney U / Kruskal-Wallis + Dunn 事后 + Benjamini-Hochberg 校正）＋**Cliff's delta**（分布偏斜，Cohen's d 不稳）＋**差异性预测效度**（各组内分别算 Spearman(六维, 效标)，用 Fisher r-to-z 检验 ρ 之差；ρ 差异显著即系统性偏倚的直接证据）。
- **打字速度专门处理**：偏相关。若 Spearman(dim, criterion) 在控制 `typing_wpm` 后下降 >0.10，该维实质在测手速。
- **CX 独有的第三个混淆源（文献里没有，但评审一定会问）**：**座位/角色时间**。driver 累积 run/fix/edit 事件，observer 结构上不累积。必须 join `seat_map` 算每人每轮 driver 时长占比并作为协变量进主模型。**不控它，「共机结对提升 CT」的结论会被一枪打掉（"你测的是谁坐在键盘前"）。**
- ⚠️ ETS 的 MH D-DIF A/B/C 分级阈值本轮未从一手来源核实，**不要引用**。

### 3.1 对 tool-fading 之争的回应（Hsu 2026, Synergistic Fading Model）

**先纠正 R1 的两处著录错误**：年份是 **2026 不是 2025**；它是 **EdArXiv/OSF 预印本（DOI 10.35542/osf.io/5eutb_v1）**，单作者 Sheng-Cheng Hsu（台湾南开科技大学休闲事业管理系），CC-BY，作者自述「no data associated with this preprint」「preregistration not applicable because no data collection, extraction, or analysis is reported」。**删掉 R1「CX 的 hop 正是被点名的那种逻辑，理论上已被判为过时」这句**——若当作既定理论写进引言，评审一查 EdArXiv 就会反噬。

**推荐路线：(a) 的"改名不改物"版 ＋ (b) 作第二层防御，不二选一。** 代码自查证明 CX 事实上已经是 guidance-fading：`ai.py:56-61` 的 SCAFFOLD 0-3 只调节提示细节量；`ai.py:33-38` 的 BASE_RULE 在**所有档位**都禁止完整可运行答案代码；0 档时 AI 仍在场、仍在提问。CX 的双角色甚至与 SFM 的 dual-agent architecture 同构（`ROLE_PROMPT['turtle']`/driver ≈ 永久性 Analytical AI Tool；`ROLE_PROMPT['reviewer']`/小枭·领航员 ≈ 淡出的 Teaching Agent）。

**讨论章定稿段（可直接用）**：

> 一个新近提出、但尚未经同行评议与实证检验的概念框架（Hsu, 2026, EdArXiv 预印本）主张：当 AI「permanently, ubiquitously, and freely available」时，将「任务执行的独立」作为支架终点已经失效，因为「To train students to work without AI is to train them for a professional context that does not exist.」该批评的靶心是**把 AI 的在场本身当作要撤走的东西**。
>
> 本研究的渐退作用于**教学型指导的强度**（scaffold_level 0–3 仅调节提示细节量），**分析型能力（驾驶员角色的代码生成、沙箱执行、报错回显）全程保留且不随档位下降**；AI 的在场与可用性在全部档位下不变。因此该批评所针对的机制在本系统中不存在。
>
> 更重要的是，Hsu 本人给出了明确的自我限定：「The SFM does not argue against cognitive independence as an educational value. What it challenges is task-execution independence as a scaffolding endpoint... Developing learners who reason productively with AI is not equivalent to developing learners who cannot reason without it.」本研究的撤 AI 后测（无 AI 独立完成＋一周延迟保持测）所测量的正是前者——学生能否自行分解、调试与验证——而非主张学生在真实实践中应当拒用 AI。此外，SFM 的适用前提是「any domain where AI-assisted analysis has become standard professional practice」，其全部论证语境为职业与高等教育（劳动力市场数据、网站流量分析案例、medical diagnostic support / legal research / financial analysis 等可迁移领域），**全文无一处涉及 K-12 或义务教育**；该前提在义务教育阶段的学业评价情境中不成立。
>
> 反过来，该框架自陈其三项核心能力（prompting ability / evaluative judgment / iterative refinement）「requires instrument development that has not yet been undertaken」，其淡出判据「requires operationalization as observable learner behaviors before it can guide practical implementation at scale」。本研究恰好提供了这两样：服务端全量落库的 `scaffold_log` 改档流水（含 level_from/level_to/source 三分类：teacher 手动 / teacher_accept 采纳建议 / dismissed 明确驳回，带 suggestion_id、round_index、room_id），以及 `policy_suggestion` 的采纳率与驳回率所构成的教师就绪度实证材料。因此本研究可作为该框架适用边界的一次经验检验。

**配套的工程决策（见第五节，不在本轮做）**：若要主张"干净的" guidance-fading，`ai.py:115` 的 `parts = [BASE_RULE, role_seg, SCAFFOLD.get(...)]` 应改为让 SCAFFOLD 段**只对 navigator/reviewer 生效**（一行 if）。但这改动提示词拼装，按仓库纪律必须升 `PROMPT_VERSION`（`ai.py:31`，当前 `ai-prompt/v1`），否则跨版本四分类占比会被当成同一条曲线读、manipulation check 失效。**若已开始收数据，本轮只改论文措辞，代码留到下一版。**

### 3.2 对「CT 与编程解耦」的回应（Schmidt & Runfola 2026）

**先纠正 R1 著录**：不是 *Software* 2025，是 ***Software* 2026, 5(2), 20, doi 10.3390/software5020020**（MDPI 开放获取，2026-05-13 发表）。文体自述「advances a theoretical argument」「through a theoretical and interpretive lens」——**立场/观点文章，无实证数据**。

**讨论章定稿段（可直接用；核心策略是用对方原文支持自己）**：

> 有论者主张，生成式 AI 使计算问题解决与直接编程发生解耦，从而动摇了以编程作为计算思维载体的前提（Schmidt & Runfola, 2026）。然而该文本身在回答「Should everyone still learn to code?」时给出的答案是肯定的：「For now, we argue the answer remains 'yes'... coding remains one of the most effective available ways to teach core habits of computational reasoning, including precision, decomposition, debugging, and verification. At present, these habits are not yet consistently cultivated through AI interaction alone.」其点名的四种习惯（精确性、分解、调试、验证）与本研究的过程性六维高度重叠。该文同时给出限定：编程的教学角色可能随时间收窄，本研究亦不假定编程是唯一或永久的路径。
>
> 更关键的是学段边界。该文的三个引导问题分别关于开发者角色、AI 增强未来所需能力、以及 CS 与数据科学教育的演进；其教学建议全部针对大学 CS/DS 课程（入门课程、AI 增强 IDE、本校 AI 伦理辅修、337 位高教管理者调查），**全文未涉及义务教育阶段**。因此其解耦主张不能直接外推至初中的计算思维形成期。
>
> 在该学段上，元分析证据的方向恰好相反：上机编程相对于不插电活动在发展计算思维上的优势在**中学与大学阶段显著（总体 g=0.606 vs 0.501），而在小学阶段两者效应相当**（Wang, Fan & Yu, 2025, *ETR&D* 73:3247–3267，37 项研究）——这为初中阶段以编程作为计算思维外化的主要载体提供了**学段特异性**的实证支持。
>
> 发展心理学层面提供了一致的解释：多数初中生尚未稳定进入形式运算阶段，抽象概念的教学需从具体表征起步并逐步褪去（concreteness fading；Fyfe et al., 2014, *Educational Psychology Review* 26），且具体表征对先备知识较低的学习者更有利于迁移。在计算思维教学中，可运行、会报错、能即时反馈的程序正是这个具体外化物。
>
> 就本土课程依据而言，《义务教育信息科技课程标准（2022年版）》将计算思维界定为「在问题解决过程中涉及分解、建模、算法设计等思维活动」，并明确区分程序设计是「在思维活动之后，将算法『翻译』成计算机能够执行的程序」，同时要求课程「不应局限于对程序设计语言语法规则的掌握」。本研究的定位正是该要求的一个实现：编程是计算思维的外化载体而非教学目的本身，AI 承担语法与样板代码，学生承担分解与算法设计。

**引用前必须补取的三处一手材料（否则只能写方向不能写数字）**：
1. Wang, Fan & Yu 2025 的 **secondary school 亚组 g 值与置信区间**（Springer 全文墙，目前只有摘要层）。
2. **Shayer & Adey (1981) 原著**（*Towards a Science of Science Teaching*, Heinemann）—— 目前抓到的"约 30% 的 16 岁学生达形式运算"全部来自科普站转述，**直接引会被查出来**；或改引一篇同行评议的复述。上文定稿段已把这条降级为不带数字的表述，可先行使用。
3. **教育部课标原文 PDF** —— 目前引文来自《西南大学学报》两篇解读文章的转述，逐字表述可能有出入。

### 4.2 「六维分值不下发学生端」的取舍两侧（R1 §五-15 需整条改写：**高估了代价**）

**必须写的正当性（从推理升级为有 20 年文献支撑的实证）**：

> 学习者会为达成系统可见的成功标志而利用系统属性本身（gaming the system；Baker, Corbett, Roll & Koedinger, 2008, *UMUAI* 18(3)：「attempting to succeed in an educational environment by exploiting properties of the system rather than by learning the material」），此类行为出现于相当比例的学生并与更差的学习结果相关（Baker et al., 2004）。在参与度被自动评分的在线讨论环境中，学生会以发布无关内容的方式满足计数（Cheng & Vassileva, 2005，转引自 Baker et al., 2008）。本研究的六维指标是学生编程行为频次的单调函数（见 `ct.py` 实现注释），若以分值形式下发学生端，将直接把过程指标转化为可追逐的目标；据此本研究规定六维分值不下发学生端。

**代价一侧的上界压缩（本轮最有价值的发现）**：

> 向学生返还其过程数据的自我调节收益在实证上并未确立：面向 SRL 的学习分析看板通常并未真正支持 SRL 策略与元认知（Matcha, Uzir, Gašević & Pardo, 2020, *IEEE TLT* 13(2)）；学业顾问使用看板向学生间接呈现表现信息，与学生动机与 SRL 策略的**下降速率**相关（Aguilar, Karabenick, Teasley & Baek, 2021, *Computers & Education* 162:104085）；暴露于看板会诱发社交焦虑并整体产生负面影响（Lim et al., 2019）；可视化对讨论参与数量与质量的效应随成就目标取向可正可负（Beheshitha et al., 2016, LAK '16）。因此本研究不下发过程指标分值，其代价的上界是有限的。
>
> 同时，本研究返还给学生的并非"什么都不给"，而是**行为描述式的详尽反馈**：在计算机环境下逐题反馈的元分析中，详尽反馈 d=0.49，显著优于仅告知对错 d=0.05（Van der Kleij, Feskens & Eggen, 2015, *RER* 85(4)）；反馈总体 d=0.48 且信息含量是首要调节量（Wisniewski, Zierer & Hattie, 2020, *Frontiers in Psychology* 10:3087, 435 项研究/N>61,000）。这一形态亦与任务卷入型评价的经典证据一致：Butler（1988, *BJEP* 58(1), N=132, 5–6 年级）发现只给评语组在兴趣与表现上均优于给分数组，且**「分数+评语」并不优于「只给分数」**。**因此本研究不将"不下发分数"视为对学生自我调节收益的牺牲。**

**必须保留的三条让步（缺一即成单边论证）**：
1. 上述看板证据基本来自高等教育，**K12 学段的学生端看板效应证据更少**；Van der Kleij 亦明确报告中小学的反馈效应显著低于高教，**故本研究不外推 0.49 这个数值**。
2. 本研究未直接测量 SRL，**故只能宣称"代价未被实证确立"，不能宣称收益**。
3. **零分值 ≠ 零反应性（R1 没意识到的一半）**：Hakulinen, Auvinen & Korhonen（2015, *iJET* 10(1), N=281 随机分组）在**徽章完全不影响成绩**的设计下，仍在每题用时、会话数、总时长上测到统计显著差异。因此 CX 现行的「行为描述成长语＋较强/中等/待加强三档」本身也是一种可视化反馈，**同样可能诱发追逐**（例如学生发现多跑几次代码就能从"待加强"升到"中等"）。**主张必须从"指标未被污染"降级为"移除了最强的追逐诱因（可比数字），但不能排除描述性反馈本身的反应性"，并把这条列为明确的效度威胁。**

**由此产生的两项零成本改良（建议采纳）**：
- **反应性探针**（离线分析，零新埋点）：比较学生**首次看到成长语/三档之后**与之前的行为频次分布（CX 已有 `ct_events` 时间戳与 `/summary` 调用记录），若出现结构性跃升即为反应性证据。**这是文献里没人做过的量，可把一条局限性变成一个发现。**
- **三档措辞调整**：`ct.py:236` 的 `RANK_CN = {0:"较强", 1:"中等", 2:"待加强"}` 仍是排序型的自我卷入信息。往「证据量」而非「能力高低」方向调（如"证据较多 / 证据一般 / 还缺证据"），既保住 Butler 的任务卷入属性，又与 CX 自己对"零行为学生""全并列"的处理逻辑更自洽。

**须留退路的一句**：本轮多路径检索**未检出**任何以"过程性计算思维指标向学生可视化后是否被策略性操纵"为研究问题的同行评议实证。论文必须写「据本研究检索（截至 2026-08-13）尚未见……本研究的相关设计决策依据的是相邻领域的实证与本平台指标的构造性质」，**不要写"无人研究过"**（未做 ACM/IEEE 站内穷尽检索，这是"未检出"而非"不存在"）。

### 4.3 「AI 挤压同伴互动」的预注册假设

**先纠正引用锚点**：R1 §五-14 把这句挂在 CAI 2026 上是错的（该文摘要与关键词通篇不含 collaboration/pair programming/peer/social，其 disrupt 对象是 error detection / self-monitoring / problem-solving）。正确出处是 **Bernstein, Rahman, Sharifi, Terbish & MacNeil, Koli Calling '25**（DOI 10.1145/3769994.3770036 / arXiv 2510.04443）。CAI 2026 应改挂到它真正支持的论点上（幻觉→外在认知负荷→干扰错误检测与自我监控，正好给 CX 的调试/验证维度做理论背书）。

**三层证据梯度（论文中按此层级呈现）**：
- **层1（最弱，质性）** Hou et al., ITiCSE 2025（N=17 访谈，北美 7 所 R1）：求助请求由 GenAI 中介；学生把同伴向自己提的问题转手推给 GenAI；社会支持系统瓦解带来孤立与动机下降。
- **层2（综述层，且自认证据薄）** Bernstein et al., Koli '25（224 篇纳入）：**Social Harms 仅 19 篇（8.5%），是六类危害中最少、且被综述自陈为 under-represented 的一类**；其证据集中于个体求助行为与小组集成，**全文无任何"pair programming"作为社会危害对象的实证**。
- **层3（最强，有效应量，但非结对同构）** Fan et al., IJ STEM Educ 2025（N=234）：CLS d=0.298、SPQ d=0.425（均人-人更高），同时 AI 结对编程表现 d=0.355（AI 更高）；MANOVA Wilks' λ=0.742, F(6,458)=12.376, p<.001, η²p=0.139；CLS 单变量 η²p=0.234、SPQ η²p=0.198。

**结论定稿：「有代价、但不是替代关系」——AI 换来表现与动机，付出协作深度与社会临场感；没有任何研究检验过"同步共机＋AI 对同伴可见"这一形态能否缓解该代价。**

**三条可证伪的预注册假设（全部可用现有埋点＋两份现成量表测，不需要新工程）**：
- **H1（复制）** CX 的 AI-共机结对臂在 CLS/SPQ 上低于无 AI 的人-人共机结对臂（复制 Fan 2025 的方向）。
- **H2（CX 的独特主张，方向相反）** 该差距**小于** Fan 2025 的 d=0.30（CLS）/ 0.43（SPQ）——因为 CX 的 AI 使用对同伴可见＋共机形态保留了社会问责。
- **H3（行为层，不靠自陈）** 同伴间提问/互相解释的观察计数与 `ai_helps` 的相关**不显著为负**；若显著为负，则 Hou 等的侵蚀机制在 K12 共机场景仍成立，须在讨论中承认并给出设计修正。

**量表与功效的诚实交代**：
- **直接沿用 CLS（So & Brush 2008）与 SPQ（Kreijns et al. 2011）的中文化版本以保证可比，不要自造协作量表**；二者均为自陈，CX 的 `obs_window` 客观席位/驾驶三数是补充而非替代。
- 功效：双侧 α=.05, 1−β=.80，d=0.43 → 每臂约 86 人；d=0.30 → 每臂约 176 人。**CX 若做不到几百人规模，必须在预注册里承认对 CLS 差距欠功效、只对 SPQ 差距有功效**，否则"未发现差异"会被读成"无差异"。H2 严格说需同量表同分析路径的跨样本比较；样本不足时退化为"本研究观察到的 d 的 95%CI 是否包含 0.43"这一**描述性对照**，并写明这是弱推断。
- 关于同伴可见性的**正面机制证据**（比 R1 引的 HHAI-Triadic N=20 实验室研究硬得多）：arXiv 2606.23237（103 对本科生、三波纵向）发现**项目早期双方对彼此 AI 使用的认知错位越大，期末项目分越低，低先备组代价最大，且面对面结对 session 并不能可靠消除这种错位**。这把 CX 的"共机＋AI 对双方可见"从"天然如此"升级为"有证据的设计决策"。（该文本轮只取到摘要层，引具体统计量需回溯全文；样本为本科、远程为主，外推 K12 共机需谨慎。）

### 4.4 效应量与样本量的现实预警

GCCCE #443 在 **n=104、10 周**的条件下三臂两两比较**全部不显著**（作者自陈"不排除偶然性因素"）。Yan et al. 2025 的显著效应也仅 **η²=0.04（小效应）**。这直接支持 R1 的 P0-5（样本量估算＋预注册＋先备水平作**预设**调节变量而非事后探索——Kazemitabaar CHI 2023 的显著效应恰恰只出现在先备水平调节项上），并说明**CX 把因变量定位在过程性指标＋撤 AI 后独立表现（而非态度量表）是更可能出结果的选择**，建议在论文中正面引用 GCCCE #443 作为"同类干预在态度层未能检出效应"的证据来反衬因变量选择的合理性。

### 5.1 三个必须先做决策、再动手的重构点

### 5.2 pm4py conformance checking 的技术路线定稿

**事件日志构建（已复核可行，零改造）**：`case_id = user_id × room_id × round_index` 三元拼键（不是学生、不是房间——R1/R2/R3 各有各的目标模型，跨轮拼 trace 会把三个模型混成一个）；`activity = ct_events.type`（白名单 6 个＋服务端 `hop`，共 7 个活动，对 discovery 是理想规模）；`timestamp = ct_events.ts` 转 datetime；`pm4py.format_dataframe(...)` 一行落地。**必须 `WHERE sv=2`**。

**两条路线都要跑**：
- **路线 A（拟合度）**：手写 R1/R2/R3 各自的规范 Petri 网，跑 `fitness_alignments` + `precision_alignments`（CX 数据量在几十到几百 trace，alignments 算得动，且比 token replay 更严格、诊断更可解释），并报 `percentage_of_fitting_traces`。语义草案：R1「能跑」≈ `design_create → (ai_help|hop)* → run → (error → fix → run)*`，终态要求至少一次不带 error 的 run；R2「跑对」要求 run 后无 error 且出现 probe/测试事件；R3「跑好」要求出现**非 error 触发的** fix 或 design_create。
- **路线 B（可分离性，最强证伪）**：分轮各自 `discover_petri_net_inductive`，然后**交叉重放**。**这才是审稿人真正会问的。**

**第三轮必须交付的**：(i) 与教学设计者共同敲定的三个规范模型定稿（当前只是语义草案）；(ii) `exit_task_passed` 是否作为 trace 终态标记纳入模型，以及 NULL（未做出口任务）算缺失还是算未通过；(iii) **预注册的三档解释规则**（禁止事后挑阈值）：三轮各自 log_fitness ≥ 0.80 且交叉重放 fitness 低 ≥0.15 → R1/R2/R3 得到支持；自身高但交叉也高 → 状态机不成立（**这是有价值的证伪结果，照实写**）；自身 <0.60 → 规范模型写错了，回去改模型而不是改数据。0.80/0.15/0.60 三个数**无文献依据，必须标注为"本研究预先设定"**。
