## 二、①CT / 思维评价：**逐层拆解，结论是"零测量"**

第一波只问了这一栏，但只写出一句结论。本次把"计算思维"这四个字在全文的**每一次出现**都定位、归类。

### 2.1 "计算思维"在全文的出现位置与功能（穷举）

| # | 位置 | 原文语境 | 功能定性 |
|---|---|---|---|
| 1 | `[P8 / p.2]` | "信息科技课程要培养的核心素养，主要包括信息意识、**计算思维**、数字化学习与创新、信息社会责任" | **课标条文转述**，无操作化 |
| 2 | `[P10 / p.4]` | 传统课堂"学生被动地模仿操作，难以发挥学生的主体地位，不利于学生**计算思维**、信息社会责任等核心素养的培养" | **修辞性归因**，用来论证"需要智能体"，无证据 |
| 3 | `[P65 / p.59]` | 案例一教学目标之二："**计算思维**：通过实例的深入分析，使学生能够把握算法的基本逻辑结构，并勇于尝试运用算法思维去解决实际问题" | **唯一一次写成教学目标**——但下文教学过程、效果分析均无对应 |

**穷举结果：全文 3 次，无第 4 次。** 无 CT 定义、无维度划分、无框架引用（**Wing / CSTA / Brennan & Resnick / Bebras 一个都没有**）、无操作定义、无测量工具、无评分规则。

> 它甚至没有一个 proxy——第一波说它"连代理指标都没有"，这一句是准确的。

### 2.2 那它测了什么？——完整证据链复盘（每一环）

第四章第三节"教学效果分析" `[P72–P75 / p.66–69]` 是全篇唯一的"效果"论证。逐环拆：

```
环 1：干预        → 两个教学案例（《算法应用在身边》《保温与散热》），北京某小学 5 年级
环 2：数据采集    → 教师访谈 8 人（4 个问题）+ 学生访谈 6 人（2 个问题）
环 3：数据处理    → 【空】无转录规范、无编码表、无类目定义、无双编码、无 Kappa
环 4：分析        → 直接摘录"教师 N 说……"，后接一段主题式归纳散文
环 5：结论        → p.68「这种分化恰好证明了智能体…教学的有效性」
环 6：升级        → p.75「显著提升了教学效果」
```

**每一环的具体问题：**

**环 2（工具层）**——访谈提纲全文可见，逐条抄录如下（这是"工具条目"的全部）：

- 教师侧 4 问 `[P72–P73 / p.66–67]`：
  1. 对于此教学智能体在信息科技教学上的使用，您有何感受？
  2. 您认为相比于传统教学，智能体辅助教学有哪些优势？
  3. 您认为该教学智能体有何需要改进之处，可否提出具体建议？
  4. 您期望未来教学智能体能帮助您做什么事？
- 学生侧 2 问 `[P74 / p.68]`：
  1. 你喜欢课上用到的智能体吗？你还想在以后的课上继续与该智能体交流吗？
  2. 你会在课后与这个智能体进行对话交流吗？如何交流？

> **这 6 个问题里，没有一个问到学生的思维过程、解题路径、作品、或任何认知内容。**
> 教师侧 4 问中 3 问是**产品反馈问卷**（感受/优势/改进/期望），学生侧 2 问是**纯偏好与使用意愿**。
> 这就是"证据链"的全部输入。**输入端没有认知信息，输出端不可能长出认知结论。**

**环 3（处理层）**——完全缺失。8 + 6 = 14 份语料，论文中呈现了 8 + 6 = 14 条引语，
**呈现率 100%，即没有做任何"从语料到编码"的抽象**。这不是编码不严，是根本没编码。
对比第二波读过的做法（如需要双编码 Kappa≥0.8 的流程），本篇**连"两位编码员"这个词都没有出现过**。

**环 4→5（推论层）——最假的一跳在这里**：

> 原文 `[P74 / p.68]`：
> "对于小学低年级学生，该教学智能体凭借情感化的互动和生动的视觉呈现成功吸引了他们的注意力……
> 而小学高年级学生则更加关注其实用性和与个人兴趣的契合度……
> 尽管两者在界面设计上的认知存在差异，**但这种分化恰好证明了智能体针对不同年龄段学生特点进行教学的有效性**。"

这句话有**三重问题叠加**：

1. **非序推理（non sequitur）**：「学生偏好随年龄分化」→「智能体针对不同年龄段教学有效」。
   前者是**学生特征的描述**，后者是**系统效能的断言**。前者不蕴含后者。
   实际上偏好分化恰恰在**没有智能体**的情况下也会发生——低年级喜欢视觉刺激、高年级看实用性，
   这是发展心理学常识，**与智能体是否有效完全无关**。这里把"学生本来就不一样"当成了"我的系统适配得好"。
2. **数据不存在**：本篇实践对象是**五年级一个年级** `[P64 / p.58]`，
   访谈的 6 名学生虽自述"来自不同年级" `[P72 / p.66]`，但**分析文本却谈论"低年级 vs 高年级"**——
   **论文中没有任何一条低年级学生的引语**（学生 1–6 的话中无年级标识）。
   即：**"低年级学生被情感化互动吸引"这句话，在本文的语料里找不到任何支撑句。**
3. **"证明"一词失范**：6 人便利样本 + 无编码的偏好访谈，用"证明"作动词。

**环 6（措辞升级）**：`[P81 / p.75]`
> "通过行动研究发现，该智能体在实际信息科技教学应用中**显著**提升了教学效果"

"**显著**"出现在一篇**没有做过任何统计检验**的论文里。作者随后在 p.76 又自认"难以进行量化评估"——
**同一篇论文相隔一页，先说"显著提升"、再说"无法测量"**。这是本篇最锋利的自相矛盾。

### 2.4 ⚠️ 一处被采集到、却被归错构念的 CT 证据（对用户最有价值的一条）

`[P72 / p.66]` 教师 1 的原话：
> "有学生问为什么网页打不开，智能体没直接给答案，而是引导他**排查网络图标—IP 地址—防火墙**，
> 这种探究过程比知识灌输更有价值。"

宋双程把这条放在 **"课堂活力与效率提升"** 标题下 `[P73 / p.67]`。

### 3.1 模式结构：三阶段 × 六环节 × 双行主体（**有限线性，不是无限闭环**）

**理论来源**：明写为廖剑等《数智分身：人工智能时代教师本位人机共教模式》[33]（现代远程教育研究 2024, 36(04):85-93）。
`[P62 / p.56]`："基于该学者提出的数智分身人机共教框架，本研究构建了智能体赋能教学的人机协同教学模式（如图 5-1）"

**图 5-1「人机协同教学模式」结构复原** `[P63 / p.57]`（图中文字 OCR 可辨部分 + 正文对应段落）：

```
┌── 课前教学准备 ──┐  ┌── 课中教师教学 ──┐  ┌── 课后智能发展 ──┐
│ 协同预习 ▸ 协同备课 │  │ 协同教学 ▸ 协同测评 │  │ 协同答疑 ▸ 协同发展 │
└──────────────────┘  └──────────────────┘  └──────────────────┘
 ── 师-机行 ────────────────────────────────────────────────────
  教师在 AI 协助下   教师在 AI 协助下   教师借助 AI 对学生   教师依据 AI 反馈
  设定预习任务        完成教学设计        表现进行测评          完成教学反思
 ── 生-机行 ────────────────────────────────────────────────────
  学生在 AI 协助下   学生与 AI 合作完成   AI 为学生提供
  完成预习任务        学习任务 / 知识建构   启发式答疑
```

**「师-机 / 生-机」双行**是本篇模式图的**核心形式创新**，也是它对用户最可复用的结构：
它把"同一环节里，人-机关系在教师侧和学生侧是两种不同关系"这件事**画进了图**。

**六环节的文字定义** `[P63–P64 / p.57–58]`：

| 阶段 | 环节 | 师-机权责 | 生-机权责 |
|---|---|---|---|
| 课前教学准备 | 协同预习 | 教师"在智能体的协助下精准设计契合学生认知水平的预习任务" | 学生自主探究初步建框架，依托即时答疑查漏补缺，**与智能体共建可视化思维导图** |
| | 协同备课 | 教师"根据智能体采集的学生**预习行为数据**动态把握学习轨迹与认知特征，通过**学情画像**实现教学活动的精准设计"；资源汇集筛选、自动生成材料、协同研讨 | — |
| 课中教师教学 | 协同教学 | 教师"更多地承担起**育人**的责任……以**指导者**的身份，对'生-机'交互过程进行引导" | 学习方式"以**任务驱动和合作探究**为主"，智能体作**小组合作学习的助手**参与学习活动 |

### 3.5 支架机制：**有支架，无渐退；且是"支架自取"不是"支架推送"**

**支架的三处硬实现（提示词级，可直接抄）：**

1. **顶层人设约束** `[P45 / p.39]`，全篇最简洁的"助学不代学"表述：
   > "仅提供指导，不直接给出完整答案。"
   同段另有：交流内容严格围绕小学信息科技，不回应无关话题；语言符合小学生理解水平；
   "所有回复内容需基于自身知识及工作流输出，**不随意编造无根据信息**" `[P46 / p.40]`。

2. **`AI_answer` 启发式答疑模型**（DeepSeek-R1）`[P46–P47 / p.40–41]`：
   > 角色："擅长通过启发式的问答引导学生自主探索并理解……而不是直接给出答案"
   > 技能："以 `{{input}}` 为**目标答案**，针对学生可能不理解的知识点，设计一系列**逐步深入**的问题"；
   > "问题要具有引导性，帮助学生自己思考并最终**推导出** `{{input}}` 这个答案"
   > 限制："必须采用启发式问答的方式引导，**不能直接输出** `{{input}}`"

3. **`AI_correct` 纠错模型** `[P47 / p.41]`：
   > "以给定的 `{{answer}}` 作为正确答案标准，精准识别……但**绝对不能直接输出** `{{answer}}`"

**渐退：全文 0 处。**
穷举检索"渐退 / 褪除 / 撤除 / 淡出 / fading / 逐步减少 / 支持强度"——**无一命中**。
支架强度是**常量**：不随学生水平变、不随轮次变、不随任务阶段变、不随正确率变。
同一个学生第 1 次问和第 100 次问，收到的引导密度完全一样。

**更关键的一个架构判定：本篇的支架是"自取"不是"推送"。**

四个快捷指令 `[P57 / p.51]`（答疑 / 纠错 / 思维导图生成 / 跨学科知识）**全部由学生点击触发**。
系统**没有任何主动介入逻辑**：不监测卡壳、不监测错误累积、不监测停顿时长，因而也不会主动推。
即：**支架的调度权 100% 在学生手上。**

> **这对用户的"支架推送"职能是一个必须回应的对照：**
> 用户模型写的是"支架**推送**"（系统主动），而本篇（以及大多数 Coze 类教学智能体）
> 实际做到的是"支架**自取**"（学生主动请求）。两者的差别是**决定性的**：
> - 自取：不需要学情感知，因此在无状态架构上就能实现 → **这正是本篇能落地而学情感知落不了地的原因**
> - 推送：必须先有学情感知 → 必须有持久层 → 必须有触发判据
>
> **所以"支架推送"和"学情感知"不是四职能里并列的两条，而是同一条依赖链的两端。**
> 若 CX 的 `ct.py` 六维分能作为触发判据，用户就拿到了本篇结构性做不到的东西。
> 建议在论文里把这一点写成明确的对照命题：
> **"渐退式支架的前提不是提示词工程，而是跨会话的学情持久化；
> 缺此前提的智能体只能实现学生自取式支架，其'渐退'无从谈起。"**

### 3.6 ⭐ 最值得抄的一个工程模式：**「答案锚 + 反向问题链」**

这是本篇对 CX 的 `ai.py` 双 persona **最有工程价值的一条**，也是第一波完全没看到的东西。

`AI_answer` 的完整调用链 `[P46–P47 / p.40–41]` + `[P52–P53 / p.46–47]`：

```
学生提问 question
      │
      ▼
┌─ 子工作流 teacher_answer ───────────────────────┐
│  ① 关键词识别                                    │
│  ② 并行检索：教学指南知识库 / 教案知识库           │
│              + info_collection（必应等 4 个搜索）  │
│  ③ 大模型"回答问题"：                             │
│     输入 = {{question}} + {{knowledge}} + {{data}} │
│     规则 = 优先用 knowledge；knowledge 为空才用 data│
│  → 输出：标准答案 A                               │
└─────────────────────────────────────────────────┘
      │  A 作为 {{input}}
      ▼
┌─ 大模型"启发式答疑"(DeepSeek-R1) ────────────────┐
│  以 A 为**目标答案**，反向设计逐步深入的问题链      │
│  硬约束：不能直接输出 A                            │
└─────────────────────────────────────────────────┘
      │
      ▼
   学生看到的：一串引导问题（附录 p.83–84 有两个完整实例）
```

**附录 `[P90 / p.84]` 的实例极具说服力**——学生问"身边有哪些信息科技设备"，智能体输出的是 7 连问：
从"每天和爸妈联系用啥工具"→"电子版作业用啥设备处理，旁边有没有连着其他机器输出成果"→
"数学课动态几何图形用哪个设备，和黑板比有啥不一样"→ 智能音箱 → 电饭煲空调扫地机 →
运动手环 → 枕边设备 → 最后："现在把想到的设备汇总，试着给它们**分分类**……说说为啥这么分组吧！"

> **注意最后一问：这是一次显式的"分类/抽象"任务。**
> 也就是说，**这条反向问题链的终点，被设计成了一个 CT 动作**，而不是一个知识点复述。
> 作者本人没有意识到这一点（他从没提 CT），但**这个形式恰恰是用户要的东西**。

**优点（CX 现在没有的）：**
- **有正向目标锚**。CX 的 `ai_navigator` 目前是**纯负向约束**（"拒绝写完整代码 + 反越狱规则"），
  没有"这一轮要把学生引到哪"的显式目标。负向约束只能保证"不代做"，**不能保证"引导有效"**——
  模型可能绕圈、可能引偏、可能问一堆无关问题，而系统无从判断。
- **有可判定的终止条件**：学生说出 A ⇒ 本轮达成。这给**渐退**提供了天然的计数单位
  （用"到达 A 需要几问"作为支架强度指标，问数下降 = 可渐退的信号）。
  → **这是把"渐退"从口号变成可测量量的一条现成路径。**
- 可控、不跑偏、可复现。

**缺陷（宋双程未讨论，用户搬用时必须补）：**
1. **答案先于探究存在**。所以它测不出学生的真实路径，只能测"学生多快走到预设答案"。
   对**开放性编程任务**（CX 的主场景，一题多解是常态）这会**压制多解**。
2. **答案质量零校验**。A 由 `teacher_answer`（知识库 + 必应搜索 + 大模型）生成，
   **没有任何人工核验或置信度闸**。若 A 错了，整条启发式链会把学生
   **更有说服力地**引向错误答案（因为学生是"自己推导出来"的，主观确信度更高）。
   → 本篇附录 `[P90 / p.84]` 的纠错例（`print("得分：" + score)` 需 `str(score)` 或 f-string）是**对的**，
     但 `[P74 / p.68]` 学生 4 转述的"电脑发热就像**锹形甲虫摩擦大颚产生能量**"是**错的**（见 §五-K）。
     **说明质量靠运气，不靠机制。**
3. 结对场景未适配：A 是给"一个学生"的。CX 是 driver/observer 双人，
   **同一个 A 对两个角色应有不同的问法**（driver 问"下一步写什么"，observer 问"你看出哪里会出错"）。

**→ 可落地到 CX 的具体建议（写进论文的"设计改进"节）：**
```
navigator 增加"目标锚 + 问数计数"：
  ① 任务开始时由教师/题库给出 goal_anchor（不是完整代码，是本题的关键决策点，可多个）
  ② navigator 以 goal_anchor 为终点反向生成问题链，硬约束不得直接说出
  ③ 记录 hops = 到达 anchor 所需的追问轮数 → 作为支架强度指标
  ④ hops 的历时下降 = 渐退触发信号（写入 ct.py 的证据链）
  ⑤ goal_anchor 必须经教师确认（补上宋双程缺的答案校验闸）
  ⑥ 允许 anchor 多解：达成任一 anchor 即视为到达，防止压制多解
  ⑦ driver / observer 各一套问法模板（宋双程无此需求，是 CX 的原创区）
```

**权责的唯一操作化：案例的三栏表**（这是本篇第二个可直接复用的形式创新）

`[P66–P68 / p.60–62]`（案例一）与 `[P70–P71 / p.64–65]`（案例二）均采用：

| 教师活动 | 学生活动 | 智能体活动 |
|---|---|---|

| 教师活动 | 学生活动 | 智能体活动 |
|---|---|---|

案例二"课中协同实验设计"的一行 `[P70 / p.64]`：

|---|---|---|

>
> **但本篇的三栏表也暴露了权责边界的缺失**：
> 全部两个案例、约 20 行，**"智能体活动"栏没有一行写明"此处需教师确认"或"AI 不得单独决定"**。

> "教师……都需要注重传递正向的情感态度和价值观，**防止技术异化对学生生命价值的侵蚀**"
> ——但这是**倡导，不是机制**：没有说哪些决策必须教师签字、哪些 AI 可自主。
>
> → **CX 的对应机会**：CX 已有的"教师口令闸""教师告警端点"（R5 护栏）
> 恰好是本篇缺的那一层。用户可以写：**"既有研究的师-机-生权责多停留于角色描述，

### 3.9 一个可直接用于"给 CX 定级"的外部框架（本篇的最大意外收获）

`[P15 / p.9]` 转述黄荣怀等 [23] 的 **iSTAR 人机协同教学框架**，其实践层次分四级：

```
① 人使用机器 → ② 基本人机协作 → ③ 双重人机协作 → ④ 复杂人机协作
```

**宋双程给自己的定位** `[P21 / p.15]`：
> "在课堂中，教学智能体与人类教师建立一种协作关系，实现**基本人机协作（HMC）**[23]"

**他的展望** `[P83 / p.77]`：
> "黄荣怀等[37]人提出'**复杂人机协作**'是人机协同教学领域未来发展取向，
> 即人类教师能够在安全平衡的人机生态系统中与**多种机器**开展协作以实现特定教育目标"

> ⭐ **这个四级量表对用户价值极高，因为它给"CX 比这一代研究强在哪"提供了一把外部尺子：**
>
> - 宋双程：单智能体 + 单人 1:1 对话 + 教师在旁 = **② 基本人机协作**（作者自述）
> - CX：**生-生结对（driver/observer，服务端权威角色轮转）+ AI 双 persona + 教师调控环 + 研究层状态机**
>   —— 至少是 **③ 双重人机协作**（人-人协作与人-机协作同时在场且互相嵌套）
>
> **可直接写进论文的一句**：
> "按黄荣怀等提出的人机协同实践四级层次，既有小学信息科技教学智能体研究
> （宋双程，2025，p.15）自评为'基本人机协作'；本研究的结对编程智能体因同时承载
> 生-生协作与人-机协作双重关系，处于'双重人机协作'层次，其权责与评价机制的复杂度不能简单外推自前者。"
>
> 这句话**同时完成了三件事**：给出定位、有外部框架背书、并解释了"为什么不能照抄前人方法"。

逐条判定：

### 4.1 【A】方向对，**归类错**（需要修正）

**对的部分**：
- "连代理指标都没有" —— ✅ **准确**。本篇确实无任何 proxy、无任何测量（§二已穷举验证）。
- "满意度冒充成效是通病" —— ✅ **准确**，且本篇是干净标本。

**错/不精确的部分**：

**（i）"直接'学生说喜欢' = 培养了素养" —— 本篇从未作此断言。**

原文的推论链是：
```
学生访谈高接受度 →〔p.68〕"这种分化恰好证明了智能体…教学的有效性" →〔p.75〕"显著提升了教学效果"
```
终点是"**教学效果**"，**不是"素养"，也不是"计算思维"**。
全文自始至终**没有声称测了或提升了任何素养/CT**。跳的是「喜欢 → 教学有效性」，
比第一波说的「喜欢 → 素养」**少跳一级**。

这不是抠字眼——它决定了这篇文献在用户论文里能被怎么引用：
- 若按第一波的描述引用（"该研究以学生满意度论证素养培养"），**是不实指控，会被评审查出**。
- 准确的引用应是：**"该研究以偏好访谈论证教学有效性，且未涉及素养测量"**。

**（ii）把 05 与 02 梁家健并列为"断层 2 的同一谱系"，抹掉了关键区别。**

第一波把 05 称作梁家健式"评价无 CT"的"**极端形态**"。但两者是**不同的病**：

| | 02 梁家健 | 05 宋双程 |
|---|---|---|
| 目标是否写 CT | ✅ 通篇写培养 CT | ❌ 未写（CT 仅作课标条文出现 2 次 + 案例目标 1 次） |
| DV 是什么 | 错误次数 / 评分报告（行为启发式） | **无 DV**（只有偏好访谈） |
| 病名 | **错测**（用非 CT 的量冒充 CT） | **未测**（根本没测） |
| 危险度 | **高**——有数字、有构念名，读者会当真 | **低**——无数字、无构念名，读者一眼看穿 |
| 是否自供 | 第 75 页被动承认 | **p.76 主动承认**（见 4.2） |

> **"未测"不是"错测"的极端形态，而是它的反面。**
> 第一波自己那句"**有数字的假比无数字的假更危险**"，恰恰蕴含了这个区分，
> 却又在同一句里把 05 说成"极端形态"，**内部不自洽**。
>
> **修正表述建议**（写进用户论文的文献述评）：
> "这一断层呈两种形态：一是**错测**（研究以培养计算思维为目标，实际测量的却是行为频次或系统评分，
> 如梁家健，2024），二是**未测**（研究未将思维素养纳入测量设计，仅以使用满意度论证效果，
> 如宋双程，2025）。前者因披着构念外衣而更具误导性，后者则暴露了该类设计-开发型研究
> **普遍缺乏结果测量环节**这一结构性问题。"

### 4.2 【A】**遗漏：作者的自供，比梁家健那句更干净、更适合引用**

如果不是同一批，论文**没有交代第四章 8 位教师的来源、也没有交代他们如何接触到该智能体**。
**两种情况下这份教师访谈数据都不可用。**

→ 这是第一波完全没抓到的、**可实锤的**方法缺陷。

### 4.5 【A】**遗漏：教师引语不可追溯（更硬的一击）**

`[P72–P73 / p.66–67]` 的结构是：先列 **教师 1 ～ 教师 8** 的原始引语，再作主题归纳，

| **教师 B** | "期望未来能**联动物联网教具**，比如学生编写完扫地机器人程序后，智能体可以直接模拟运行并反馈避障效果" | ❌ **原始引语中不存在** |

### 4.6 【A】**遗漏：AI 输出的事实错误被当作正面证据引用（最锋利的一条）**

`[P74 / p.68]` 学生 4 的原话：

**这个类比是错的**：电脑发热的机理是电流通过电阻的焦耳热与晶体管开关损耗；
"锹形甲虫摩擦大颚产生能量"既不是一个真实的生物学现象，也不构成任何有效类比
（摩擦生热与电阻生热在小学阶段可类比，但"甲虫摩擦大颚**产生能量**"是**能量守恒层面的错误表述**）。

**而作者把这条放在"学生高接受度"的正面证据里，未加任何标记。**

> ⭐ **这是"满意度冒充成效"最完整的三连标本**：
> **AI 说错了 → 学生很喜欢 → 研究者当成效。**
>
> 它比第一波那句抽象论断（"满意度冒充成效是通病"）**有力一个数量级**，

> 1. 缺 AI 输出质量闸（用户方案 idea J / Feldstein 5 维）的**具体后果**是什么；
> 2. 学生满意度**与内容正确性无关**——喜欢恰恰可能来自那个错误类比的生动性；
> 3. 研究者本人**没有能力发现**这个错误（他不是学科专家，也没有核验流程）。
>
> **建议这条作为用户论文中"为何必须设 AI 输出质量闸"的引证首选。**

> "宋双程（2025，p.68）在论证学生接受度时引用的一条学生反馈中，

> 前者因而不能作为教学有效性的充分证据。"

## 六、研读时的思考痕迹（留档，不修饰）

**（1）开局的误判与纠正。**
看到摘要里"培养学生的数字素养和创新精神""解决个性化教学实施困难"，
我一开始按"又一篇素养承诺 + 满意度验证"的模板准备下判。
读到第三章才发现判错了重点：**本篇 32 页的工程细节是它真正的重量所在**，
而第一波（只问评价）注定看不见这 32 页。这也解释了为什么第一波对本篇只留下一句话——
**不是本篇内容少，是提问框架把 42% 的正文屏蔽掉了。**

**（2）"计算思维"穷举检索的那一刻。**
我原本以为至少能找到 5–8 处 CT 表述，结果只有 3 处，且 2 处是课标条文转述。
这个数字本身是结论：**本篇不是"CT 测得差"，而是"CT 不在研究里"。**
于是我意识到第一波把它和梁家健放在同一谱系是错的——
**梁家健是把非 CT 的东西叫做 CT，宋双程是压根没提 CT。** 这两件事的危险度是反的。
（这一步是本次最重要的一个修正。）

**（3）发现"教师 1 的排障链"时的转折。**
读到"排查网络图标—IP 地址—防火墙"被归到"课堂活力"标题下，我停了很久。
这不是作者疏忽，是**他没有一个能接住这条证据的框架**。
CT 证据就在语料里，缺的不是采集能力，是编码手册。
→ 这条直接改变了我对本篇价值的判断：**它是一个"证据源丰富、编码框架为零"的样本**，
   对 CX 来说反而是最好的正面启示（CX 的日志比这密集得多）。

**（4）比对图 5-1 与图 6-1 的那 5 分钟。**
两张图我逐格对了三遍，确认师-机行 4 格、生-机行 3 格文字**逐字相同**。
第一遍以为自己漏看了；第三遍确认后，"两轮迭代"这个说法在我这里就塌了。
**但要注意区分**：功能层（3→4，答疑→启发式答疑）**是真迭代**。
所以准确的判断不是"他没迭代"，而是"**他迭代了系统，却把这个说成迭代了模式**"。
这个区分对用户是保护性的——用户的"三轮"如果只是系统在迭代，也会落进同一个坑。

**（5）"学情感知"的四工作流核对。**
我把四条主工作流 + 两条子工作流的输入逐一列出来，确认全部无状态。
然后再回去数"学情"这个词在论文里出现了多少次——很多。

无持久层 → 学情感知落不了地 → 支架只能自取不能推送 → 渐退无从谈起 → 学习分析与评价生成整条断掉。
**一个根因，五个症状，在这一篇里全齐。**

**（6）甲虫类比。**
这条是意外收获。我本来只是在核学生引语的真实性（因为已经发现教师引语有问题），

也不是有效类比（能量守恒层面就错了）。
而作者把它当"生动有趣"的正面证据。
**这一条比我这次找到的任何抽象论证都更有说服力。**

**（7）iSTAR 四级。**
这条是读参考文献综述时"顺带"看到的，但它可能是本次对用户**收益最高**的一条。

黄荣怀这把尺子有四档、有公开定义、被本篇作者自己用来定级（"基本人机协作"），

**对于要建立"我的研究和他们不一样在哪"的用户来说，裸露的样本比精致的样本更好用。**

## 七、苏格拉底式追问链

### 追问链 A：「没测 CT」到底是缺陷，还是诚实？

**Q1：本篇没测 CT，这是不是一个缺陷？**
第一反应：是。研究背景大谈信息科技四大核心素养（含计算思维），实践却零测量。

**Q2：等一下——本篇声称过要培养 CT 吗？**
查：全文 3 处 CT，2 处是课标条文转述，1 处是案例一的教学目标。
**研究目的（p.11 研究内容四条、p.2 摘要）里没有一条提到计算思维或任何素养测量。**
它的目标是"设计并开发一款教学智能体"+"提出应用策略"。
→ **按它自己声明的目标，它没有欠一份 CT 测量。**

**Q3：那它欠的是什么？**
欠的是"**教学效果**"的测量——因为它在第四章第三节明确设了"教学效果分析"这一节，
并在第六章下了"显著提升了教学效果"的结论。
**它欠的债是它自己借的，不是我们替它借的。**

**Q4：所以第一波把它列为"断层 2（评价无 CT）"的 archetype，对吗？**
不对。断层 2 的病灶是"**声称测 CT，实际测的不是 CT**"（梁家健）。
本篇是"**没声称测 CT，也没测任何东西**"。
把它归入断层 2 会导致一个实际后果：**用户在论文里引用时会写出不实指控**。

**Q5：那本篇应该被归到哪？**
应归入一个第一波没有单列的类别：**"设计-开发型研究的结果测量缺位"**。
这类研究以"做出了一个系统"为主要贡献，**结果测量是附加物、不是设计的一部分**，
因而必然退化为满意度访谈。**这是体裁决定的，不是作者个人的失误。**

**Q6：这个重新归类对用户有什么用？**
巨大。因为**用户自己的研究也带着强烈的设计-开发色彩**（CX 平台是实打实的系统）。
如果用户把这类文献都归入"他们测错了"，就学不到真正的教训；
如果归入"**设计-开发型研究天然会把测量当附加物**"，用户就会明白：
**要避免同一命运，测量必须在系统设计之初就作为一个模块被设计进去，而不是做完系统再去补测。**
→ **这正是 CX 已经在做的事（`study.py` 研究层状态机、`ct.py` 六维、`seed_ct_v1.py` 18 题卷
   与业务代码同仓、同生命周期）。用户应当在论文里把这一点显式说出来**：
   "本研究将测量层作为系统的一等模块（而非事后评估工具）纳入设计，
   以规避设计-开发型研究中普遍存在的结果测量缺位（如宋双程，2025）。"

**收敛 A**：本篇不是"评价无 CT"的极端形态，而是"**设计-开发型研究把测量当附加物**"的标本。
用户的差异化，不在于维度切得更好，而在于**测量与系统同生命周期**。

### 追问链 B：模式 1.0 → 2.0 差量为零，"两轮迭代"还成立吗？——迭代的最小可辨识单位是什么？

**Q1：模式 1.0 和 2.0 一字未变（除阶段名与两个环节的顺序），能说"优化了模式"吗？**
不能。"优化"要求存在一个可指认的**改进量**。

**Q2：但作者确实迭代了功能（3→4，答疑→启发式答疑）。这算不算迭代？**
算，而且是**实质性的**："答疑"→"启发式答疑"改变了智能体与学生的知识关系
（从供给方变成引导方），这是设计层面的质变。

**Q3：那为什么功能变了、模式没变？**
因为**这个模式图的抽象层级太高，容不下功能层的变化**。
"协同答疑"这个格子，无论智能体是直接给答案还是启发式引导，格子里的字都是"AI 为学生提供启发式答疑"。
→ **模式图的格子粒度 ≥ 功能变化的粒度时，任何功能改进在模式层都不可见。**

**Q4：这是本篇独有的问题，还是普遍的？**
普遍。第二波已经发现谢鑫的轮名与其瀑布环节逐条同义——**同一个病**：
模式图的语言与实现的语言不在同一层，导致模式图**既不能约束实现，也不能被实现证伪**。

**Q5：那用户的"师—机—生三轮迭代"会不会重蹈？**
**会，除非能回答一个问题：第 1 轮和第 2 轮之间，模式图上哪个格子的内容变了？依据哪条数据？**
如果答不上来，"三轮"就是叙事装置。

**Q6：怎么让它答得上来？**
把模式图的粒度**下降到与可观测量同层**。具体地：

```
每一轮迭代，预先声明：
  ① 可变格（这一轮允许改哪几个格子）—— 不是所有格子都可变，否则不是迭代是重写
  ② 变更判据（哪条数据达到什么阈值就触发这一格的变更）
  ③ 变更留痕（改前 / 改后 / 触发它的那批数据 ID）
```

举例（CX 可落地）：
- 可变格 = "支架推送强度"（教师调控环）
- 判据 = 该班 `hops`（到达 goal_anchor 的平均追问轮数）连续两次作业下降 ≥20%
- 变更 = 下一轮该班 navigator 的初始提示密度降一档
- 留痕 = `study` 表记录 round_id / before / after / trigger_metric / evidence_ids

**Q7：这样"三轮"就有意义了吗？**
有，而且获得了**有限性**：当所有可变格都到达最低支架档、或连续两轮判据不触发 → **收敛，退出**。
**"三轮"从此不是画三个圈，而是一个有终止条件的过程。**
→ 这恰好是第二波指出的"四篇模式图只画无限闭环"的正解，
   而本篇（图是线性、文字喊闭环）反过来证明了：**光把图画成线性也不够，
   有限性必须来自"收敛判据"，不能来自"课时天然有终点"。**

**收敛 B**：迭代的最小可辨识单位 = **（可变格 × 变更判据 × 留痕）**。
三者缺一，"N 轮迭代"就是叙事。本篇缺全部三者，所以"两轮"不可引用；
用户必须在论文的方法章把这三者写死，否则"三轮"会被评审用同一把刀砍。

### 追问链 C：「答案锚 + 反向问题链」能不能搬到 CX 的结对编程？

**Q1：这个模式的本质是什么？**
先算出终点 A，再让模型在"不得说出 A"的约束下反向生成通往 A 的问题链。
**本质是给苏格拉底式对话装了一个目标函数。**

**Q2：CX 现在的 `ai_navigator` 有目标函数吗？**
没有。它只有负向约束（拒绝写完整代码 + 反越狱）。
**负向约束保证"不代做"，不保证"引导有效"**——模型可以问一堆无关问题，系统无从判断。

**Q3：那直接抄过来？**
不行，因为编程任务和"信息科技设备有哪些"不同：**编程一题多解**。
若把 A 设成一份标准代码，反向问题链会把所有学生逼向同一个实现，**压制多解**。

**Q4：那 A 应该是什么？**
不是"标准答案"，是"**关键决策点**"。
例：判断成绩等级的题，A 不应是一段 if-elif 代码，而应是一组决策锚：
```
anchor_1: 意识到需要按区间划分（而非逐值枚举）  ← 问题分解
anchor_2: 意识到区间必须互斥且完备              ← 抽象建模
anchor_3: 选择一种控制结构实现（if链/字典/bisect 均可）← 算法设计
anchor_4: 能构造边界用例验证（89/90/100/-1）    ← 调试评估
```
→ **四个 anchor 恰好一一映射到用户的 CT 四要素。**
   多解被允许（anchor_3 明确接受多种实现），但每个 anchor 的**达成**是可判定的。

**Q5：这解决了什么 CX 现在解决不了的问题？**
三个：
1. **navigator 有了正向目标**（引导有效性可判定）；
2. **CT 证据从"行为计数"升级为"anchor 达成"**——
   这直接回答了第一波诊断的"行为→构念那一跳无锚"：**anchor 就是那个锚**，
   且它是**任务级预设的**，不是从行为反推的，因而不构成同义反复；
3. **渐退有了度量**：`hops_to_anchor`（到达每个 anchor 所需追问轮数）历时下降 = 支架可降档。

**Q6：宋双程的版本有什么坑必须补？**
两个：
- **答案质量零校验**（他的 A 来自知识库+必应+大模型，错了整条链会更有说服力地引向错误）。
  → CX 必须让 anchor 由**教师/题库预设并确认**，不能由模型现算。
- **单人假设**。CX 是 driver/observer 双人。
  → 同一 anchor 需两套问法：driver（"下一步你打算怎么处理 90 分这个边界？"）
     vs observer（"你觉得他这个写法，输入 90 会走哪个分支？"）。
     **这是宋双程完全没有的需求，是用户的原创区。**

**Q7：会不会有人说"这不就是把答案藏起来"？**
会。反驳点在于 anchor 是**认知里程碑**不是**解**：
学生达成 anchor_2（意识到区间必须互斥完备）时，**离可运行的代码还很远**，
且不同学生从 anchor_2 走到代码的路径完全可以不同。
**anchor 约束的是"想到没想到"，不是"写成什么样"。**

**收敛 C**：本篇的「答案锚 + 反向问题链」是可抄的，但必须做三处改造：
**A 从"标准答案"改为"CT 四要素对齐的多解容忍 anchor 组"；
anchor 由教师预设并确认（补答案校验闸）；
driver/observer 双套问法。**
改造后，它同时解决了 navigator 无目标、CT 无锚、渐退无度量三个问题——
**这可能是本次二次研读产出的最高价值的一条工程建议。**

### 追问链 D：四场景×四角色 vs 四职能，哪个切法在 CX 上真能落地？

**Q1：宋双程的切法（课堂/评价/小组/课后 × 答疑/纠错/协作/跨学科）和用户的切法（学情感知/支架推送/学习分析/评价生成），哪个更好？**
先别问好坏，问一个更可判定的问题：**哪个切法的每一格都有实现兜底？**

**Q2：核对宋双程的四格。**
四场景 → 四角色 → 四工作流 → 四快捷指令，**四层一一对应，全链闭合，零空格**。
（唯一的空头是模块框架里的"学情感知"，但那不在他的四角色切法里，
 那是他从卢宇那儿抄来的五模块框架里的东西。）

**Q3：核对用户的四职能在本篇上的落地情况。**
学情感知 ❌（无实现）、支架推送 ⚠️（实际是自取）、学习分析 ❌、评价生成 ⚠️（实为单点纠错）。
→ **用户的四职能，在本篇这样的架构上，四格里有两格半是空的。**

**Q4：为什么宋双程的切法能填满，用户的填不满？**
因为**切分依据不同**：
- 宋双程按**教学场景/时机**切 → 每个场景对应一次学生主动发起的交互 → **无状态即可实现**
- 用户按**智能体职能**切 → 学情感知/学习分析**本质上需要状态** → 必须有持久层

**Q5：所以用户的切法更差？**
不。**用户的切法更贵，但也更强**。
关键在于：**用户的切法是有依赖序的，不是四条并列。**

```
学情感知（需持久层）
    ├──▶ 支架推送（需学情感知才能"推"，否则只能"自取"）
    └──▶ 学习分析（需持久层 + 时间序）
              └──▶ 评价生成（需学习分析 + 外部锚）
```

**Q6：这条依赖链有什么用？**
它把第二波的"四缺口同一根因 = 缺跨会话画像持久层"从**归纳**升级为**结构性证明**：
**不是四个缺口碰巧同源，而是四职能本来就串在一条链上，
链首（持久层）断了，后面三个必然全断。**
本篇是这条链的完整反面验证：**它链首就没有，所以后面三个一个都没有，而且作者没意识到。**

**Q7：用户论文里怎么用？**
建议把四职能**画成依赖链而不是并列四框**，并明确写：
"四职能并非并列，而是以跨会话学情持久化为链首的依赖序；
既有研究（如宋双程，2025）因采用无状态工作流架构，
其'学情感知''学习分析'仅存在于框架描述层，未见实现，
其支架机制因而退化为学习者自取式而非系统推送式。"
→ **一句话同时立了自己的架构、点了别人的名、还给出了机制解释。**

**收敛 D**：宋双程的切法（场景×角色）优点是可落地、零空格，但**天花板低**（无状态就是上限）。
用户的切法（职能）成本高但天花板高，**且必须画成依赖链才能解释清楚"为什么别人做不到"**。
两种切法**不冲突**：可以用职能切内部架构，用场景×角色切对外的功能入口（这正是 CX 现在的样子）。

### 追问链 E：为什么"学情感知"会出现"声称有、实现无"？这个缺口在 CX 上会不会重演？

**Q1：宋双程是在撒谎吗？**
大概率不是。他在三栏表里写"智能分析学情"时，很可能真的认为这件事会发生——
因为**从教师视角看，把学情数据粘进 Coze 对话框，智能体确实会输出一份"学情分析"**。

**Q2：那问题在哪？**
问题在**边界**：那个动作是**教师手工完成的一次性提示词交互**，不是智能体的自主能力。
第五章的原句其实说漏了嘴 `[P76 / p.70]`："**在线平台导出的**学情数据，通过对教学智能体的快速分析……"
→ **数据来源是"在线平台导出"，即人工搬运。**
"智能体具备学情感知能力" ≠ "教师可以把学情粘给智能体分析"。

**Q3：这个混淆有名字吗？**
可以叫"**能力归属错置**"：把"人 + 工具可以完成 X"记成"工具具备 X"。
它在 LLM 时代特别高发，因为 LLM 对任何粘进去的东西都能生成看似专业的输出。

**Q4：CX 会不会重演？**
**会，而且风险点很具体**。CX 已有 `insights.py`、`ct.py`，看起来"有分析"。
但要问三个问题：
1. 分析的**输入**是自动流入的，还是需要人工触发/搬运？
2. 分析的**输出**是否进入了下一次教学决策，还是只渲染成一张图？
3. 分析的**结果**是否被持久化并跨会话可比，还是每次现算？

**Q5：怎么判定"没有重演"？**
一个可操作的判据：**断掉人工环节，系统还能不能跑完一圈？**
```
学生行为 → (自动) 埋点入库 → (自动) 学情计算 → (自动) 触发支架档位调整 → 下一次交互
                                       └──▶ (自动) 生成教师侧提示
```
如果这条链上任何一环需要教师手工导出/粘贴/点击，那一环就是"能力归属错置"的候选。
（注：**教师终审闸是有意设计的人工环节，不算这里说的断点**——
 区别在于：终审是"人有权否决自动结果"，搬运是"没人干就什么都不会发生"。）

**Q6：这对论文写作有什么要求？**
**用户在描述 CX 的四职能时，每一条都应当标注"自动/半自动/人工"，并给出证据位置。**
这样做有两个好处：
- 防止自己重蹈"陈述句伪装成能力"（本篇第五章的病，§五-H）；
- 让评审无法用同一把刀砍——**主动交代边界的论文，比被查出边界的论文强得多**。

**收敛 E**：本篇的"学情感知空头"根因是**能力归属错置**（人+工具能做 ≠ 工具具备）。
判据是"**断掉人工环节，链条还能不能自转**"。
用户应在论文中对四职能逐条标注自动化程度并给证据位置，
**主动交代边界本身就是与这批文献的差异化。**

### 追问收敛：本次二次研读问出来的、第一波没有的六个结论

1. **本篇不属于"评价无 CT"（错测），而属于"设计-开发型研究的结果测量缺位"（未测）。**
   两者危险度相反；第一波的归类会导致用户写出不实指控。→ 必须修正表述。

2. **"作品当访谈素材"是事实错误——本篇根本没采集作品。**
   案例二的程序 + 折线图是本批文献里离"可评作品"最近的一次机会，被完整放过。
   这让"作品测评是集体空白"这一论断**更强**。

3. **模式 1.0→2.0 差量为零，而功能层是真迭代。**
   → 迭代的最小可辨识单位 = 可变格 × 变更判据 × 留痕。
   用户的"三轮"若不预先声明这三者，会被同一把刀砍。

4. **「答案锚 + 反向问题链」是本篇最有工程价值的发现，第一波完全没看到。**
   改造方案：anchor 组对齐 CT 四要素 + 多解容忍 + 教师预设确认 + driver/observer 双套问法。
   一次性解决 navigator 无目标、CT 无锚、渐退无度量三个问题。

5. **四职能是依赖链不是并列四框**，链首是跨会话持久层。
   本篇是这条链的完整反面验证（链首没有 → 后三个全无 → 且作者未察觉）。
   → 用户论文应把四职能画成依赖链，这比画成并列框多解释了"为什么别人做不到"。

6. **iSTAR 四级层次给了用户一把外部尺子**：
   宋双程自评"基本人机协作"；CX 因同时承载生-生协作与人-机协作，至少是"双重人机协作"。
   → 这是"不能照抄前人方法"的最经济论证方式。
