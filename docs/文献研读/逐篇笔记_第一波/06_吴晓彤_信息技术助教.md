### 2.2 L1：精确度/召回率——**证据链每一环的可复算性检查**（本轮最硬的发现）

#### 2.2.1 声称的流程（p.77–78 / PDF 88–89）

1. **问题收集**：3 名教师，收集必修二《信息系统与社会》常问问题 **10 个**（A1–A5 教学设计场景、A6–A10 生成测试题场景，表 5-1，p.78 / PDF 89）。
2. **金标准制定**：研究者 + 3 名信息技术教师组成"评估小组"，依据教学大纲、课标、教科书、课程教学目标，为每题制定标准答案，包含 **6 类评价要点**：`知识点 / 逻辑步骤 / 关键结论 / 案例 / 学科核心素养 / 表达规范`。
3. **标注一致性**：前 5 题共同标注、协商达成共识；后 5 题**独立标注**，"经一致性计算发现，评价要点的标注一致性达到 **0.83**"（p.78 / PDF 89）。
4. **测试**：10 题分别输入 助教智能体 / 文心一言 / Kimi / DeepSeek。
5. **判定**：与标准答案逐一比对，"**完全正确或关键要点都涵盖的可视为正确；部分正确可根据与标准答案的契合度酌情判断；回答完全错误或与问题无关则为错误**"，"**标记'正确'或'错误'**"。
6. **统计**：代入 `Precision = TP/(TP+FP)`、`Recall = TP/(TP+FN)`（式 1、式 2，p.78–79 / PDF 89–90）。

#### 2.2.2 断链点 A：**判定粒度与结果呈现在方法上不相容**

第 5 步明确写的是**题级二分**——"标记'正确'或'错误'"、"统计正确回答的**问题数量**"。
若真按题级二分，**单题的 P/R 只能取 0 或 1**。

但表 5-2（p.79 / PDF 90）给出的是**每题四模型各一对连续小数**（如 A1 助教 0.915 / 0.900）。
连续值只可能来自**要点级**计数（一题内有 k 个评价要点，TP/FP/FN 在要点上计）。

→ **文本自述的分析单位（题）与表格的分析单位（要点）互相矛盾**，且：
- **每题有多少个评价要点，一个数都没给**；
- **TP / FP / FN 的原始计数，一个都没给**；
- **谁来判定"部分正确…酌情判断"，酌情的规则是什么，没有细则**。

> ⚠️ **判定**：表 5-2 **在方法学上不可复算**。这不是"算错了"，是"读者无法知道它是怎么算的"。
> 这比第一波说的"把整题对错错套 P/R"（synthesis line 95）**更严重**——错套至少还能复现；这里连粒度都不确定。

#### 2.2.3 断链点 B：**"一致性 0.83"没有说明是什么统计量**

原文只有一句："经一致性计算发现，评价要点的标注一致性达到 0.83"（p.78 / PDF 89）。
- 没说是 **Cohen's Kappa / Krippendorff's α / 百分比一致性 / ICC** 中的哪一个；
- 没说 **n（标注了多少个要点）**；
- 没说**几人两两配对还是四人多评**（评估小组是"研究者 + 3 名教师"共 4 人）；
- 没给**未达标时的迭代过程**（对比 03_杨瑞珍 是"抽 15% 试编→未达标→修订框架→再抽 17%→Kappa≥0.8 才正式编码"）。

若 0.83 只是**百分比一致性**（最可能，因为它没做任何机会校正的说明），那它**不足以支撑"标注结果较为准确"的结论**——
百分比一致性在二分任务上基线可高达 0.5–0.7。

#### 2.2.4 断链点 C：**知识库与金标准同源 = 构念污染**（第一波完全没提，本轮最狠的一击）

- 金标准是评估小组"**依据教学大纲、普通高中信息技术课程标准的要求、《信息系统与社会》教科书、课程教学目标**"制定的（p.78 / PDF 89）。
- 助教智能体的知识库上传的正是"**测试题题库、普通高中信息技术课程标准(2017年版2020年修订)、粤教版/人教版/浙教版等不同版本《信息系统与社会》教科书、教学设计资源**"（p.55 / PDF 66，图 4-9）。

→ **实验组的检索源与评分金标准是同一批文件**；三个通用大模型没有这批文件。
这不是"学科智能体更懂学科"，这是**把答案册喂给了考生之一**。
P/R 的优势中，"检索到与金标准同源的原文"贡献了多少、"生成质量"贡献了多少，**在本设计下不可分离**。

> 💭 这一条我犹豫过是否过苛：RAG 的本意就是接入权威资料，接入课标不算作弊。
> 但**"评分标准也由这批同样的资料生成、且由制定标准的同一批人来评分"**，三重同源叠加，
> 就不再是公平比较，而是**循环验证**。类比：用教材原文当标准答案，去比较"背了教材的学生"和"没背的学生"。

#### 2.2.5 断链点 D：**无盲评、无重复采样**

- 研究者本人是评估小组成员，且**知道哪一份输出来自自己开发的智能体**（未描述任何遮蔽、乱序、编号呈现程序）。
- 每模型每题**只跑 1 次**；未报模型版本号、时间、温度/采样参数。LLM 输出的随机性完全未处理。
- 四个被比较对象**能力代差巨大**（豆包 + RAG + 六工作流编排 vs 三个裸对话模型），却按同一提问方式提问，**未给通用大模型任何提示词工程或资料上传的对等条件**。

### 2.3 L2：SRL 量表——维度操作定义 / 条目 / 信度数值 / 效度缺口

#### 2.3.1 工具来源与结构

- 来源：**Barnard L, Paton V, Lan W. Online Self-Regulatory Learning Behaviors As a Mediator In The Relationship Between Online Course Perceptions With Achievement. IRRODL, 2008, 9(2):1-11.**（脚注，p.80–81 / PDF 91–92；即 OSLQ 的前身量表）
- 结构：**18 题、5 维、5 点李克特**（p.81 / PDF 92），维度与题数（表 5-3，p.83 / PDF 94；条目全文见附录 6，p.124–125 / PDF 135–136）：

| 维度 | 题数 | 题号 | α |
|---|---|---|---|
| 目标设定 | 4 | 1–4 | 0.857 |
| 学习任务策略 | 4 | 5–8 | 0.863 |
| 时间管理 | 3 | 9–11 | 0.817 |
| 寻求帮助 | 3 | 12–14 | 0.821 |
| 自我评估 | 4 | 15–18 | 0.851 |
| **合计** | **18** | | **表中写 0.963** |

#### 2.3.2 硬伤 1：**总 α 正文与表格自相矛盾**（第一波引了 α 却没发现）

- **正文 p.82 / PDF 93**：">评价量表的总克隆巴赫 Alpha 系数达到 **0.874**，显示出较高的整体信度。"
- **表 5-3 p.83 / PDF 94** 最后一行："系数和总项目 | **0.963** | 18"

**0.874 ≠ 0.963**，同一份数据、同一页相邻，两处并存且无任何说明。
且从统计上看，5 个分维 α 在 0.817–0.863 之间、18 题合并，**0.963 更符合数量效应（题数越多 α 越高）**，
0.874 反而偏低——即**正文那个数更可能是笔误或从别处抄来**。无论哪个是真，**这份 α 报告已不可单独引用**。

#### 2.3.3 硬伤 2：**李克特锚点与题干语义错配**（条目层效度问题，第一波完全没看）

附录 6（p.124–125 / PDF 135–136）**全部 18 题的作答选项都是**：
`非常满意 / 满意 / 一般 / 不满意 / 非常不满意`

但题干**全部是行为频率/程度陈述**，例如：
- 第 1 题："我会为信息技术课程的学习任务**设定完成的标准**。"
- 第 6 题："为了不走神，我会**大声读出**信息技术课程中的任务指南部分。"
- 第 9 题："我会**额外分配更多的时间**给信息技术，因为信息技术的课堂时间一周仅有一节。"

→ 让学生对"我会不会大声朗读任务指南"回答"**非常满意/不满意**"，**语义上不通**。
正确锚点应为 `非常符合—非常不符合` 或 `总是—从不`。
这不是排版小疵，**是条目层的应答框架错误**，会直接污染 18 题的全部作答分布——
而作者对此毫无察觉，还基于这份数据做了 6 次 t 检验。

> 💭 我反复核了两遍附录 6，18 题的锚点行确实一模一样，全是满意度五级。
> 这条比总 α 矛盾更致命：α 高只说明"学生答得一致"，如果他们一致地在误解题目，α 反而更高。
> 这正是 synthesis line 182"'有流程'≠有效度"的具体形态——**它有量表、有 α、有前后测，但条目本身就是坏的**。

#### 2.3.4 硬伤 3：**只有信度，零效度**

- 无 **KMO / Bartlett / 探索或验证性因子分析**（全文 `KMO` 0 命中）；

### 3.2 智能体架构：ReAct 五模块（宣称层）+ 单 Agent 六技能六工作流（实现层）

#### 3.2.1 宣称层：基于 ReAct 的五模块技术架构（图 4-2，p.47 / PDF 58）

ReAct 定义（p.46 / PDF 57）：`思考(下一步做什么/调用什么工具) → 行动(调用工具执行) → 观察(任务执行结果)` 反复循环。

五模块（p.47–48 / PDF 58–59）：

| 模块 | 内容 | 原文要点 |
|---|---|---|
| **核心大脑** | **豆包大语言模型** | 接收多模态教育任务输入（文本/图像/音频/视频） |
| **教育任务规划** | 规划 · 决策 · 反思 | 规划=复杂任务拆子任务；决策=定步骤与工具；**反思=审视行动结果，优化子任务分解** |
| **知识与记忆** | 短时 / 长时 / 混合 | **短时=教育提示信息；长时=RAG 知识库；混合=人机对话历史** |
| **工具** | 外部数据库 + 插件 + 其他大模型 | 学术论文检索、必应搜索、接入考试数据库生成试卷 |
| **行动** | 依据记忆+规划决策调工具执行 | 持续观察结果 → 反思迭代 → 输出 |

**三层记忆的切法是本篇最值得抄的架构语言**（短时=提示 / 长时=RAG / 混合=对话历史），
可直接映射到用户 CX：`ai.py` 的 system prompt = 短时；`resources.py` 知识库 = 长时；会话历史 = 混合。
**但用户模型缺的第四层——跨会话学生画像持久层——本篇同样缺**（详见 3.2.5）。

#### 3.2.2 实现层：**明确自述"单 Agent 模式"**

> p.59 / PDF 70 原文：**"本研究开发的信息技术学科助教智能体是基于大模型的单 Agent 模式。信息技术学科助教智能体共包括六大技能，因此搭建了六个工作流。"**

→ **不是多智能体**。六技能 = 六工作流 = 六条并行的独立管线，**彼此不通信、无编排层、无仲裁**。

**"智能体"在本篇 = "一个配了工作流的对话应用"**，不是自治体。

|---|---|---|

> ⚠️ **对用户四职能切法的检验结论**：
> 本篇是"**产出物驱动切法**"的完整样本，其代价一目了然——
> **六个技能之间没有任何信息流**。"生成教师评语"不知道"生成测试题"出的是哪套卷，
> "生成教学设计"不知道上一节课的评语说了什么。**每个技能都从零开始，每次都要教师手工重述上下文**。
>
> 这恰恰**正面支持了用户的"四职能"切法**：按教学职能切，职能之间天然有先后与数据依赖，
> **有可能定义契约**；按产出物切，产出物之间天然无依赖，**契约无从谈起**。
> 但用户仍须补上第二波指出的缺口：**四职能之间的数据契约必须显式写出来**（`学情感知` 输出什么 schema、
> `支架推送` 消费哪些字段、`学习分析` 的输入是不是 `支架推送` 的效果回执），否则会退化成本篇的六条平行管线。

#### 3.2.4 工作流内部结构：**全文唯一的真迭代循环，但判据是"教师说满意"**

工作流构建思路（图 4-16，p.61 / PDF 72；文字见 p.60 / PDF 71）：

```
开始节点
  └─ 询问：是否已提供主题或参考文档？
       ├─ 有文档 → 调用「读取用户链接」插件 → 代码节点统一各种格式 → content
       └─ 无文档 → 输出文字提示，告知用户等待
  ↓
知识库节点（Query = 开始-topic）
  ↓
生成标题节点（LLM：豆包·工具调用）
  ↓
生成内容节点（LLM：豆包·工具调用）
  ↓
询问用户是否满意？
  ├─ 满意 → 问答节点 → 意图识别节点 → 询问是否生成新文档 → 生成文档返回
  └─ 不满意 → ⟲ 进入循环，重复"生成标题+内容"，直到用户满意才退出
```

> ⚠️ **这是全文唯一的闭环，且它有明确的终止条件——但终止条件是"教师主观满意"**。
> 没有任何质量指标、没有最大循环次数、没有降级策略。
>
> **对用户"三轮迭代"的直接启示**：用户模型的"三轮"如果只是"直到教师满意"，
> 就与本篇的 while 循环同构，**不构成教学模式创新**。
> 用户的差异化必须落在：**每一轮的进入条件、退出判据、以及轮与轮之间被改变的是什么状态**——
> 这三样本篇一样都没有（第二波已在 10_谢鑫处看到"有限 4 周 5 步"是有的）。

#### 3.2.5 记忆与画像：**宣称有跨会话记忆，实现时主动砍掉了它**（本轮最重要的架构发现）

**宣称（p.45 / PDF 56，"Coze 平台优势·持久化的记忆能力"）**：
> "本研究开发的信息技术助教智能体针对的是'信息系统与社会'这个模块，使用者是信息技术教师，教学对象是高二年级的学生，**可以通过创建数据库来记录教师的经常性需求以及学生信息的变化**。"

**实现（p.54 / PDF 65，"技能"节末）**：
> "本研究所开发的信息技术助教智能体将技能分模块进行开发，**教师每使用一个技能可以重新添加对话**，这样做的目的是为让了智能体更加准确的识别教师的需求，**减少大模型产生的幻觉问题**……**智能体每次重新添加对话也限制了其他无关功能，减低出现识别混乱的风险**。"

**使用手册（p.76 / PDF 87）**再次确认操作规程：
> "教师每次使用一个特定功能可以点击输入框上方的快捷指令，**若要切换下一个功能，可以点击左下角+开始新对话**。"

→ **它把"跨会话记忆"作为平台优势写进论文，然后在设计上主动放弃了它**，理由是幻觉与意图识别混乱。
全文**没有任何学生画像表、没有任何跨会话状态、六技能之间零共享**。

> ⚠️ **对用户第二波结论的强佐证 + 反面教材**：
> 第二波结论是"四缺口同一根因 = **缺跨会话画像持久层**"。
> 本篇提供了一个**主动放弃**该层的样本，并暴露了放弃它的**真实工程动机**：
> **上下文越长，意图识别越差、幻觉越多**。
>
> 这不是懒惰，是一个**真实的工程权衡**。用户在设计 CX 画像持久层时必须正面回应它：
> **画像不能作为"更长的对话上下文"注入 prompt，必须是结构化的、按需检索的、有 schema 的持久实体**
> （即：不是把历史对话粘回去，而是把"学生 X 在算法设计维近三次的证据摘要"作为字段注入）。
> 否则用户会撞上与吴晓彤完全相同的墙，然后做出与她相同的选择——砍掉记忆。
> **这是本篇对用户最有工程价值的一句话。**

#### 3.2.6 知识库与检索层的技术细节（含两处技术性错误）

**知识库资源清单**（p.55–56 / PDF 66–67，图 4-9、表 4-2）：
- 普通高中信息技术课程标准（2017 年版 2020 年修订）
- **粤教版 / 人教版 / 浙教版 / 教科版**《信息系统与社会》教科书
- 教学设计资源
- **测试题题库 1245 题**（表 4-2，p.56 / PDF 67）：单选 **521**、多选 **278**、填空 **88**、判断 **200**、简答 **108**、案例分析 **50**
  - 来源：多版本教材、国家中小学智慧平台资源库、学科网、一线教师自编题、学术文献题
  - 以**表格数据库**形式保存，需配置表结构与**索引字段**（系统将 Query 与索引字段内容比对，按相似度匹配）

**检索参数**（p.61–62 / PDF 72–73，图 4-17）：
- 搜索策略：**混合搜索**（全文检索 + 语义检索）
- **最大召回量 = 15**（平台上限 20）——理由："太大可能导致召回段落超过 Token 限制"
- **最小匹配度**：⚠️ **原文自相矛盾**——
  > "如果开发者希望返回的结果非常精确，可以选择较大的数值，**本研究调至 0.9 左右。因此本研究将最小匹配度设为最大值 0.99**。"
  >
  > **0.9 还是 0.99？同一句话里两个值。** 且 **0.99 的最小匹配度在实践中几乎必然导致零召回**
  > （余弦相似度 ≥0.99 意味着 query 与段落几乎逐字相同）。若真设 0.99，RAG 事实上被关闭，
  > 那 §2.2.4 说的"知识库=答案册"污染反而不成立、而 P/R 的优势就更无从解释。**两种可能都对结论不利。**

**词嵌入模型**（p.58 / PDF 69，图 4-12）：⚠️ **技术不自洽，不可引用**
- 声称使用 **Word2Vec**，并给出训练参数：`window=5~10`、`vector_size=100~300`、`min_count=5~10`
- 声称做了词类比评估："**数据库 - 存储设备 + 显示器 ≈ 信息系统**"
- **问题 1**：Coze 是**零代码平台**，用户**无法上传自训的 Word2Vec 模型作为知识库向量化引擎**，平台使用内置 embedding。图 4-12 的"训练参数设置"与其所述开发环境**在技术上不成立**。
- **问题 2**：**技术代差**。Word2Vec（2013）是静态词向量，**不能编码句/段语义**，而 RAG 检索的基本单位是**段落**。用 Word2Vec 做段落检索是 2016 年前的做法；论文自己在 p.7 / PDF 18 的文献综述里刚讲完 BERT/Transformer 时代，转头在实现里用 Word2Vec。
- **问题 3**：给出的词类比式子**语义上不成立**（"数据库−存储设备+显示器"在任何语义空间里都推不出"信息系统"）。这更像是照着 `king−man+woman≈queen` 造的仿写句。

> ⚠️ **判定**：**第 4.6 节（词嵌入）整节不可引用**。这是全篇技术可信度最低的部分。
> 摘要（PDF 4）却把"通过检索增强生成技术、**词嵌入技术**开发了辅助教师教学的智能体"写成核心贡献之一。

1. **成绩排名等个人信息的变化趋势**——"具体且准确地指出进步或退步情况及**幅度**"
2. **知识点掌握程度诊断**——"明确指出学生掌握较好和薄弱的知识点"
3. **核心素养的深度诊断评估**——"结合学科特点阐述学生在核心素养方面的表现"
4. **针对性、建设性的建议 + 激励性点评**
5. **推荐个性化习题强化训练**——"习题要与学生的问题紧密相关且难度适中"
+ 技能 2「优化评语风格」：**根据不同学生的性格特点和学习风格调整语言风格**（亲和力/感染力/严谨性）

⚠️ **但这段提示词有一处硬伤**：其 `===回复示例===` 给的是**物理学科**的力学评语——
"你对**物理**中的力学概念有了一定理解，如**牛顿第二定律**……复杂的**受力分析**问题，**力的合成与分解**运用不够熟练"，
推荐习题是"一个质量为 m 的物体放在粗糙水平面上，受到水平拉力 F，**动摩擦因数 μ**……求加速度"。
→ **在一个"信息技术学科助教"里，few-shot 示例整段是物理题**。这会把 LLM 的输出分布直接拉向错误学科，
是**提示词工程的低级错误**，且论文原样印在正文里未察觉。

**⚠️ 伦理约束的结构性缺失（重要对比）**：
六条工作流的"限制"段**只有三类**：不答无关话题 / 严格按格式 / 注明来源。
**没有任何"助学不代学"式的教学伦理约束**——因为使用者是教师，**代做正是产品目标**。

> 💭 这条对比很重要，别搞混：
> **面向教师的助教 Agent 与面向学生的学伴 Agent，其约束设计方向是相反的**。
> 吴文的提示词以"生成得越完整越好（不少于 2000 字）"为目标；
> 用户 CX 的 `ai_navigator` 以"拒绝写完整代码"为目标。
> **用户绝不能照抄本篇的提示词框架去写学生侧 persona**——四段式（角色/技能/限制/格式）可以抄，
> 但"限制"段的内容要完全重写。这一点第二波在 07/19 处已有触及，本篇把反差做到了最大。

### 3.3 支架与渐退：**完全空白**（0 命中）

全文检索 `脚手架 / 支架 / 渐退 / fading / 逐步撤除`——**全部 0 命中**。

最接近"支架"的三处：
1. **技能 6 概念趣味讲解**（p.54 / PDF 65）：用比喻/故事/生活实例把抽象概念讲成 ≤200 字——但**输出对象是教师**，教师再转述给学生。属于"教师的备课素材"，不是给学生的支架。

- **输入极贫**：p.76 / PDF 87 的使用示例是 `"李明，高二，信息技术计算机网络测试题得分60分，对计算机网络在信息系统中的作用理解不清。"`
  → **一个姓名 + 一个总分 + 一句教师的主观判断**。
  而 p.30 / PDF 41 宣称评语是"根据学生的学习表现、作业完成情况、考试分数等**多维度数据**，自动生成既个性化又富有针对性的评语"。
  **宣称"多维度数据驱动"，实现是"教师手打一句话"**。所谓"数据驱动的个性化评语"，
  其个性化信息量 ≈ 教师原本就知道的东西，智能体只是把它**扩写成 500 字**。
- **无强度分级**：不管学生是 40 分还是 90 分，评语结构（五要素）与长度（≥500 字）**恒定**。
- **无渐退**：8 周内共发 2 次评语（测试 2 后、测试 3 后），**两次的机制完全相同**，不随学生水平/轮次变化。
- **无效果回执**：评语发出后，学生是否做了推荐习题、做了效果如何——**无任何回收路径**。

> ⚠️ **对用户"渐退式支架"的判定**：
> **本篇在支架维度上是纯空白，用户的"渐退式支架"相对本篇是真差异化**。
> 但要注意论证方式：不能说"吴晓彤没做支架所以我做了很创新"——她的产品定位（教师备课工具）本就不需要支架。
> **正确的引用方式是**：用它证明"**面向教师的助教路线在结构上不可能产生支架渐退**"——
> 因为支架渐退要求"感知学生状态 → 调整支持强度 → 观察效果 → 再调整"，
> 而这条链的第一环（学生状态）在本篇里是**教师手打的一句话**，最后一环（效果观察）**根本不存在**。
> **这为"必须把学生纳入人机回路"提供了结构性论证，而不只是价值主张。**

同时，**评语五要素输出契约本身是可抄的**（见 §六引用点 Q7）——它给了"评价生成"职能一个具体的 schema。

**人机协同教育理论**（p.28–30 / PDF 39–41）：
- 演进三层次：**人机交互 → 人机融合 → 人机共创**（p.28 / PDF 39）

#### 3.4.2 实际权责（从实现与访谈还原）

| 主体 | 实际做什么 | 证据 |
|---|---|---|
| **教师** | 提需求（打 topic）→ **审核 → 修改 → 决定是否使用** → 决定给不给学生 | 教师A"每次生成的题目我都必须**严格把关**，才敢让学生进行测试"（p.88 / PDF 99）；教师B"其模板还是不错的，可以直接引用，**内容方面我在修改一下即可**"（p.86 / PDF 97） |
| **机（智能体）** | 生成**候选产出物**（教案/卷子/评语/导入/讲解稿） | 六技能 |
| **学生** | **只接收教师转交的评语**（且是纸面），做卷子 | 实验组"除此之外，还会**收到助教智能体生成的教师评语**"（p.81 / PDF 92） |

**关键事实：学生从头到尾没有接触过智能体**。
学生的角色是"被评价对象 + 数据来源"，不是交互主体。
p.81 / PDF 92 的实验操作是：对照组拿"含排名和分数变化的成绩单 + 教师口头整体反馈"，
实验组**多拿一份 AI 生成的评语**。**干预 = 多一张纸**。

> ⚠️ **这直接决定了本篇的因果解释力**：
> 实验组多得到的是"**一份 500 字的个性化书面反馈**"，
> 对照组得到的是"**排名分数条 + 全班口头点评**"。
> 两组的差异**至少包含三个混淆变量**：(a) 是否有个性化书面反馈；(b) 反馈的**篇幅**（500 字 vs 一个排名）；
> (c) 反馈里**是否有推荐习题**。
> 而学生自己在访谈中说的恰恰是第三个：p.82 / PDF 93——
> "许多学生反映，相较于对知识点掌握情况的诊断，他们**更关注评语中给出的题目练习**"。
>
> → **所以 SRL 的提升，最可能的解释是"多给了一份带练习推荐的详细书面反馈"，
> 与"这份反馈是 AI 生成的"没有必然关系**。
> **本研究缺一个关键对照组：教师人工撰写的同等篇幅个性化评语**。
> 没有这个组，就无法把"AI 生成"的效应从"个性化书面反馈"的效应中分离出来。
> **这是本篇准实验设计最根本的缺陷，第一波完全没有指出。**

## 九、苏格拉底式追问链

### 追问链 A：如果它的 DV 是 SRL 而不是 CT，那用户还有什么理由引它？

**Q1｜第一波把它列为"CT 维度挂靠外部框架"的证据，删掉之后，它还剩什么？**
剩的是**架构与设计层**——六技能切法、单 Agent 自述、三层记忆、四段式提示词、评语五要素、
以及"主动放弃跨会话记忆"这个工程决策。**这些都不依赖它的构念是 CT 还是 SRL。**

**Q2｜但架构层的东西，柴兴祝（11）和刘伯成（18）不是讲得更系统吗？为什么还要它？**
因为那两篇是**理论文/技术文**，而本篇是**唯一一篇把完整提示词全文印出来的**（表 4-2 至 4-7，共 11 页）。
用户要做 CX 的 `ai.py` persona 设计，需要的不是"应该有角色和限制"这种话，
而是"别人的限制段具体写了什么"。**本篇提供的是可对照的实物，不是构念。**

**Q3｜那"它测的是 SRL"这件事，对用户还有别的用处吗？**
有，而且是反向的用处：**它证明了一条被用户忽略的因果路径**——
`AI 生成的个性化书面反馈 → SRL 提升 → 成绩提升`。
用户的模型里，"评价生成"职能的下游效应写的是"素养画像"，
但本篇（哪怕方法有瑕疵）提示：**评价的第一顺位效应可能是 SRL（目标设定/时间管理/寻求帮助），而不是 CT 本身**。
学生自己说的也是这个——"**更关注评语中给出的题目练习**"（p.82 / PDF 93），
即他们把评语当成**行动指引**而非**认知诊断**。

**Q4｜那用户是不是也该测 SRL？**
不必增测，但应**在讨论章承认**：CT 干预的近端效应很可能先落在学习行为调节上，
再传导到 CT。若用户的 CT 前后测增益不显著，**这是一个可辩护的解释路径**，而不是失败。
**追问 A 的收敛**：06 从"CT 测评先例"降级为两样东西——**(a) 提示词与架构的实物样本；(b) 一条"评价→SRL→成绩"的替代因果路径假设。**

### 追问链 B：为什么"面向教师"必然导致"无支架、无渐退"？这是偶然还是结构？

**Q1｜会不会只是作者没想到做支架？**
不是。支架渐退的最小闭环是 `感知学生状态 → 给出强度 S 的支持 → 观察效果 → 调整 S`。
本篇的第一环是**教师手打的一句话**（`"李明，高二，60分，理解不清"`，p.76 / PDF 87），
最后一环**根本不存在**（评语发出后无任何回收）。
**四环里坏了两环，而且坏的是首尾两环。**

**Q2｜那如果给它加一个学生答题数据接口，是不是就能做支架了？**
仍然不能，因为**智能体不与学生交互**。它输出的是一份 500 字的纸面评语，
支持强度 S 一旦印出来就固定了。**渐退需要在交互中发生，纸面反馈没有交互。**
→ 所以这是**结构性的，不是实现疏漏**。

**Q3｜那反过来问：用户的 CX 把学生放进回路了，是不是就自动有渐退了？**
**不是。** 这是本追问链最该警惕的地方。
CX 现在有 `ai.py` 双 persona（driver/navigator），学生确实在回路里，
但**只要 persona 的强度是常量、不随学生状态变化，它就和吴晓彤的 500 字评语同构**——
只不过一个是纸、一个是屏。
**"在回路里"是必要条件，不是充分条件。**

**Q4｜那渐退的充分条件是什么？至少要有哪几样？**
从本篇的四环反推，至少要三样，且**每一样都必须落到数据结构，不能只在 prompt 里**：
1. **一个可读的学生状态量**（CX 已有雏形：`ct.py` 六维分 —— 但必须是**近期的、按维度的**，不是总分）；
2. **一个可调的支持强度参数**（CX 缺）——persona 里必须有一个由状态量决定的档位变量
   （如 `hint_level ∈ {直接给结构, 给提示, 只反问, 沉默}`），而不是一句固定的"不写完整代码"；
3. **一个效果回执**（CX 缺）——推送支架后，学生在接下来的 N 分钟/N 次运行里是否自主前进，
   这个回执必须写回状态量，形成闭环。

**Q5｜第三样（效果回执）会不会太难？吴晓彤就是因为难才没做的？**
她没做不是因为难，是因为**她的架构里没有"接下来"**——评语是终点。
CX 不同：CX 是**在线 IDE + 结对会话**，"接下来"天然存在（下一次 run、下一次 error、下一次 role_switch）。
**这恰恰是 CX 相对本篇最大的结构优势，且几乎零成本**——数据本来就在流，只是没被当作回执消费。

**追问 B 的收敛**：**"渐退式支架"不能作为口号写进用户模型，必须落成三件具体的东西：
`状态量（已有）+ 强度档位参数（待建，在 ai.py）+ 效果回执（待建，把已有事件流当回执消费）`。
本篇提供的证明是：缺任意一件，渐退就退化为"固定强度的一次性支持"，与一张纸没有区别。**

### 追问链 C：它的"六技能六工作流"和用户的"四职能"，到底哪种切法对？

**Q1｜本篇按产出物切（教案/单元计划/试卷/导入/评语/讲解），坏处是什么？**
六条管线**零通信**（§3.2.3）：出卷的不知道教案里的重难点，写评语的不知道卷子考了什么。
每次都要教师**手工重述上下文**，这也是它必须"每技能开新对话"的另一半原因。

**Q2｜用户按职能切（学情感知/支架推送/学习分析/评价生成），就一定更好吗？**
**不必然。** 第二波已经指出：用户的四职能之间**同样没有数据契约**。
如果四职能只是"四个各自调 LLM 的端点"，那它与六技能的差别只是"名字更教育学"，
**结构上是同一个东西：并列的、无状态的、彼此不通信的管线。**

**Q3｜那怎么判断一种切法是真的"有结构"？**
判据只有一个：**能不能写出模块间的输入输出 schema，且下游模块的输入确实是上游的输出。**
按这个判据检验：
- 吴晓彤六技能：输入统一是 `topic: string`（+ 可选 file），**输出互不消费** → **无结构**。
- 用户四职能：`学情感知` 的输出应当就是 `支架推送` 的输入；
  `支架推送` 的效果回执应当就是 `学习分析` 的输入；
  `学习分析` 的产物应当就是 `评价生成` 的输入。
  **如果这三条能写出 schema 并在代码里成立，四职能就是真结构；写不出，就是六技能换了个名字。**

**Q4｜那具体该定义哪些字段？（本轮尝试给一版，供用户后续验证）**
```
学情感知  →  LearnerState { user_id, session_id, ts,
                            ct_dim_scores{分解,抽象,算法,调试},   // 各带 evidence[]
                            stuck_signal{error_streak, idle_ms, repeat_run_n},
                            role_now: driver|observer }
支架推送  ←  LearnerState
          →  ScaffoldEvent { scaffold_id, dim_targeted, hint_level, prompt_used, ts }
效果回执  →  ScaffoldOutcome { scaffold_id, resolved: bool, latency_ms,
                              next_actions[], self_progress: bool }   // ★ 当前 CX 缺
学习分析  ←  LearnerState[] + ScaffoldEvent[] + ScaffoldOutcome[]
          →  LearnerProfile { 跨会话画像，按 CT 四要素，带时间序列 }   // ★ 当前 CX 缺（持久层）
评价生成  ←  LearnerProfile + 作品/测评
          →  Comment { 变化趋势, 知识点诊断, CT四要素诊断, 建议, 下一步任务 }  // 结构抄 Q7
```
**注意最后一行**：吴晓彤的评语五要素（Q7）**正好可以填进 `Comment` 的 schema**，
但她的输入是"教师手打一句话"，用户的输入是 `LearnerProfile` ——
**输出契约可以照抄，输入契约必须换掉，这是全部差别所在。**

**Q5｜那两个标 ★ 的缺口（效果回执 / 画像持久层），哪个更急？**
**效果回执更急，且更便宜。** 理由：
- 画像持久层需要先有东西可存；而"存什么"取决于回执告诉我们哪些支架有用。
- 回执可以直接复用 CX 已有的事件流（run/error/fix/role_switch），**不需要新采集**，只需要新的时间窗归因逻辑。
- 且回执是**唯一能让支架强度学会自我调整**的信号源——没有它，`hint_level` 只能由人拍脑袋定死。

**追问 C 的收敛**：**四职能优于六技能的唯一理由，是"职能之间天然有先后与依赖，因而可以定义契约"。
这个优势必须靠写出 schema 来兑现，否则不成立。
且兑现的顺序应是：`效果回执（便宜、复用已有事件流）→ 画像持久层（贵，但由回执决定存什么）→ 强度档位参数（消费前两者）`。**

### 追问链 D：它的准实验"缺一个对照组"，那用户的实验该设几个组？

**Q1｜本篇缺的到底是哪个组？**
它比的是 `AI 评语 + 成绩单` vs `成绩单 + 口头点评`。
两组差了三样东西：**是否个性化书面反馈 / 反馈篇幅（500 字 vs 一行）/ 是否含推荐习题**。
缺的对照组是：**教师人工撰写的同等篇幅个性化评语**。
没有它，"AI 生成"的效应就与"给了一份详细书面反馈"的效应**完全混淆**。

**Q2｜这对用户意味着什么？用户的对照组该是什么？**
用户的干预是"结对编程智能体"。若对照组是"无智能体的普通结对编程"，
那实验组多的东西同样是**一堆**：AI 的提示、AI 的即时性、AI 带来的额外交互量、
甚至只是"有个东西一直在说话"的存在感。
→ **同样的混淆会原样重演。**

**Q3｜那用户该怎么设？**
最有信息量的对照不是"有 vs 无"，而是**"同量不同质"**：
- 实验组：`ai_navigator`（苏格拉底式、拒绝写完整代码、按状态调强度）
- 对照组：`ai_driver` 或**固定强度的通用 AI 助手**（交互量、响应频率、篇幅尽量对齐）
→ 这样两组的"AI 存在感"和"交互量"被控住，差异**只剩 persona 策略**，
才能把"苏格拉底式 + 渐退"的效应分离出来。
**而这恰好是 CX 已经有的（`ai.py` 双 persona），几乎零额外成本。**

**Q4｜但双 persona 对照会不会有伦理问题——给对照组一个"更差"的 AI？**
不会更差，`ai_driver` 对完成任务其实**更高效**（它直接写代码）。
两组学生**都得到帮助**，只是帮助方式不同。
这比"对照组什么都没有"在伦理上**更干净**，也比本篇"对照组只拿一张分数条"更可辩护。

**Q5｜那本篇的准实验还有别的可借鉴之处吗？**
有一条**流程上的**：它做了 **`前测 → 干预中的两次形成性测试（测试2/测试3） → 后测`**，
即在干预过程中插了两次测量，而不是只有首尾两点。
**这个"多点测量"的形状值得学**（可以看增益轨迹，而不只是首尾差）。
但它把这三次测量的卷子做成了互不等值还复用原题的三张卷（§2.4），
**形状对了，实现毁了**。
→ 用户若做多点测量，**必须同蓝图出多套等值卷**，且**绝不复用题目**。

**追问 D 的收敛**：**三条可执行结论——
(1) 对照组用 `ai_driver`（同量不同质），而非"无 AI"；
(2) 保留"前测 + 过程中两次 + 后测"的多点测量形状；
(3) 多点测量必须同蓝图等值多卷、零题目复用——本篇在这一点上是最直接的反面教材。**

### 追问链 E：一篇 2025 年的论文，为什么会用 2013 年的 Word2Vec？这暴露了什么共性风险？

**Q1｜先确认这是不是我读错了。**
不是。p.58 / PDF 69 有整节"（三）选择词嵌入模型（Word2Vec）"、有图 4-12"Word2Vec 训练参数设置"、
有具体参数（window 5–10 / vector_size 100–300 / min_count 5–10）、有词类比评估。
摘要（PDF 4）也把"**词嵌入技术**"列为核心技术贡献之一。

**Q2｜但它用的是 Coze 零代码平台，能自训 Word2Vec 吗？**
不能。Coze 的知识库向量化由平台内置 embedding 完成，用户侧只能配"分段策略/搜索策略/召回量/匹配度"
（这些参数本篇在 p.61 / PDF 72 也确实写了）。
**"训练参数设置"那一节与它自己上一节的平台描述互斥。**

**Q3｜那这一节是从哪来的？**
最可能是**从 NLP 教科书/综述里搬来的通用描述**，用来填"技术基础"的篇幅，
未与实际开发对齐。词类比例子"数据库−存储设备+显示器≈信息系统"**语义上不成立**，
是照着 `king−man+woman≈queen` 仿写的，**进一步佐证这是纸面填充而非实操记录**。

**Q4｜这对用户有什么直接警示？**
两条，都很实在：
1. **"技术基础章"是学位论文最容易脱离实现的地方**。用户写 CX 的技术章时，
   凡是写进去的技术，**必须能在 `server/app/*.py` 里指出对应行**；
   指不出的，宁可不写。审稿人只要问一句"这个 Word2Vec 在哪训练的"，整章可信度就崩。
2. **零代码/低代码平台会掏空技术贡献**。本篇的真实技术工作量是
   "配了六个 Coze 工作流 + 写了六组提示词 + 传了一批文档"，
   这本身是合理的工程量，但**撑不起"基于词嵌入技术开发"这样的表述**，
   于是就出现了填充。
   → 用户的 CX 是**自建 FastAPI + 自写状态机 + 自定义 ct-rules**，技术贡献是真实的，
   **反而更该老实写具体做了什么**，不需要借术语壮胆。

**Q5｜反过来问：本篇有没有被低估的真技术贡献？**
有一个：**六组工作流提示词的完整披露**（表 4-2 至 4-7，11 页）。
在这个领域，绝大多数论文只给架构图不给提示词。
**它给了，且给全了**——这是它最扎实、最可复现、最该被引用的部分，
偏偏摘要里一个字没提。**它自己也没意识到自己最值钱的东西是什么。**

**追问 E 的收敛**：**两条写作纪律——
(1) 技术基础章的每一项技术，必须能指到代码行，指不到就删；
(2) 最值钱的往往是"完整披露的实物"（提示词全文、schema、参数表），而不是术语。
用户应把 CX 的 persona 全文、`ct-rules/v3` 规则表、`study.py` 状态机转移表**完整附录化**——
这是本篇无意中示范的最佳实践（尽管它自己没当回事）。**

### 追问收敛：本轮问出来的、原研读没有的五个结论

1. **06 从"CT 评价先例"重新定位为"二元路线的天花板样本 + 提示词实物库"**——
   它对用户的价值全部在第二波的问题域，第一波的引用位置需要系统性修正（5 处删改）。
2. **"信息论意义上的天花板"**：机的输出信息量不可能超过输入；
   本篇的输入是教师手打的一句话，所以它的"个性化"必然停在语气层。
   **这为"必须把学生纳入回路"提供了结构性论证，而不是价值主张。**
3. **跨会话记忆被主动放弃的工程动机是"长上下文 → 意图识别劣化 + 幻觉"**——
   用户的画像持久层必须是**结构化按需检索的字段**，而不是"把历史粘回 prompt"，
   否则会撞同一堵墙并做同样的选择。
4. **渐退式支架的三件套**：`状态量（CX 已有）+ 强度档位参数（待建）+ 效果回执（待建，可复用已有事件流）`；
   **效果回执应优先做，因为它最便宜且决定了画像该存什么。**
5. **实验设计三条**：对照组用 `ai_driver`（同量不同质）而非"无 AI"；保留多点测量形状；
   多点测量必须同蓝图等值多卷、零题目复用。
