## 〇、三轮自问的结论（先给答案，后给证据）

**Q1：三个独特性还剩几个是真的？——严格说，剩 0.5 个，但可以重组出 1 个更硬的。**
- 「测评回灌教学」**已被做过，且有人做得更完整**（ClassAid, CHI 2026）。
- 「支架渐退可测量」**需大幅修正**：既有先例（Kazemitabaar, Koli 2023），且理论上已被 Synergistic Fading Model 判为过时逻辑，度量对象也被指错（该测学生 uptake，而非 AI 给了多少）。
- 「轮次同构迭代」**没找到对照物，但也没找到任何外部理论支撑**——它现在不是独特性，是一个未经检验的设计假设。
- **真正没被做过的是三者的交集**：K12 共机结对 + 教师锚点注入 AI + 过程性 CT 六维 + 撤 AI 后独立表现。建议把独特性主张从「三个机制」重写为「一条因果链」。

**Q2：有人做完了吗？——没有人做完整条链，但有四家各做完了 CX 的一块，且都比 CX 那一块做得硬。**
ClassAid（教师实时调支架档位 + AI 看板）、Codio（同步结对 driver/navigator + 控制权协商）、CodeHelp（输出侧机器强制改写）、Tutor CoPilot（RCT 级专家话术注入教师）。CX 的贡献必须从「发明了 X」改为「把 X1..X4 集成并首次连到 CT 过程构念与撤 AI 后表现」。

**Q3：CX 有没有在做外部证据显示是错的事？——有，至少 6 条，其中 2 条会直接影响结论有效性。**
最严重两条：① hop 若按轮次触发即为「按时间表淡出」，与自适应淡出定义相悖，且与专业知识逆转效应元分析的非对称结论冲突；② hop 只测「AI 给多少」，而 arXiv 2606.15766（9,490 条对话）证明支架强度与学生 uptake **相关弱且跨数据集不一致**——只报 hop 下降而不报 uptake，结论可能是空的。

## 二、CX 三个独特性的外部检验结论

### 独特性①「轮次同构迭代」（R1 能跑 / R2 跑对 / R3 跑好 + round_snapshot 冻结）
**结论：仍成立，但它现在不是独特性，是一个未被检验的设计假设。**
- 我用「make it work / make it right / iterative rounds + 评价量规」做定向检索，**未找到同构的研究框架或产品**（检索层，结果为通用编程量规，无对应物）。这一点上游扫描的判断成立。
- 但「找不到对照物」有两种解释：真空白，或**没人认为它值得做**。目前 CX 拿不出任何外部学理把 R1/R2/R3 锚住——不像六维可以回溯 Brennan & Resnick。
- **致命问题**：R1/R2/R3 目前只有设计假设，没有实证。教育过程挖掘（Frontiers in Education 2025 综述 / arXiv 2409.09204）已提供现成的 conformance checking 方法，可以直接检验「学生真实轨迹是否符合这个状态机」。**不做这一步，答辩第一问就会问「这是你设计的还是你发现的」。**
- **重新定位建议**：不要把它写成独特性，写成**可证伪的过程模型假设**，并给出拟合度数字。假设被部分证伪也是好结果（说明真实学习轨迹不是线性三段）。

### 独特性②「支架渐退可测量（hop）」
**结论：需大幅修正——先例存在、理论已被超越、度量对象错位。三处都要改。**
1. **先例存在**：Kazemitabaar Koli Calling 2023 已做 AI Single Prompt / Hybrid / Step-by-Step 路径占比并跑后测回归（全部趋势不显著，n 小）。CX 的差异是**服务端自动埋点、学生不可伪造、带 round_index/room_id、且刻意不进六维公式**——这是可辩护的方法学差异，但必须写成「差异」而非「首创」。
2. **理论已被超越**：Synergistic Fading Model（2025）明确批评「AI 随能力提升被逐步撤走」的 tool-fading 逻辑，主张 guidance-fading + 永久保留分析型工具。CX 的 hop 正是被点名的那种逻辑。**CX 需要在论文里主动回应：初中 CT 形成期与职业实践语境不同，tool-fading 在此仍适用——或者接受并改造。**
3. **度量对象错位（最严重）**：arXiv 2606.15766 的 9,490 条对话证明，**支架强度与学生 uptake 相关弱且不一致**。hop 测的是「AI 追问了几轮」（供给侧），学生完全可以照收不误却零投入。**只报 hop 下降 = 报了一个可能与学习无关的量。**
   - 必须配一个需求侧量：学生对追问的**响应质量**（是否在下一轮修改了代码、是否回答了追问、话轮长度分箱），以及 Ma 等（arXiv 2511.04144）的 **P-M-E 循环完整度**。
4. **另一处硬伤**（承接扫描但我确认其严重性）：Sheese 2024 发现**成绩更好的学生用得更多**。因此 hop 下降既可能是渐退成功，也可能是弱生放弃提问。**hop 必须与能力变量交叉，单独解释一律无效。**

**修正后仍成立的部分**：「服务端全量、不可伪造、与因变量正交隔离的支架强度信号」——这一条我没找到对照物，可以主张。

### 独特性③「测评回灌教学」
**结论：已被做过，且 ClassAid 做得更完整。CX 必须换一个更窄、但真正空白的主张。**
- ClassAid（CHI 2026）已实现：教师**实时**在四档间切换 AI 支架强度（含 silent），AI 看板可视化师生-AI 交互，真实课堂部署 + 教育者访谈。这基本覆盖了 CX 的「支架档位策略 v1 + 教师确认制 + 教师端回灌」，且比 CX 的「只建议不写库」更进一步（教师直接改 Agent 行为）。
- Tutor CoPilot 已用 RCT 证明「专家策略注入教学者」有效；Ozaria 已把形成性评价做成教师四件套工作流；VizGroup 已做实时协作编程分析看板。
- **CX 剩下的、我确实没找到对照物的部分**：回灌所依据的证据是**过程性 CT 构念（六维）**，而非任务完成度、错误频次或对话分类。ClassAid 回灌的是「学生卡在哪」，CX 回灌的是「学生的抽象/分解维度弱」。**这是一个真实但很窄的差异，必须精确表述，不能笼统说「我们做了测评回灌」。**

### 补充：一个被低估的、真正的第一独特性
**「K12 共机结对（服务端权威 driver/observer）+ 对同伴可见的 AI + 过程性 CT 六维」这个三元交集，我在本轮检索中未找到任何对照物。**
- Codio 有同步结对但面向高校、无 CT 构念、无 AI 教学契约；
- ClassAid 有教师-AI-学生三方但**是一人一机**，无同伴维度；
- HHAI-Triadic（2601.12134）证明了「AI 使用对同伴可见」激活社会共享调节，但 N=20、非 K12、是实验室研究不是运行系统。
**建议把这一条提为对外表达的第一独特性**，理由：最容易一眼看懂、最难被抄、且有 HHAI 的理论背书。同时诚实注明 Codio 的存在（否则「国内外无同步结对」这句话会被一枪打掉）。

## 三、理论与技术路线上 CX 该跟进的（按收益/代价比排序）

**P0 — 不做会导致结论无效**

1. **后测必须含「无 AI 独立完成」任务 + 一周后延迟保持测**｜代价：小（设计与课时协调）｜依据：PNAS 2025 的因变量正是撤 AI 后的独立考试；Kazemitabaar CHI 2023 的关键结果在一周保持测。**只报练习期过程指标，等于没有回答「撤走会不会垮」。**
2. **给 hop 配一个学生侧 uptake 量**｜代价：小（重切现有 ai_reply_log + 代码事件，不需新埋点）｜依据：arXiv 2606.15766。至少三个布尔：追问后学生是否改了代码 / 是否作答 / 话轮字符数分箱。
3. **hop 触发条件自查并改为「指标达标驱动 + 轮次上限兜底」，且渐退非对称（加快撤慢）**｜代价：改参数与文档，近零｜依据：自适应淡出定义 + Tetzlaff 元分析（撤支架收益弱、年幼学生证据不清）。
4. **对 round 级事件做 process discovery + conformance checking（pm4py，离线）**｜代价：小（离线脚本）｜收益：把 R1/R2/R3 从设计假设变成实证事实，直接堵住答辩必问项。
5. **样本量估算与分析计划预注册（含先备水平为预设调节变量）**｜代价：小｜依据：Koli 2023 全部趋势不显著；CHI 2023 显著效应就在调节项上。

**P1 — 显著提升论文与产品硬度**

6. **输出侧「多候选打分取优 + 含代码则改写」，改写前后分类都落库**｜代价：中（prompt 流水线，成本量级参考 CodeHelp 50 人一学期 <$10）｜收益：改写前 D 类 = 自变量保真度真值，改写后 = 学生实际收到的。与既有纪律零冲突。
7. **按功能入口做结构性约束**（「求助修 bug」与「求助写实现」拆入口，前者结构上不返回可运行代码）｜代价：中（前端 + prompt）｜依据：CodeAid 用产品结构而非 prompt 实现「不给码」，比继续加规则收益确定。
8. **Parsons / faded-code 题型作为支架第二通道**｜代价：中（题型 + 题库）｜收益：支架强度天然可离散量化（干扰项数、留空比例），比对话档位好度量得多，且与 cog_load 交叉验证。
9. **引入 Bebras + ACE 作为外部效标**（ACE 21 题 arXiv 附录全公开、9-15 岁、聚合效度 r=0.41）｜代价：中（授权核对 + 中文化 + 小样本项目分析）｜收益：一次性解决「六维只是测了平台熟练度」的核心质疑，并给出 r≈0.4 的期望值锚。
10. **ProgSnap2 导出器**｜代价：小（一张宽表 + 快照目录，标注 v8 Beta）｜收益：数据集符合 CS 教育界公认格式，可复现性质疑基本解除。优先级高于 xAPI。
11. **六维溯源映射表**（Brennan&Resnick / Weintrop / ISTE / Dr.Scratch 七维 / 课标计算思维）｜代价：纯写作，零工程｜收益：极高。**不改六维定义**，只补理论出处。
12. **「自评-实测落差」度量 Progression / illusion of competence**｜代价：极小（轮末 1-5 自评一题）｜依据：Prather ICER 2024。

**P2 — 值得做但可延后**

13. obs_window 的 Rasch/项目分析（N 不足就只做 item-total 相关）｜依据：HS-CTOP 2026 已把这条路走通。
14. epistemic debt 探针（轮末 1-2 道针对本轮代码的即时理解题）。
15. goal_anchor 双向化：增加「向教师实时建议提问话术」通道（Tutor CoPilot 移植），并按教师经验分层看效应。
16. 用 LLM 模拟学生生成红队回归语料（SimClass 思路），把人工红队变成 CI。
17. AI 生成内容显式标识 + 「本轮代码中 AI 生成行占比」（合规与研究指标一举两得）。

**明确不做（并写进 DECISIONS，写出来比不提更显成熟）**

## 五、第二轮要深挖的问题（越具体越好）

**A. 直接决定贡献声明的（最高优先）**

1. **ClassAid（CHI 2026）全文精读**：它的四档（technical/heuristic/automatic/silent）是**教师手动切**还是有推荐逻辑？看板展示的是原始对话还是分类？有没有做学习结果测量（还是只有可用性评估）？**关键判断点**：如果 ClassAid 只做了可用性而没做学习结果，CX 的「回灌 → CT 增益」因果链仍是空白；如果它做了，CX 必须换主张。
2. **Codio 的 driver/observer 权限是服务端强制还是客户端约定？** 有无角色时长/贡献统计？是否有任何 K-12 客户案例？**判断点**：若 Codio 也是服务端强制，CX 的「服务端权威角色」这半句就不能说了，只剩「角色量与 CT 构念绑定」。
3. **把「K12 + 同步共机结对 + AI 教学契约 + 过程CT」这个四元交集做一次穷尽式反证检索**（中英双语 + ACM DL/IEEE/arXiv 站内检索，而非通用搜索），目标是拿到一句可写进论文的、带核查日期的普查结论。本轮我只做了通用检索，强度不够。

**B. 度量有效性（决定数据能不能用）**

4. **arXiv 2606.15766 全文**：它用什么指标算「scaffolding level」与「student uptake」？这两个操作化能否直接移植成 CX 的 hop 配对量？其 CoMTA/StemChat/RECIPE4U 三个真实产品的 uptake 数值是多少（作为 CX 的基准线）？
5. **自查 ct-rules/v3 中 hop 的触发条件**：是轮次驱动还是达标驱动？（这是代码级自查，不是检索，但必须在第二轮前完成，否则 P0-3 无法定案。）
6. **round_snapshot 已有数据的分布诊断**：六维在 R3 阶段是否触顶（天花板效应）？按性别 / 有无编程基础 / 打字速度分组的六维分布与效标相关是否存在系统性偏倚？（cCTt 已示范这是必查项，评审几乎必问。）
7. **ACE 21 题与 Bebras 题库的授权条款究竟允许什么**：能否中文化？能否用于学位论文数据收集？能否公开改编版？（这条不查清楚，P1-9 无法启动。）

**C. 理论辩护（决定引言与讨论怎么写）**

8. **Synergistic Fading Model 全文**：它对 tool-fading 的批评是否适用于 K12 CT 形成期？若适用，CX 是改造 hop（改为 guidance-fading）还是限定适用边界？两条路的论文代价分别是多少？
9. **《Democratization of CT》（Software 2025）全文**：它主张 LLM 使 CT 与编程解耦。CX 的构念效度辩护（初中阶段编程仍是 CT 外化的主要载体）需要找到支持性的发展心理学或 CT 学段文献，目前只有推理没有引证。
10. **教育过程挖掘的两篇全文（Springer CT 日志 scoping review、ILE 2025 过程导向 CT + ML）**：它们指出的「研究空白」是否与 CX 的贡献声明重叠或冲突？本轮因 403/IdP 未取到全文，属投稿前必要尽职调查。

**D. 落地与商业（决定进校能不能成）**

11. **「教育智能体择优上线国家平台」的申报口径**（教科信〔2026〕1号第十一部分已确认存在，moe.gov.cn 官方全文）：谁受理？材料清单？是否要求先入省级白名单？——这可能是硕士课题之外最大的落地出口。
12. **属地教育行政部门的两个问题当面问清**：① Web 形态教育平台是否需要提供者备案；② 本地白名单的申报口径与材料清单。这两条不能靠检索，只能靠问。
13. **成本测算**：AI 调用 + 沙箱执行的单生单学期成本（对标 CodeHelp 公开的 50 人一学期 <$10 量级）。Replit 关停的官方理由就是算力与维护不可持续，CX 体量更小。

**E. 需要正面处理的反面证据（决定局限性一节）**

14. **《CAI 2026 系统综述》全文**：文献明确点名 GenAI「扰乱包括结对编程在内的协作学习实践」。CX 必须把「AI 是否挤压同伴互动」设为**预注册的检验假设**，并用 obs_window 席位对齐/驾驶三数检验。同时找到 Int J STEM Educ 2025 三臂研究的具体效应量作为对照基准。
15. **「分数不下发学生」这条纪律的代价必须量化并写出来**：教育测量文献普遍支持学生获取自身过程数据对自我调节与动机的正向作用（检索层：NWEA、Edutopia 等实践证据；需补一篇同行评议的自我调节学习证据）。CX 用「牺牲学生自我调节收益」换取「过程指标不被策略性刷分污染」——这是一个**取舍**，不是纯正确。论文里当作纯正确写，会被有教学背景的评审直接指出。

**一句话终审意见**：CX 的三个独特性有两个站不住了，但拆掉之后露出来的东西更结实——不是任何单一机制，而是「K12 共机结对 + 教师锚点 + 过程性 CT + 撤 AI 后独立表现」这条**没有任何人串起来过的因果链**。第二轮的全部力气应该花在把这条链的每一环连上（尤其是撤 AI 后的独立表现，目前完全缺失），而不是继续给 hop 加功能。
