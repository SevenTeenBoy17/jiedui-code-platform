## 🔴 二、要改你图上字的四条（按致命度）

**【1｜最致命】三轮的轮名与"螺旋"宣称自相矛盾。**
「第一轮·分解建模 / 第二轮·算法实现 / 第三轮·综合优化」与谢鑫表 2「需求分析+方案设计 / 集成开发 / 测试改进」**逐条同义**。
你用来批评谢鑫的那把刀（阶段化≠迭代化、CT 要素被切开绑死在不同阶段），砍在自己的轮名上同样见血。
→ **改法**：轮次区分维度从 CT 要素改为**制品完成度层级**（**R1 能跑 / R2 跑对 / R3 跑好**），每轮完整走四要素，轮间差异是分解粒度、抽象层级、调试判据严格度；CT 要素降为**每轮重心标注**。
第三轮"综合优化"建议改名「**调试迁移**」（现名与 CT 要素"调试评估"不对齐，会被误读为第三轮才开始调试）。

**【2】四职能之间没有数据契约 —— 你批评朱婷婷的话原样适用于自己。**
图上四职能彼此**一条线都没画**；而 CX 现状印证了它：`ai.py` 的 scaffold 不读 `ct.py` 输出、`insights.py` 不消费 `ai.py` 对话。
→ 补一张四职能输入/输出/受众/时间粒度契约表（综合 §4.5 已写好，可直接贴进系统实现章）。
→ **口径建议**：契约写清后会发现这是"一条 LLM 工作流的四阶段"，建议全文称「**四职能模块/四职能架构**」，慎用"多智能体"（否则被问"自主性、规划在哪"）。

**【3】缺教师→智能体的控制输入箭头。**
图上机→师只有画像/诊断，师→机没有。**而 CX 实物里教师已能下发苏格拉底锁、维护问题链——落地物比模式图更完整，这是倒挂。**
→ 补一条"采纳即回流"实线，并把"数据回流"一根箭头拆成 **L1/L2/L3 三根并标注权限**（档位机器写 / 任务链教师确认 / 问题链教师手改），"人机权责边界"就从口号变成图上可数的三条边。

**【4】学生侧没有第二个学生 —— 漏掉的正是 CX 最独有的资产。**
学生侧是单一红色主体，而 CX 核心机制是结对。检验问题：**支架档位是算给个人的还是算给这一对的？**
→ 一旦回答就产出最有价值的新命题：**角色互换本身是一种支架调节手段**（弱者当驾驶员=加支架，强者当驾驶员=对弱者撤支架）；3 轮 × 每轮 ≥1 次互换 = **6 个档位判定点**，顺带化解"三轮观测点太少"的质疑。

## 💡 三、三个应该提到模式图上的原创点（11 篇全无）

| 原创点 | 为什么是原创 |
|---|---|
| **① 支架来源迁移（AI → 同伴 → 自我）** | 11 篇的支架全是**单人学习者模型**（李昊东 p.63 明确自陈仅支持单人）。CX 三元结构让支架**转移而非撤销**——撤的不是人机协同，是协同中机器的答案供给。**这也是回应"AI 时代为什么还要撤 AI"（谢鑫 p.51）的唯一钥匙** |
| **② 角色轮换 × 支架渐退二维矩阵** | 无一篇处理"两个学习者共享一个智能体会话"；且 CX 有**服务端权威角色**（`collab.py`），"谁在驾驶"是系统已知事实——别人没有这个前提 |
| **③ 输出契约作为"助学不代学"的机制符号** | 11 篇里方海光是规范性断言、谢鑫是过程计分，**没有一篇做输出侧的可机器校验约束**。建议图上智能体框内加一格「输出契约/约束闸门」，否则模式图无法回答"凭什么智能体不会代做" |

## 🧱 四、支架渐退：这是你最大的缺口，文献里也几乎没有

**11 篇里没有一篇有"同一学习者随轮次递减"的机制**（马金帅是横向分级、谢鑫吴君方向相反）。综合给出了可实现的操作定义：

**四条正交轴分离**（回应"AI 时代不该撤支架"的唯一硬答复）：
- **A 代劳度/答案供给 → 递减**（CT 形成期，代码是能力的外显证据，给完整解即销毁证据链）
- **B 信息通道/媒体丰富度 → 可增**（任务变复杂，通道要更宽）
- **C 学生对智能体的控制权 → 递增**（AI 素养；K12 降级为"受约束的选择权"）
- **D 语法/API 层帮助 → 恒常开放**（"不代的是思考，不是打字"）

> 一句可写进论文的话：**智能体给出的答案越来越少，学生对智能体的支配越来越强，信息通道不减反增，基础工具始终在手。**

**从"输入侧祈使"到"输出侧契约"**（全篇最关键的一步转换）：
李昊东/刘伯成能用**次数配额**是因为规则引擎时代每次"帮助"信息量恒定；**LLM 输出信息量连续可变——一次"提示"若顺手写全伪代码就等于一次示例，配额对 LLM 无效**。
正确形态是 `scaffold_level → 可机器校验的输出契约`：代码量契约（解码层把 ``` 设为 stop sequence）、可运行性契约（AST）、**信息增益契约**（回答不得引入学生当前代码中尚不存在的关键 API——"AI 可以让你用好你已经有的，不能替你想出你没有的"）、形式契约（diagnose 档必须以锚定当前代码行的追问收尾）。

**无支架检查点**：每轮末 5 分钟 AI 只读不答，用同一套 CT 指标测三次。
**没有它，"渐退式支架"在论文里只是配置说明，无法证明"支架递减而表现不塌"。**

## 🏗️ 五、工程排序结论：四个缺口是同一个根因

**四职能缺的那一格是「记忆」**——马金帅把导学规则存长期记忆 Profile（p.37）、方海光有画像库（p.43）、刘伯成有学生学习状态表（p.30）。
CX 的四个缺口——档位无处存、任务链无处挂、round 无持久维度、回流无可写回对象——**是同一件事：缺跨会话的学生画像持久层。**

→ **P0 必须先做**：`learner_state`（档位/轮次/掌握度/卡点/回退计数/独立性指数）+ `learning_round`（与 `study.py` 的 pretest/running/posttest **正交**，绝不复用其字段）。其余三个缺口全部挂在它们上面。

完整 34 条 idea 见综合 §6（含优先级、落地文件、来源文献）。

## 🚫 六、引用红线（会被评审直接抓）

- **柴兴祝「机器追问→认知觉醒」的"渐进"机制（p.75）是介入递增，方向与渐退相反，绝不可当渐退支架的文献支撑引用。**
- **四处"三"轴不同必须显式区分**：柴兴祝"三维"=架构层级、"三范型"=按学科并列选用；黄红涛"三"=三场境（空间并列）；马金帅"三阶"=难度解锁；你的"三元"=师—机—生、"三轮"=时间迭代。
- **不可引用的效果数据**：朱婷婷全部（无样本量/无检验，且表1"15项"vs正文"9项"自相矛盾）；柴兴祝（纯理论、校级学报、无实验）；黄红涛（形式化的姿态而非可实现的形式化）；孙贞岳 94% 建立在 SFT+未来上下文+离线之上（**绝不可写"参考孙，本系统可达94%"**）；李昊东 16 人组内被试顺序未平衡；马金帅 N=10 且理论溯源错误（把认知学徒制记为 Lave & Wenger，实为 Collins/Brown/Newman 1989——**引用时绕开其理论归属句**）。
- **谢鑫的效率指标（Bug率/千行、开发时长缩短20%）不可抄**——抄了等于承认效率是教学目标，自拆 CT 导向的台。

**场景不可比的硬答复**（"为什么别人的智能体可以给代码、你的不可以"）：
> 本科目标是产出可用软件（代码是产品，AI 加速产品化不损目标）；K12 目标是 CT 能力形成（代码是能力的外显证据，AI 给完整解即销毁证据链）。**"助学不代学"在 K12 是评价效度要求，不是道德要求。**
