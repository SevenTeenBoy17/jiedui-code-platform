## 一、教学模式的跨篇比较：循环形态与「三轮有限迭代」差异化点的存亡判定

### 1.1 循环形态的六类谱系（必须先做分类学，才能定位差异化）

把 11 篇按「时间结构」重排，会发现"无限闭环 vs 有限迭代"这个二分根本不够用，实际存在六类：

| 类型 | 文献 | 具体形态 | 有无终止判据 |
|---|---|---|---|
| **A. 纯无限闭环（教学过程层）** | 柴兴祝（5个闭环，p.73-75）、方海光（元路径"触发下一轮元路径循环"，p.46）、刘伯成（5→6→7→8→5，p.22） | 环环相扣、无编号 | 无。方海光有分层回溯但无轮次上限 |
| **B. 无限闭环（系统构建层，非教学层）** | 黄红涛（图7"四个步骤形成一个闭环系统，通过不断的迭代和优化"，p.66）、朱婷婷（三个"监测—诊断—优化"闭环，p.65-66） | 是研发/运维闭环，被同一套图形语言掩盖 | 无 |
| **C. 有限但被降级到实施层** | 谢鑫（模式图无限，但表2是4周5步瀑布，p.53） | 周历锚定的线性流程 | 有（周次到点），但不在模式层 |
| **D. 有限异构阶段链 + 外层无限螺旋** | 梁云真（五阶共知—共论—共证—共创—共行，p.112；共行阶段又写"螺旋上升闭环"） | 每阶做不同的事 | 阶段有序但无收敛判据 |
| **E. 有限线性阶梯（任务难度顺序解锁）** | 马金帅（LPP新手/进阶/专家，p.30-32）、李昊东（配额+阈值：复习≤2、固定3槽、至少1新课，p.21/37-38） | 内容难度递进 | 马金帅**无**跨阶段判据（"随着玩家成长"p.65）；李昊东**有**（分数<60 + 槽位配额） |
| **F. 线性无环 / 时间轴** | 吴君（两段：知识形成 / 整合-精化-扩展，无回流箭头，p.28-29）、朱婷婷（课前/课中/课后，p.66） | 无闭环、无轮次 | 阶段推进靠"认知任务复杂度"自然上升 |
| **G. 无教学模式** | 孙贞岳（教研测量论文，只有三层分治分析模型） | — | — |

### 1.2 判定：「四篇均只画无限闭环」这句话必须撤回，但差异化点仍然成立——只是要换承重墙

**必须撤回的三条表述：**

1. **"四篇/五篇均只画无限闭环"** — 谢鑫表2（p.53）是严格有限的 4 周 5 步，一条表格即可证伪；梁云真五阶（p.112）是有限异构链；马金帅 LPP 三阶（p.30-32）、李昊东配额机制（p.21）都是有限的；吴君（p.28-29）连闭环都没有，是线性两段。
2. **把黄红涛/朱婷婷算作"第 N 个无限闭环样本"** — 这是**层次混淆**。黄红涛 p.66 的闭环是"形式化→策略→表征→反馈调节"的**系统构建**闭环，朱婷婷的三个闭环含"建设—使用—迭代"的**平台运维**闭环，与谢鑫/方海光的**教学过程**闭环不在同一层。混着计数，审稿人翻开任一篇即可指出计数错误，连带整条论证失信。
3. **"有限 vs 无限"本身是差异化** — 梁云真是"有限内环 + 无限外环"，用户的三轮只要承认"下一个项目还要再来一轮"，同样是有限内环 + 开放外环。**这个维度上双方结构等价。**

**仍然成立、且无一篇具备的三条（这才是真差异化）：**

| 差异化条 | 11篇的状况 | 证据 |
|---|---|---|
| **① 轮次同构**（同一探究任务在多轮中重复穿过同一组 CT 环节） | **零篇**。谢鑫是瀑布分段（需求→设计→开发→测试，每个 CT 要素只练一遍）；梁云真五阶异构；马金帅三阶是三类不同任务；李昊东是批次容量而非迭代深度 | 谢鑫 p.53 表2；马金帅 p.30-32 |
| **② 支架强度沿轮次单调递减且有操作定义** | **零篇**。唯一有分级的马金帅是"按学习者层级"分级（横向），不是"同一学习者随轮次"递减（纵向）；谢鑫与吴君方向相反（递增） | 马金帅 p.37/47-49；谢鑫 p.51；吴君 p.28-29 |
| **③ 每轮有可判定的出口判据 + 未达标的回退规则** | **接近零篇**。李昊东有分数阈值但只在同一循环内；方海光有回溯（p.46）但无轮次上限；马金帅跨阶段跃迁只有"随着玩家成长"（p.65）；梁云真五阶无收敛判据 | 李昊东 p.21；方海光 p.46；马金帅 p.65 |

**建议的论文表述（可直接用）：**

> 已有研究在时间结构上呈四种形态：或为无终止的教学过程闭环（柴兴祝，2025，p.73-75；方海光等，2026，p.46；刘伯成，2009，p.22），或将阶段有限性降级为实施层的周历安排而未上升为模式的结构要素（谢鑫等，2026，表2，p.53），或为异构阶段的有限链（梁云真等，2025，p.112），或为任务难度的顺序解锁（马金帅，2025，p.30-32；李昊东，2023，p.21）。**在所检文献中，尚无一项研究呈现"同构轮次的有限迭代"——即同一探究任务在多轮中重复经历同一组计算思维环节、而智能体支架强度沿轮次单调递减且给出可判定的出口判据与回退规则。**需要指出的是，现有文献在使用"闭环"一词时普遍存在教学过程层与系统构建层的混淆（黄红涛等，2024，p.66；朱婷婷等，2026，p.65）。

### 1.3 「三」这个数字的合法性：三条独立锚点，避免循环论证

用户当前的隐含依据是"CT 四要素递进"，这有**范畴错误**（CT 四要素是并存的能力维度，不是时间序列——调试在第一轮第 3 分钟就发生了）；若改答"因为支架有三档"，而支架档位又"按轮次递减"，则是**循环定义**。

三条可辩护的外部锚点（互相独立，在 3 上相交）：

1. **可观测性下限**：要在数据上判定"单调递减"而非"有差异"，最少需三个测量点。两点只给一个差值（可能是噪声），三点才同时给方向与单调性。**三轮是"支架渐退可被证伪"的最小级数。**
2. **制品完成度三层**（源自编程活动本身，最硬）：R1 能跑（最简可运行原型）→ R2 跑对（覆盖边界与正确性）→ R3 跑好（优化与迁移）。这条同时修掉"三轮其实是瀑布"的硬伤——**每轮都完整走一遍分解/抽象/算法/调试，轮间差异是分解粒度、抽象层级、判据严格度**。
3. **三次撤除动作**（来自梁云真三拓扑的学生化改写，p.111-112）：AI示例 → AI提示 → AI仅诊断 → 人类同伴接管，三次撤退恰好三轮。

**同时必须补两条，否则"有限三轮"比无限闭环更弱：**
- **出口判据表格化**：R1→R2 = 分解产物提交且过 AI 诊断阈值；R2→R3 = 基础用例通过 + 调试事件收敛；R3→回流 = 提交反思单 + 无支架检查点达标 + 生成 CT 画像增量。
- **降级回退（逃生阀）**：R3 卡点超阈值临时回退到 hint 档并记 `fallback_count`（负向指标）；作用域写明"单元内有限、跨单元开放，跨单元轮次重置但支架基线上移"。否则"有限三轮"会被读成"到点就停、不管学会没学会"，而这在教育学上比无限闭环更不诚实。

### 1.4 师生机权责转移：11篇的集体空白，以及可直接抄的两份体例

**教师完全缺席的四篇**：黄红涛（全文"教师"出现 1 次且是被"模拟"的对象，p.66）、马金帅（AI NPC 完全替代师傅）、吴君（模型中根本没有教师角色）、李昊东（教师 = admin CRUD，p.32-34）。

**教师被降格为管理员的一篇**：刘伯成（"个性服务"教师页仅呈现学号|姓名|学习内容|时间|类型|评价，p.53）。

**两份可直接抄的权责体例：**
- **吴君 LEARN 表（p.42-43）**：Lead-in / Excite / Adjust / Reflect / Navigate 五阶段，**每阶段分别写明教师、AI助手、学生三方各做什么**——这正是用户图缺的"每轮三方权责表"的现成模板。
- **朱婷婷"AI补位、教师主导"（p.66）**：AI 承担 60% 重复答疑 + 80% 基础批改，教师保留复杂问题小组辅导、依据学习数据制定个性化方案、线下深度育人。注意这是**任务类型边界**（哪些活归谁），不是**能力生成边界**（能不能给代码）——用户需要的是后者。

**唯一显式的权责递进**：谢鑫"使用者 → 配置者 → 开发者"（p.51，中后期引导学生基于 Coze/ChatGLM 做 Agent 定制）。方向与用户的"支架递减"正交而非冲突，见第三节的双维方案。

### 2.2 三条从对比表得出的硬结论

**结论一：用户四职能是"需求层"语言，缺一次"架构层"分解和一张映射表。**
马金帅（p.17-19 / p.34-38）明确做了两次正交分解并给出映射，方海光（p.43）做了过程×资源二维。用户只有一层。**建议保留四职能作为对师生的功能承诺（图不动），另补一张「四职能 × 感知-记忆-推理-规划-执行」映射矩阵**，同时说服教育学审稿人与工程读者，成本极低。

**结论二：四职能缺的那一格是「记忆」，而这正是 CX 四缺口的共同根因。**
- 马金帅把导学规则（支架强度）明确存放在**长期记忆的 Profile 模块**（p.37）；
- 方海光有**画像库**作为推理规划的"直接依据"（p.43）；
- 刘伯成有**学生个性化信息表 / 学生学习状态表（已掌握/欠缺知识点双集合）**（p.30）；
- 李昊东有 **classhistory + 学习状态表**（p.18/30）。

CX 的四个缺口——支架档位无处存、任务链无处挂、round 无持久维度、回流无可写回对象——**是同一件事：缺跨会话的学生画像持久层。** 这个诊断直接改变工程排序（见第四节 P0）。

**结论三：四职能之间没有数据契约，而用户批评朱婷婷的那句话原样适用于自己。**
朱婷婷"全文未述及五个智能体如何协同、如何传递数据、由谁调度"（p.66-67）是用户最锋利的批评；但 CX 现状是：`ai.py` 的 scaffold 由教师手传、不读 `ct.py` 输出；`insights.py` 不消费 `ai.py` 对话。**结构上与朱婷婷五个并列入口同构。** 必须补契约（见第四节 4.5）。

### 2.3 多智能体分工：11篇中只有 2 篇是真的

| 判定 | 文献 | 依据 |
|---|---|---|
| **真多智能体** | 梁云真 | AutoGen 角色制 + 组长 speaker-selection orchestrator（"决定每一轮的发言人（人类教师或某个角色的智能体），并将信息实时同步给所有教研组成员"，p.113） |
| **真多智能体（前LLM）** | 刘伯成 | KQML 扩展通信语言 + 中心化消息总线，三类 Agent 显式分工（p.21-22） |
| 声称多智能体但无协同协议 | 朱婷婷（五个并列入口）、谢鑫（五个工具型 Agent）、方海光（"智能体组通过功能分工与协同调度"仅一句，p.43）、柴兴祝（仅表3一个单元格） | 无角色划分/通信协议/仲裁机制/状态管理 |
| 单体 + 模块 | 柴兴祝、黄红涛、吴君、李昊东、马金帅、孙贞岳（属性并行但无编排） | — |

**对用户的建议（口径问题，影响审稿）：**
契约一写清就会发现四职能是**一条 LLM 工作流的四个阶段**，不是四个自治智能体。建议全文改称「**四职能模块 / 四职能架构**」，慎用"多智能体"，否则被问"自主性、目标、规划在哪"而答不上来。改口径不削弱贡献，反而更诚实。

**但 CX 有一份别人没有的真协同协议可写**：`ai.py` 的 ai_driver/ai_navigator 双 persona + `collab.py` 的服务端权威角色裁决（谁能写码、谁只能提问、角色如何裁决、断线如何接管）——这比方海光"智能体组协同调度"一句话、比朱婷婷完全空白都实在，应整理成一份协议文档写进系统实现章。

**三条可直接抄的工程硬技巧：**
1. **LLM 输出净化层**（孙贞岳 p.46/49）：大模型偶尔返回"该话语的编码类别为3"这种非纯数字，不过滤会在统计/可视化环节直接报错。**任何 LLM 分类结果进统计管线前必须先过正则抽取 + schema 校验。**
2. **类别分布先验反向约束判别边界**（孙贞岳 p.45-46）：话语兼含"讲授"与"评价反馈"两义时，prompt 里写死"若同时包含1或4则优先编码为4"，理由是"讲授类别已足够多"。CX 的 CT 六维打标可用同法防止"调试"被"编码"吞掉。
3. **结构化中间层治理 LLM 不确定性**（马金帅 p.51）："大模型输出的自然语言教学意图具有一定的不确定性，而行为树要求输入的指令具有明确的结构化格式" → 自建意图解析器。CX 的任务链生成必须有这一层（JSON schema 强约束）。

### 3.2 综合：一份可实现的「渐退式支架」操作定义

**这是 11 篇文献里没有任何一篇给出的完整定义，也是本研究最硬的原创点。** 它由五个可分别落地的部分组成：

#### (1) 支架强度的三因子裁决函数

```
scaffold_level = clamp(
    ceiling(round),              # 天花板：教学设计给定，保证越到后面越放手  [用户原创]
    floor(demand_t),             # 地板：实时诊断触发，保证真卡住不被饿死    [方海光 p.46]
    gate(has_own_attempt),       # 时序门：先尝试后解锁                     [本轮增量]
    source(round)                # 来源迁移：AI → 同伴 → 自我               [梁云真 p.111-112 学生化]
)
```
- `ceiling(round)` = {1: example, 2: hint, 3: diagnose}，**硬约束，只能降不能升破上限**
- `floor(demand_t)` = f(连续失败次数, 停滞时长, 同类错误重复率, 求助频次)。**关键纪律：只采信"有动作的失败"**（运行报错、提交失败、同类错误重复），纯时间停滞降权为提醒而非提级——初中场景下停滞 ≠ 卡住（可能是走神、聊天、离座）
- `gate(has_own_attempt)`：level ≥ hint 需学生已提交过自己的错误尝试（运行过/报过错/写过伪代码或 Blockly 草稿）。**防止初中生第一课就学会"复制能过"**
- **滞回与非对称阈值**：降级需连续证据（双条件合取：任务判据达成 AND 示例型支架请求率低于阈值）；升级只需一次失败信号（连续 2 次运行失败 + 无代码增量 + 停滞 > 5 分钟，且每轮升档上限 1 次）。**只降不升的单调渐退，一旦某轮误判就变成放任，这是教学风险不是设计洁癖。**

#### (2) 五条渐退通道（马金帅 p.37/47-51/55-60 的直接学生化）

| 通道 | 内容 | 来源 |
|---|---|---|
| **① 提示词模板族** | R1 具体/生活化比喻/可给同构异题的完整可运行示例；R2 引导思考、只给伪代码骨架+关键API名；R3 启发批判、只描述现象+反问 | 马金帅三级模板族 p.47-49 |
| **② 教学材料难度** | R1 经典简单案例（详展组成/原理）；R2 加减变化案例；R3 无案例 | 马金帅行为树选择节点 p.50-51 |
| **③ UI 可供性** | Blockly 积木可见分类、代码片段库条目数、求助入口类型（R3 只暴露"提问"不暴露"给例子"）随档位收窄 | 马金帅 p.60"初级玩家界面简化，只提供常见的药材选项" |
| **④ 任务步骤数与选项集** | 错误率高+耗时长 → 减少步骤数、简化流程；表现出色 → 提高复杂度 | 马金帅 p.55-57 |
| **⑤ 支架来源迁移** | R1 AI 示例 → R2 AI 提示 + 领航员承接质疑职能 → R3 AI 仅诊断 + 同伴/自我承担 | 梁云真三拓扑 p.111-112 |

**通道③是最被低估的一条**：它比提示词渐退更可观测、更易做量化证据（"可见集大小"可直接作自变量），而 11 篇里只有马金帅提到，且他做在游戏 UI 上、没有理论化。

#### (3) 双向调节：不是所有支架都该退（这是回应吴君与谢鑫的唯一硬答复）

吴君明写这叫"分层、渐进的学习支持"（p.60），谢鑫隐含主张"AI 时代不该撤支架，该改变的是学生对支架的支配方式"（p.51）。**这两条都不是无理的**——若学生毕业后终身与 AI 协同工作，"撤掉 AI"训练的是一种不会出现的工作条件。

**回应必须是四条正交轴的分离，而非否认：**

| 轴 | 方向 | 理由 | 文献支撑 |
|---|---|---|---|
| **A. 代劳度 / 答案供给**（可提交代码、完整解） | **递减** | CT 能力形成期，代码是能力的外显证据；给完整解即销毁证据链 | 用户原创；方海光负面实证 p.48 |
| **B. 信息通道 / 媒体丰富度**（图示、可视化、多模态） | **可增** | 任务变复杂，通道要更宽 | 吴君 p.28-29（媒体丰富度理论） |
| **C. 学生对智能体的控制权**（预设 → 白名单档位自选 → 槽位组装） | **递增** | AI 素养培养 | 谢鑫 p.51 |
| **D. 语法/API 层帮助**（片段库、随查手册、Blockly 积木） | **恒常开放** | 初中零基础，"不代的是思考，不是打字" | 马金帅 N=10 记忆维度输给传统网课 p.76-77 的教训 |

**一句可写进论文的话**：智能体给出的答案越来越少，学生对智能体的支配越来越强，信息通道不减反增，基础工具始终在手。
⚠️ K12 必须把轴 C 降级为"**受约束的选择权**"：谢鑫的"使用者→配置者→开发者"是大三软工微专业（能写 Coze 工作流），初一学生的现实上限只到"从教师给的 3-5 个提问风格模板里选一个"，且上限被"不给答案"这条硬红线封顶。

#### (4) 从"输入侧祈使"到"输出侧契约"：助学不代学的机制化

**这是全篇最关键的一步转换，也是修掉一处自相矛盾的地方。**

李昊东与刘伯成**能**用次数配额，是因为规则引擎时代每一次"帮助"的信息量是恒定定值（固定语音 `audio/right.wav`、固定正确答案高亮）。**LLM 输出信息量连续可变——一次"提示"若顺手写全伪代码就等于一次示例，配额对 LLM 无效。**

正确形态是 `scaffold_level → 可机器校验的输出契约`：

| 契约 | 判据 | 实现层 |
|---|---|---|
| **代码量契约** | level ≥ hint 禁连续代码块 > N 行；level = diagnose 禁任何代码块 | **解码层前置**：把 ``` ` ``` 设为 stop sequence（首选，避免流式"先吐出来再收回"） |
| **可运行性契约** | AST 判定是否存在完整 `def` + `return` 且无占位符 | 后置校验 |
| **信息增益契约**（最锋利） | 回答不得引入学生当前代码中尚不存在的关键 API/结构名 | `code_context` 已传入 `build_system_prompt`，做一次符号 diff 即可。**语义直译："AI 可以让你用好你已经有的，不能替你想出你没有的"** |
| **形式契约** | diagnose 档回复必须以锚定当前代码行/报错的追问收尾（禁泛问） | 正则 + LLM 裁判双校验，不合格重生成 |
| **来源可追溯契约** | Monaco 单次插入超阈值、且不匹配本会话任何 AI 回复文本、且不在编辑历史中 → 标为**外源片段**，不计入 CT 的算法/调试证据 | 前端埋点 + `ct.py` 证据排除 |

**外源片段的处理纪律（决定这个功能能否活下来）**：口径必须是**证据完备性**不是**诚信审查**——写"这段没有过程记录，无法用于能力画像"，不写"疑似外部生成"。初中生对"被抓"极敏感、对"没记录到"接受度高。**这同时保护了 CT 测量效度**：粘贴来的代码没有调试轨迹，六维会给出虚高的"能力上升"，从而触发错误的支架降级——污染的是渐退控制器的输入。

**另需并入"禁止 + 计分"三件套**（谢鑫 p.51-52）：CX 的苏格拉底锁是"禁止"（输入侧限制，无法自证有效——锁住 AI 不给代码 ≠ 学生在思考），谢鑫是"计分"（把人机协作过程质量直接计入 30% 过程性成绩）。**禁止（输入侧）+ 契约（输出侧）+ 计分（过程侧）才是完整机制。**
⚠️ 但不可抄谢鑫的效率指标（Bug率/千行、开发时长缩短20%，p.48）——抄了等于承认效率是教学目标，自拆 CT 导向的台。

#### (5) 结对场景的档位裁决（CX 独有，11篇文献全部是单人模型）

**没有一篇处理"两个学习者共享一个智能体会话"**（李昊东 p.63 明确自陈"目前系统仅支持单人使用"）。这是 CX 相对全部已读文献的真原创。

裁决规则：
- **档位绑在人（student × 课题 × 轮次），渲染在角色**：驾驶员用本人档位；领航员侧走 `ai_navigator` 且取两人较低档再收一档（逼其提问而非替队友要答案）；角色轮换时档位随人走，由 `collab.py` 在 `role_switch` 广播里一并下发。
- **角色互换本身是一次支架调节**：弱者当驾驶员 = 加支架，强者当驾驶员 = 对弱者撤支架。于是 3 轮 × 每轮 ≥1 次互换 = **6 个驾驶段、6 个档位判定点**，顺带化解"三轮观测点太少"的质疑。
- **双盲兜底**：双方连续 N 次运行失败且无代码增量且结对对话静默 → 允许临时升档，但该升档必须同时写入教师可见事件，防止学生用"两人都不动"骗示例。
- **可见性纪律**：**降级静默、升级才广播**（降档只体现为 AI 风格变化，升档给"解锁自主模式"徽章），教师端可见完整档位表。避免弱生知道自己被留在示例档产生污名化。

#### (6) 渐退的可测性：无支架检查点（否则渐退只是配置说明）

每轮末插入 5 分钟**无支架小测**：AI 只读不答（persona 切 silent，仅记录），用同一套 CT 指标在三轮末做三次测量，画出"支架级 vs 表现"两条曲线。
**没有它，"渐退式支架"在论文里只是配置说明，无法证明"支架递减而表现不塌"。**
同时，无支架通过率是进入下一轮更低支架的**准入门槛**，也是"有限轮迭代"的收敛判据之一。

## 四、补 CX 四缺口的具体方案（落到 server/app 与 web/src）

> 前置判断：**必须先做 P0 的 `learner_state` 持久层与 `round` 维度**，其余三个缺口全部挂在它们上面。这是本次综述最重要的工程排序结论。

### 4.0 【P0-a】学习者状态持久层 `learner_state`
**来源**：马金帅长期记忆 Profile（p.37，导学规则/导学角色/导学场景）、方海光画像库（p.43）、刘伯成学生学习状态表（p.30）

```
learner_state(
  id, student_id, class_id, study_id, topic_id,
  round_index,               -- 1|2|3
  scaffold_level,            -- example|hint|diagnose
  scaffold_source,           -- ai|peer|self
  ceiling_override,          -- 教师锁档（苏格拉底锁的新语义）

)
```

### 4.0 【P0-b】教学轮次 `round`，与研究阶段正交
**来源**：本轮跨篇共识 + 谢鑫 4周5步双触发（p.53）+ 李昊东配额（p.21）

**关键澄清（必须写进文档，防后续混用）**：`study.py` 里的 `pretest/running/posttest` 是**研究流程状态机**，与**教学轮次**正交，`round` 挂在 `running` 之下，绝不复用其字段。


### 4.2 缺口②：任务链实例化（问题链 → 任务链）

**四段式管线（直接照搬马金帅 p.49-51，输入换成学情）：**

```
① 取数        ← ct.py 六维弱项 + 近 N 次运行错误类型分布 + 用时 + 求助频次 + blocker_type
② LLM 出一句话【教学意图】   ← 马金帅 p.50 原型："强化方剂配伍知识学习……提供更多针对性练习"
③ 意图解析器（JSON schema 强约束）  ← 马金帅 Dify 意图解析器 p.51；孙贞岳输出净化 p.46/49
     输出 {focus, goal, ct_dim, difficulty, exit_criteria}
④ 展开任务序列  ← 行为树三节点语义（马金帅 p.50-51）
     sequence(读题拆解 → 建模 → 编码 → 自测 → 复盘)
     + selector(同一子任务的难度变体，按 scaffold_level/mastery 选一)
     + parallel(下发的同时挂"监测作业"=埋点规则+阈值，用于轮内触发再规划)
```

**数据模型（把图上的"三链"变成库里的表，答辩可直接展示 ER 图）：**
```
problem_chain(id, teacher_id, class_id, seq, stem, ct_dimension, difficulty_tier,
              tags[], quality_status, round_hint)        -- 教师制品，"标注+分层分类"是可实例化的前置工序 [方海光 p.42]
task_template(id, problem_id, variant_level, prompt_template, slots, done_criteria)  -- 候选池
task_chain(id, study_id, class_id, student_id, round_index, seq, problem_ref,
           task_template_id, slots_filled, done_criteria, scaffold_level,
           status, done_rate, reordered_from)            -- 智能体实例化产物
eval_chain(id, task_chain_id, ...)                        -- 评价，且回喂下一轮 planner
```

**三条纪律：**
1. **验收判据**：同一条问题链条目对两个不同学情的学生，产出的任务卡必须**可见地不同**，否则只是换名字的 CMS。论文里应放一张"两个学生任务卡对比图"作为证据。
2. **候选池约束**（防飘出课标）：selector 只能从 `task_template` 候选池里选，LLM 只做**选择+排序+措辞**，禁止自由生成任务体。这既治飘移（等价于马金帅 Neo4j 本体的兜底作用），又构成"助学不代学"在教师侧的对偶——**AI 不代教师做课程性判断**。
3. **教师审核位**：智能体产出草案 → 教师一键采纳/改序/换题/调档 → 下发。**这一位是 CX 相对吴君（无守门人、无教师在场）与马金帅（教师完全缺席）的结构性增量**，且采纳/否决记录直接供给缺口④。

**概念前序图（v2 增强，可选）**：初中 Python 概念集只有 30–60 个节点（变量/输入输出/条件/循环/列表/函数/海龟/调试），先修边由课标+教材目录一次性生成，**无需图数据库，SQLite 一张 `concept_edge` 表足够**（刘伯成 p.29 的"前序知识点+难度等级"两字段即序列自动生成的全部依据）。增量做法：用实际通过率**自动修正前序边**（大量学生未掌握 A 却通过 B → A→B 可疑，提示教师确认）——刘伯成的图是静态的，动态修正是 CX 的小而实的创新点。

**落点**：新增 `server/app/services/task_chain.py`、`server/app/routers/tasks.py`（`POST /api/v1/tasks/instantiate`、`GET /api/v1/tasks/current`、`PATCH /api/v1/tasks/{id}/review`）；`resources.py` 的手动推送降级为兜底；教师端教研区新增"问题链 → 任务链"预览-编辑-下发三步页。

### 4.3 缺口③：三轮教学结构

见 4.0-b。补充三条：

1. **轮次目标改为制品完成度三层**（R1 能跑 / R2 跑对 / R3 跑好），而非 CT 阶段名——**这是修掉"三轮其实是瀑布"这一模式硬伤的落地物**。`done_criteria` 按轮分层：R1 = 运行通过（无报错即可）；R2 = 教师用例集全过；R3 = 自查表勾选 + 一道迁移题。前端任务卡顶部显示**本轮制品目标**而非阶段名。
2. **轮次挂配对会话、支架档位挂个人**——"轮"是共同教学节拍，"档"是个体化，以此在实现层调和"有限轮"与"个性化"（回应方海光对"标准化课程设置"的批判，p.40）。
3. **换驾建议器（规则触发，不用 LLM）**：驾驶员连续 N 分钟无有效编辑 / 领航员发言被连续忽略 / 同一报错重复 K 次未改策略 → 发**建议卡片**，需双方同意才生效（保留"学生自己协商角色"的教学价值）。梁云真的 AutoGen 组长路由（p.113）只作**引证来源**说明"编排者"角色文献已有，**不作实现方案**——他那里发言是免费的，CX 里稀缺的是编辑权不是发言权；且 LLM 判断不可复现，削弱研究的可报告性。
   **落点**：`collab.py` 新增 `handoff_suggest` 消息类型 + 纯规则 evaluator（读房间内 edit/chat/console 事件窗口）。

### 4.4 缺口④：数据回流 → 教师策略调整闭环

**核心诊断（来自梁云真 p.108 与本轮追问）**：这条闭环的可行性**不取决于数据够不够，取决于教师动作的成本是否低于其收益**。刘伯成的教师端表格（p.53）20 年未被突破，不是没想到记录，是记录成本落在最忙的人身上。初中教师一节课带 15–20 对结对、还要巡台维持纪律，**可消化信息量上限约 3–5 条**。

因此"对师输出 = 学情画像"在课中是**错的输出形态**——画像是高维只读物，教师没有解码预算。

**三段闭环 + 五条设计纪律：**

```
建议（带证据的归因候选） → 采纳/否决/忽略 → 后效
```

| 纪律 | 内容 | 来源 |
|---|---|---|
| **① 课中给可操作队列，不给画像** | 教师端 live 页只出 **Top-3 干预建议**，每条含〔谁 / 卡在哪个 CT 维度 / 建议说的一句话 / 一键动作〕；画像与诊断留课后 | 本轮增量 |
| **② 机给候选、人做选择** | `insights.py` 结论卡给 2-3 条**归因候选**，每条强制挂 `evidence_refs`（可点开到原始 ct_event / 代码快照 / 报错记录）。教师做"选择与修正"而非"从零撰写"，负荷从生成降到识别 | 梁云真 p.114（"机出是什么、人出为什么和怎么办"）+ 本轮工程化 |
| **③ 捕获而非索取 + opt-out** | 教师已在做的动作（下发苏格拉底锁、推资源、换组、调难度、推进轮次）自动补写 `teacher_action`，不新增填写表单；轮末系统自动生成下一轮参数进入"待生效"，教师只需「维持/改」，**不操作也闭环** | 本轮增量（对抗"表会是空的"） |
| **④ 区分 dismissed 与 ignored** | 显式否决是**高价值负反馈**（可用于降低同类建议推送权重），无动作只是没看见。两者必须分开记 | 本轮增量，文献里无人做 |
| **⑤ 主指标用后效不用采纳率** | 采纳率仅研究者可见、不回显教师（否则教师知道被记会无脑点采纳）；后效 = 下发后 15 分钟窗口内同类报错复现率 + 轮次达标率，与同班未下发者作班内自然对照 | 本轮增量 |

**回流必须有一条可追踪的写路径**：报告若不能改变下一轮任务链的实际内容，闭环就没闭。回流产物要能**一键写回 `task_chain`**（`prompt_template` / `done_criteria` / `scaffold_level` 的差异化覆盖）。

**三级回写按权限与可逆性排序**（来自柴兴祝 p.75"多模态数据反哺知识图谱优化" + p.77"教师转型认知架构师"）：
- **L1** `scaffold_level` — 机器自动、规则可审计 → `scaffold_policy.py`
- **L2** 任务链路径跳过/插入概念 — 教师一键确认 → `task_chain` + `concept_edge`
- **L3** 教师问题链制品本身 — 教师手动编辑 → 教研区 `study.py` 的真正用途
  **只有 L3 才真正落实"教师=认知架构师"，也才让模式图左侧的教师调控环不落空。**

**表结构**：
```
teacher_action(id, class_id, teacher_id, target_student_ids[], round_index,
               suggestion_type, candidate_id, action ∈ {adopted|dismissed|ignored|auto_applied},
               follow_up_type, triggered_by_insight_id, evidence_snapshot JSON, acted_at)
```
`evidence_snapshot`（决策当时的指标与分层名单快照）是**关键字段**——没有它事后只能靠猜，闭环在论文里无法被验证。

**教学预注册（替代马金帅的"效果区间预测"）**：CX 无历史数据，机器预测的区间是虚假精度，一旦不准就摧毁教师信任。改为教师下发任务前**自己填写预期区间**（本班预计多少人完成到哪一步），事后系统自动对照实测。既是评价链首尾呼应的廉价实现，又强制把教师隐性经验外显化——正好落实梁云真只命名未实现的人链"内隐化→社会化→外显化"（p.111）。

**落点**：`server/app/routers/insights.py`（结论卡增 `candidates[]` / `evidence_refs[]` / `actions[]`，新增 `GET /api/v1/insights/round_report`）、`server/app/routers/ct.py`（按 round 分组聚合 + 卡点 Top-N）、`server/app/models/teacher_action.py`、`server/app/routers/study.py`（对比报告消费 cohort）；`web/src/views/teacher/Live.vue`（Top-3 队列）+ 教研区（轮次对比 + 一键采纳 + 内联提示）。

**内联而非新看板**：回流提示必须出现在教师**下次布置作业/编辑问题链的那一刻**（备课环），在该问题节点旁自动显示"上次此节点在轮2用 hint 档，后续错误重复率 −3%"，而不是新增第五个仪表盘——否则这条闭环在真实课堂里是死的。

### 4.5 四职能数据契约（跨缺口的架构基础，必须先定）

**这条不属于四缺口，但它是四缺口能否互相咬合的前提**，且直接消解"你批评朱婷婷的话原样适用于你自己"这一致命反击。

在 `server/app/` 里落成 4 个 pydantic schema 作为模块间**唯一接口**，论文系统实现章直接贴这张表：

| 职能 | 输入 | 处理 | 输出物 | 受众 × 时间粒度 | CX 落点 |
|---|---|---|---|---|---|
| **学情感知** | 原始交互事件 | 埋点 + **语义解释层**（卡点类型标注） | 事件流 + 状态向量 + `blocker_type` | 系统内 / 实时 | `ct_events` 埋点 + `ai.py` SSE 结束后异步轻量分类 |
| **学习分析** | 事件流 | 跨时段聚合建模 | CT 六维分数 + 卡点标签 + 轮次达标位 | 教师 / 课时级，**须可复现可审计** | `ct.py`（拆 `infer_realtime` 与 `eval_batch` 两条时延通道） |
| **支架推送** | CT 分数 + round + 角色 + demand | 档位裁决 + 契约校验 | `scaffold_level` + 提示文本（受契约约束） | 学生 / 秒级，**低延迟、允许近似** | `scaffold_policy.py` + `ai.py` + `scaffold_gate.py` |
| **评价生成** | 以上全部 | 判读 + 归因候选 | 画像增量 + 归因候选卡 + 回流包 | 学生（即时判读）+ 教师（形成性诊断） | `insights.py` + `study.py` |

**两条必须写进论文的补充：**

1. **"学情感知"必须拆成信号层与解释层。** CX 现状的学情感知就是 `teacher/live` + `ct_events` 埋点——**恰恰是平台职能**，这与"学情感知是智能体职能"的主张直接冲突，看系统截图就会被发现。补法：从结对对话与 AI 对话中抽取**卡点类型标签**（需求没读懂 / 分解不到位 / 算法想错 / 语法错但归因错 / 已放弃求答案）写回 `ct_events.blocker_type`。**这是只有智能体能产出、平台埋点产不出的那部分数据**，四职能中的"学情感知"专指解释层。

2. **CX 有一个 11 篇文献全都没有的动机标注源：结对对话。** 孙贞岳的整个微活动定义建立在"动机完整性"上（p.15），而埋点事件本身不含动机——`run` 三次，边界测试与瞎撞在字节层面一模一样。**PairDock 里领航员必须把意图说出来驾驶员才可能改代码，因此结对对话就是学生自产、无需教师事后标注的动机标注。** 工程含义：CT 六维打标的输入应是 `(代码 diff 事件, 时间对齐的结对对话片段)` 二元组而非纯事件流；窗口把孙贞岳的"前后各 5 句"改造为"**前 10 个事件 + 延迟 3 个事件**"（实时场景拿不到"后 5"），标签表保留 `provisional/confirmed` 两态。

### 5.2 挑战点（按致命程度排序，前四条会改变图上的字）

**【1｜最致命】三轮的轮名与"螺旋"宣称自相矛盾，必须改名。**
"第一轮·分解建模 / 第二轮·算法实现 / 第三轮·综合优化"与谢鑫的"需求分析+方案设计 / 集成开发 / 测试改进"（表2, p.53）**逐条同义**。用户用来批评谢鑫的那把刀（阶段化≠迭代化、CT 要素被切开绑死在不同阶段），砍在自己的轮名上同样见血。若第一轮只做分解建模，那么"每轮完整走一遍分解—建模—实现—调试"在图上毫无结构支撑。审稿人把外圈轮名与中间宣称并排一读，差异化点即刻瓦解。
**改法**：轮次的区分维度从 CT 要素改为**制品完成度层级**（R1 能跑 / R2 跑对 / R3 跑好），每轮完整走四要素，轮间差异是分解粒度、抽象层级、调试判据严格度。CT 要素降为**每轮的重心标注**。同时把第三轮"综合优化"改名"**调试迁移 / 优化与迁移**"（现名与 CT 要素"调试评估"不对齐，会被误读为第三轮才开始调试）。

**【2】四职能之间没有数据契约，与朱婷婷同源。**
图只画了对师/对生两条输出边，四职能彼此的输入输出**一条线都没画**。你据以批评朱婷婷的理由原样适用于自己，且 CX 现状印证了这一点（`ai.py` 的 scaffold 不读 `ct.py` 输出，`insights.py` 不消费 `ai.py` 对话）。见 4.5。
**附带口径建议**：契约写清后会发现这更像"一条 LLM 工作流的四阶段"，全文改称"四职能模块/四职能架构"，慎用"多智能体"。

**【3】"对师输出"仍是单向推送，缺教师→智能体的控制输入箭头。**
梁云真明批"MAS 的海量信息单向推送加重教师信息筛选负担"（p.108）、"非对称互惠"（p.110）。图上机→师只有画像/诊断，师→机只有"教学调控"（而"教学调控"是师对生的动作，不是师对机的反馈）。而 CX 实物里教师已能下发苏格拉底锁、维护问题链顺序——**这是教师→智能体的控制输入，图上却没有**，落地物比模式图更完整，这是倒挂。
**改法**：补一条实线"采纳即回流"（依据梁云真 p.111"通过教师的教学策略反哺持续优化推理模型"），并把"数据回流"一根箭头**拆成 L1/L2/L3 三根并标注权限**——"人机权责边界"就从口号变成图上可数的三条边。

**【4】学生侧没有第二个学生——漏掉的正是 CX 最独有的资产。**
学生侧是单一红色主体，而 CX 的核心机制是结对（PairDock 小狐/小枭 + `collab.py` 服务端权威角色 + 苏格拉底锁）。检验方式是问一个单主体模型里根本问不出来的问题：**支架档位是算给个人的还是算给这一对的？** 一旦提出就必须给规则，而给规则的过程恰好产出最有价值的新命题：**角色互换本身是一种支架调节手段**。
**且这是回应"AI 时代为什么还要撤 AI"（谢鑫 p.51）的唯一钥匙**：谢鑫是二元结构（撤了 Agent 学生就孤立无援，所以他主张不撤而是让学生升级为开发者），CX 是三元结构，支架可以**转移而非撤销**：AI→同伴→自身。⚠️ 图上必须分清 PairDock 的 AI 小狐/小枭与 `collab.py` 的真人 driver/observer 两套角色体系。

**【5】"评价生成"这个职能名与文献的权责线正面冲突。**
梁云真 p.114 虽命名"归因分析"阶段，正文里执行归因与制订措施的是**教师**（机器只出多维数据、三维评估、可视化报告）。图上把"评价生成"写成智能体职能，会撞上这条最有力的权责线。
**建议**改为「**评价支持**」或「**证据组织**」，或至少在图注写明"生成的是候选评价与证据，判定权在教师"。

**【6】四职能缺"交互/情境"，而 CX 恰恰最强。**
柴兴祝三层中的**交互层**（情境沉浸、社会互动、多模态，p.74）在用户四职能中无任何对应物，而 CX 有 Monaco/Blockly 双模、Pyodide 海龟绘图、PairDock 结对。
**但补法不是加第五职能**，而是让交互层成为**渐退的物质形式**（渐退终点从"无帮助"改为"机→人移交"），这样 PairDock 不是图外的底板，而是渐退阶梯的第四档本身。

**【7】诊断维度缺情感/动机轴。**
方海光以行为/认知/**情感**三诊断为起点（p.42），元路径依据含"情感波动"、行动风险含"情感倦怠"（p.46）；马金帅有表情识别 + 语音情感分析（p.57）。用户只有 CT 四维（纯认知）。
**补法**：用停留时长、连续失败、求助频次、放弃/关闭事件、结对中的发言量等**代理指标**，无需量表。它同时是 `demand(t)` 的输入。⚠️ 谢鑫的"日志情绪词"（p.51）在初中易误判且涉学生心理数据，建议不采纳，换成行为信号（含**结对沉默方占比**——CX 独有的强信号）。

**【8】教师侧缺成长回路。**
方海光教师四角色含"**学习者**"（p.42-43，回归学习者身份、重构知识与价值框架）；梁云真"教师转型认知架构师"（p.77）。用户只有备课环+调控环两个"做事"的环。
**补法**：回流箭头分叉——(a) 短周期回调控环（课内策略调整）；(b) 长周期回**教研反思**（教师专业成长），正好挂 CX 教研区 `study.py`/`insights.py`，让教研区第一次在模式图上有位置。

**【9】"三"的轴混淆风险。**
黄红涛的"三"是**三场境**（自学/混合/协作，空间并列）、柴兴祝的"三维"是**架构层级**、柴兴祝的"三范型"是**按学科场景并列选用**、马金帅的"三阶"是**难度解锁**。同一数字四种轴，审稿人极易串。**图注或正文必须加显性辨析。**

**【10】图学修辞层面。**
智能体画在正中央，在视觉上暗示 AI 是主导主体，与"协同而非替代""教师回归育人本位"（方海光 p.42）存在张力。建议用虚线边框/浅色底表达为**中介服务层**，或让 CT 四要素占据中心、智能体作为环带。

### 5.3 可强化处：三个应该提到模式图上的原创点

| 原创点 | 为什么是原创 | 怎么写进图 |
|---|---|---|
| **① 支架来源迁移（AI → 同伴 → 自我）** | 11 篇文献的支架全是**单人学习者模型**（李昊东 p.63 明确自陈仅支持单人）。CX 的三元结构让支架得以**转移而非撤销**，撤的不是人机协同，而是协同中机器的答案供给；协同强度不降，支架承担者逐级内化 | 在"渐退式支架"下加一行小字标注四档三退；PairDock 从"平台功能"升格为模式的**理论承重墙** |
| **② 角色轮换 × 支架渐退二维矩阵** | 无一篇处理"两个学习者共享一个智能体会话"。且 CX 已有**服务端权威角色**（`collab.py`），"谁在驾驶"是系统已知事实——别人没有这个前提 | 学生侧改画两人 + 一条"角色轮换"箭头，标注"每轮 ≥1 次互换 → 6 个档位判定点" |
| **③ 输出契约作为"助学不代学"的机制符号** | 11 篇里，方海光的约束是规范性断言、谢鑫是过程计分、其余全无；**没有一篇做输出侧的可机器校验约束** | 智能体框内加一格「输出契约 / 约束闸门」，作为四职能的**输出闸**而非第五职能——否则模式图无法回答"凭什么智能体不会代做" |

### 5.4 可直接借用的写作范式（三条）

1. **"由文献共性生成模式"的方法论**（方海光 p.43-45）：做编程/CT 培养模式对比表 → 从"核心结构/运行机制/调节方式"三视角提炼共性 → 指出共同短板（同构轮次的缺席 + 支架的时间维缺席）→ 由此推出三轮迭代模型。模型就不再是"拍脑袋画的图"。⚠️ **必须交代文献纳入标准**（几篇、怎么选、谁编码），否则重蹈方海光 n=6 自选样本的方法论薄弱。
2. **风险标注矩阵**（柴兴祝三表把"潜在风险"独立成列与"教育功能"并置，p.76）：建《智能体四职能 × 风险 × 护栏 × 证据》表——学情感知↔隐私泄露↔PII 打码（CX 已有 R5 护栏与常驻回归语料，可直接填证据列）；支架推送↔代做与削弱自我调节↔四档渐退+输出契约+无AI检查点；学习分析↔忽略个体差异↔六维分位而非均值；评价生成↔算法偏见↔教师复核留痕。**既是工程文档，也直接充当论文"人机权责边界"一节，把"助学不代学"从口号变成可审计的表格。**
3. **八维轮次可区分表**（本轮综合）：制品目标 / AI 支架档位 / 学生控制权 / 支架承担者 / 完成判据严格度 / 评价重心 / 教师角色 / 推进触发——**差异化不在"画了三轮"，而在"三轮之间有八条可区分的机制变化且每条在系统里都有实现"**。这张表同时是模式说明、系统设计说明与差异化论证。

### 7.3 需要真实课堂验证的假设（不可在论文里当已知结论写）

1. **三档支架能否被初中生感知为不同档位** —— 若一节课 45 分钟内降三级，学生可能感知不到差异，渐退成走过场。需先验证"每轮 ≥1 课时、项目 ≥3 课时"的下限假设，并给出降级规则（2 课时降为两轮，1 课时降为单轮+轮内渐退）。
2. **`demand(t)` 的代理指标在初中生身上的信噪比** —— 停滞 ≠ 卡住（走神、聊天、离座都表现为停滞）。必须实测"有动作的失败"与"纯时间停滞"的区分度。
3. **教师采纳率** —— 若实测 < 10%，"数据回流驱动教师决策"被自己的数据打脸。**提前埋点区分"未采纳"与"未看见"**（曝光/点击/采纳三级事件），并把采纳率作为**研究发现**报告而非隐藏。承认真实使用率，远好于宣称一个没人用的闭环。
4. **降档的污名化效应** —— 弱生知道自己被留在示例档是否产生负面影响，需要访谈证据支持"降档静默、升档广播"的设计。
5. **"同构异题"的内容工程成本** —— LLM 现场生成不稳定（容易退化成给同一题的答案），题库预挂 1–2 个同构题是真实成本，必须在论文实施条件里如实写出。
6. **准实验的主结局必须预先声明** —— 方海光的结果结构（数据素养 p=0.001、路径丰富度 p=0.046 显著；知识测试 p=0.128、任务完成度 p=0.351 不显著）提示：智能体提升的是**过程多样性与元认知类素养**，没提升**结果质量**。若 CX 把主结局放在作品质量/正确率，大概率不显著。**主结局应预注册为过程性指标**（CT 事件密度、路径节点数、调试收敛速度、独立性指数、支架渐退曲线），作品质量作次要结局。
7. **马金帅记忆维度失分的复现风险** —— 其 N=10 实验中实验组知识记忆维度**输给传统网课**（p.76-77），归因于"侧重原理探究、弱化机械记忆"。CX 对应物是语法与 API。**必须预置基础技能后测与补偿模块**（间隔重复 + 语法层不渐退），否则同坑重演并成为评审攻击点。

### 7.4 一条方法论自省

用户对文献的批评（"闭环画得漂亮但不落到教师决策""智能体之间无协同机制""支架无操作定义"）**目前全部适用于用户自己的模式图**——四职能无数据契约、回流箭头无写路径、渐退无判据。这不是弱点，而是本轮综述的最大价值：**这些批评之所以锋利，正是因为它们指出的是这一整个研究领域的系统性缺失；而 CX 有可运行系统 + 真实埋点 + 服务端权威结对角色，是这批文献里唯一有条件把它们逐条兑现成代码的。** 论文的贡献应写成"给出了这些缺失的操作定义与系统实现"，而不是"别人做错了"。
